## 这个项目是什么

把 GitHub 上好用的开源工具"工具化"：无需安装环境、无需命令行，打开网页填参数即出结果。

**当前收录 99 个工具**：37 个本地执行（浏览器内完成，数据不上传）+ 62 个在线直达（知名开源项目官网，URL 已逐个拨测验证）。另有 6 个资源合集（50 条）、10 个专题、5 篇工具横评、34 篇使用教程——教程累计 185 条问答，每条都写具体的技术边界而不是套模板。


## 架构（可扩展核心）

- **平台本体零工具**：所有工具通过 **Manifest 规范** 接入，平台自动渲染表单 UI 与结果区。
- **纯浏览器执行**：所有计算在用户本地完成，数据不上传（隐私卖点 + 零服务器成本）。
- **接新工具 = 新建目录**：`tools/<工具id>/run.js`，导出 `manifest`（声明输入参数）和 `run()`（执行逻辑），平台代码零改动。

```
toolhub/
├── index.html            # SPA 骨架（History API 路由）
├── assets/
│   ├── style.css
│   ├── app.js            # 注册表 / 搜索 / Manifest→表单渲染 / 路由 / 命令面板
│   ├── pyodide-runtime.js  # Pyodide 共享运行时（多 Python 工具复用）
│   ├── offline.js / batch.js  # 离线包页与批量处理的控制器（按需加载，不进首屏）
│   ├── lib/              # 共享能力：zip 打包 / 加密分享 / 意图解析 / 安全头定义
│   └── icon-*.png        # PWA 图标（192 / 512 / maskable）
│   └── vendor/           # 本地化的开源库（qrcode / marked / purify / jsQR / pdf-lib / pyodide）
├── tools/
│   ├── registry.json     # 分类 / 推荐位 / 排序（手写）
│   ├── tools.json        # 本地工具注册表（由各工具 tool.json 派生的产物）
│   ├── schema.json       # Manifest 与 tool.json 的 JSON Schema（构建期闸门）
│   ├── directory.json    # 在线目录：60 个开源项目官网（URL 已验证）
│   └── <工具id>/         # tool.json（身份）+ run.js（manifest + run）
├── topics.json           # 10 个专题（按场景打包工具 + 资源 + FAQ）
├── evaluations.json      # 5 篇工具横评（隐私/速度/功能取舍）
├── articles.json         # 34 个本地工具的长尾教程（简介+步骤+常见错误+FAQ）
├── resources.json        # 6 个资源合集 / 50 条（逐条标注授权）
├── changelog.json        # 更新日志数据
├── sw.js                 # Service Worker（由 scripts/gen-sw.mjs 构建期生成，勿手改）
├── scripts/              # build-pages / gen-sw / verify / smoke-test / health-check / spa-render-test / new-tools-test / browser-test / serve / perf-budget
├── topics/ evaluations/ resources/ tools/<id>/   # 构建生成的静态 SEO 页
└── wrangler.toml         # Cloudflare Workers 静态资源部署配置
```

## 加一个工具（第三方接入）

三条硬规则：**不发起任何网络请求**、**单工具体积 ≤ 200KB**、**manifest 必须是对象字面量**。
违反任一条，构建阶段就会失败（不会流到线上）。

```bash
node scripts/new-tool.mjs my-tool --name "我的工具" --cat 文本   # 生成可跑目录并自动登记
node scripts/lint-tools.mjs my-tool        # 清单合规（秒级，错误精确到 file:line）
node scripts/build-pages.mjs               # 生成静态页（开头会再跑一次闸门）
node scripts/verify.mjs                    # 全量校验
```

也可以直接在站内 `/submit/` 填表单：生成器会产出 `tool.json` + `run.js` + `README.md` 并打包下载，
校验规则与构建期完全一致（同一份 `assets/lib/json-schema.js` + `tools/schema.json`）。
完整约定见 [`docs/TOOL-CONTRACT.md`](docs/TOOL-CONTRACT.md)。

## Manifest 字段

输入类型：`text` / `textarea` / `number` / `select` / `range` / `file`（`multiple: true` 支持多选）
工具可选导出 `onForm(form)`：表单渲染后做联动（如单位换算的「类型 → 单位」下拉、PDF 工具的按模式显隐字段）
运行时：`browser` / `pyodide`（浏览器内 Python）

## 本地运行

```bash
cd toolhub
python -m http.server 8765
# 打开 http://localhost:8765
```

## 已知技术债（重要）
1. **hash 路由不利于 SEO**：`#/tool/xxx` 不会被搜索引擎独立收录，`document.title` 的 JS 动态修改爬虫也常忽略 → 需改为 path 路由 + SPA fallback，或为每个工具生成静态落地页
2. 缺 `sitemap.xml` / `robots.txt`
3. 目录链接巡检脚本需手动运行（可挂 GitHub Action 定时）
4. i18n 覆盖率无自动校验（工具新增时容易漏翻译）

## v2.8：平台化——让别人也能加工具，而且加不坏（2026-10-25）

这一版没做用户可见的新功能（除了一个新工具），重点是把「加工具」这件事从口头约定变成构建期约束。

- **Manifest 规范**：`tools/schema.json` 用 JSON Schema 写死 shape（字段白名单、类型、长度、枚举、默认值与选项的对应关系）。配套 `assets/lib/json-schema.js` 是 200 行零依赖校验器，**构建期与浏览器提交页共用同一份代码**——页面里过了，构建就不会拦。
- **构建期闸门**：`build-pages.mjs` 第一件事就是校验全部清单，不合规 `exit 1`。错误长这样：`tools/x/run.js:11  [inputs[0].options] select 必须提供 options`，行号来自一个专门写的定位解析器（纯数据字面量给精确行，`ZONES.map(...)` 这类表达式退化成字段起始行，不误导）。
- **注册表拆分**：元数据从中心的 `tools/tools.json` 拆到每个工具的 `tool.json`，中心文件降级为派生产物（`scripts/sync-tools.mjs --check` 查漂移）。两个人同时加工具不再冲突。
- **接入契约变成硬约束**：禁止 `fetch`/`XHR`/`WebSocket`/`EventSource`/`sendBeacon`（本地执行是本站唯一的差异化承诺）、单工具体积 ≤ 200KB、manifest 必须是对象字面量。违反即构建失败。
- **新工具「照片元数据剥离」**：只按公开契约实现，读 EXIF + GPS 坐标；剥离时直接裁掉 APP1/APP13/COM 段而**不重编码**，画质一位不变，ICC 色彩配置保留（删掉它苹果设备拍的 P3 照片会偏色）。
- **提交闭环**：`/submit/` 内嵌生成器（按需动态加载），填表单 → 同一套 Schema 校验 → 生成 `tool.json` + `run.js` + `README.md` → 本地打包 zip（自写 STORE 模式 ZIP + CRC32）。另有 `scripts/new-tool.mjs` 一条命令生成目录并自动登记、立刻自检。
- **校验顺带抓出的真 bug**：`text-diff` 的示例数据用了中文键（「示例」按钮其实一直填不进任何字段）、`tax-calc` 两个下拉选项 value 重复、三处 `number` 字段默认值类型不一致。
- **C4（iframe 隔离）不做**：会让工具失去统一的表单渲染、结果操作条与工具链接力，等于把 v2.6 重做一遍；现阶段禁止联网 + 体积上限 + 构建闸门已覆盖主要风险。

## v3.8：把「再拆一块」量化之后否掉了（2026-10-27）

这一版**没有改界面**。改的是一件事：怎么判断一块样式该不该拆。

v3.7 收尾时 `style.css` 10.9 KB / 上限 11.5 KB，只剩 0.6 KB 余量——三个新工具里最后那条样式都得先掂量才敢加。于是按原计划去拆「内容页样式」。结果两边都被数据否了。

### 第一个候选：内容页样式 —— 这个集合是空的

`scripts/css-coverage.mjs` 报出 **0 条**。一开始以为是脚本判错，查下来是架构决定的：

`build-pages.mjs` 生成的**每一个** HTML（首页、内容页、工具页）都带着全部视图（`#view-home` / `#view-tool` / `#view-page`），SPA 切换只是切显隐。所以「只在内容页出现的类」这个集合天然为空——内容页用的每个类，首页的 DOM 里也都有。

顺带修掉一个 Windows 上的真 bug：`walk()` 返回的是反斜杠路径（`assets\lib\pages.js`），跟 `/` 分隔的字面量比较**永远不相等**，导致 `pages.js` 从没被从「首屏 JS」里摘出去。原来那份「看起来全是 base」的结果，一半是它造成的。

### 第二个候选：浮层样式 —— 实现了，实测，然后回退了

命令面板 `#palette` + 快捷键帮助 `#kbd-help` 共 24 条规则、2.78 KB 原始，首屏一次都不显示。看起来是完美的拆分对象，于是真做了一版：

- 新建 `assets/style.overlay.css`
- 两个浮层标签加 `hidden`（样式表不再兜底隐藏，否则 CSS 没到前面板会以裸 HTML 铺在页面底部）
- 打开时 `await` 样式 → `hidden = false` → 加 `.show`，并加了「等待期间用户已按 Esc」的竞态守卫

然后量了一下：

| | 结果 |
|---|---|
| 首屏省下 | **0.43 KB** |
| 搬出去那块单独成文件 | **0.88 KB** |
| 新增加载逻辑让 app.js 变厚 | +0.3~0.5 KB |
| **合计** | **82.5 → 83.0 KB，反而涨了** |

**已完整回退。** 原因是 gzip 按整个文件建一份共享字典：`.pal-box` / `.kbd-box` 的声明跟别处面板大量重复，搬出去等于把字典拆散——2.78 KB 原始只换回 0.43 KB 压缩体积，而散装的那块没有任何字典可用。

### 这版真正留下的东西

1. **`node scripts/css-coverage.mjs --price '<选择器>'`** —— 输入一段选择器，直接算「首屏能省多少 / 搬出去要付多少 / 净差价多少」。以后任何「拆样式省首屏」的提议，先跑这个再说，别照原始体积估算。
2. **两条新闸门**（校验 45 → 47 项）：
   - `styles` 余量低于 0.5 KB 直接判死——防止上限再被压成实际值（那正是「加一条样式都要掂量」的成因）
   - `style.css` 里出现全站无引用的规则直接卡在发版前——预算膨胀最常见的原因是删了功能、样式留着，不是加了一条大样式
3. **预算重新定档**：`styles` 11.5 → 12.0 KB、`total` 92.8 → 90.0 KB。单项上限从此是**提醒线**，真正的刹车交给 `total`。

### 一条以后都成立的结论

`style.css` 已经接近它的压缩熵底。继续在文件内部搬字节，收益是零点几 KB；想真正减少首屏样式，只有「不加载某些字节」这一条路——而这条路要先算清散装字典的代价。

## v3.7：三个新工具，以及一次完整的外包交付（2026-10-27）

前六版都在「收口」——收首页、收样式、收移动端。这一版第一次往外长：**94 → 97 个工具**，加了图片裁剪、文件哈希校验、CSV 选列。

也是第一次把一整包活按 `docs/taskpacks/TP4-new-tools.md` 派给外部模型做，我只做验收。所以下面除了改了什么，也记了验收时**发现了什么它没发现的问题**。

### 1. 三个工具，为什么是这三个

不是「补全分类」，是三个具体的人在具体场景下会打开的东西：

| 工具 | 谁会用 |
|---|---|
| `img-crop` | 截图里只有中间一块有用、或要把照片切成 1:1 圆角头像的人 |
| `file-hash` | 刚下完 2GB 系统镜像、装之前要确认没下坏，手里还有官网那串 SHA-256 的人 |
| `csv-columns` | 从后台导出 40 列报表、只要 6 列且顺序按自己表头来的人 |

站里原本已经有 `image-compress` / `image-resize`（缺裁剪）、`sha256-hash`（只算文本）、`csv-json`（只做格式互转），三个都是真实空位。

### 2. file-hash：为什么不用 `crypto.subtle`

三个理由，缺一个都不成立：

1. `subtle` **没有 MD5**，而老发布页还在用 md5；
2. `subtle` 必须一次吃下完整 ArrayBuffer —— 1GB 的镜像先占 1GB 内存，手机上直接崩；
3. 只有自己算才能**边读边出进度**。

所以四种算法全部手写增量实现。代价是 MD5 的两个经典坑得自己踩：

- padding 的**长度位是 64 位小端**（写成 32 位在 >512MB 才暴露，小文件全对）；
- 末轮寄存器顺序是 `a=d, d=c, c=b, b=b+rotl(...)`。

空串和 `abc` 两个公开向量能同时锁死这两类错误。SHA-256/512 的 K 表与 IV 是**按定义现算**（前 80 个素数的立方根小数部分，Newton 迭代），而不是手抄 160 个 64 位常量 —— 抄错一位哈希会**静默**算错，算出来的值看起来和正常值一模一样。

实测 30MB：MD5 0.26s / SHA-1 0.62s / SHA-256 0.74s / SHA-512 1.02s。

### 3. csv-columns：`split(',')` 必然错位

只要有一格是 `"张三, 备用"`，按逗号切出来的列数就比表头多，那一行之后所有列全部错位。所以写的是引号状态机，支持引号内逗号、引号内换行、双写引号。

两个容易做错的细节：

- **空字段不是缺字段**：`a,,c` 是三列，中间那列值为空。压成两列是最常见的手写 bug。
- **导出保留原引号风格**：每个单元格记一个「原本是否带引号」的标记，`"abc"`（本来没必要带引号）导出后仍然带引号。

### 4. 收包时补的三条样式（外包方无权改 `assets/`）

任务包明令禁止碰 `assets/**`——这正是样式预算只剩 0.8 KB 时的必要约束。代价是新工具需要的专属样式得我补：

| 补什么 | 为什么 |
|---|---|
| `#tool-fields .field canvas { max-height: 42vh }` | 800×2000 的长截图按宽度铺满会变成 252×630，把「左上角 X/Y」四个数字框整个推出视野。限高后 341px，坐标框紧跟在预览下方 |
| `.chip-row { max-height: 112px; overflow: auto }` | CSV 40 列的标签会换五六行，把「运行」按钮顶走 |
| `.msg-warn` + `--warn` 变量 | 之前只有 `.msg-ok`。提醒类提示（「已收缩到边缘」「校验值不一致」）在 exif-strip 和三个新工具里都是裸文本 |

### 5. 验收时发现的两个它没发现的问题

**a) 深色模式下一排白块。** csv-columns 的列标签把颜色内联写死成 `#fff` / `#eff6ff` / `#1d4ed8`，浅色下没问题，深色主题下是一排刺眼的白块；img-crop 的提示文字硬编码 `#6b7280`，深色下对比度只有 **3.6:1**（体检按 4.5 判定）。两处都改成 CSS 变量，复检 0 问题。

这恰好说明一件事：**「功能测试全绿」和「界面能用」是两件事**。它的测试测的是 `run()` 的返回值，测不到「深色下看不见」。

**b) `accept` 漏了压缩包。** 它把 `accept` 写成安装包/镜像白名单（`.exe .msi .dmg .iso .img .bin .jar .whl .pdf`），理由是「写通配符会让首页对任何文件都推哈希工具」——这个判断**是对的**，不该写 `*`。但白名单漏了 `.zip` / `.tar.gz` / `.7z`，而开源项目的发布包绝大多数正是这些格式，那才是校验值最典型的对象。补上之后，又发现既有断言「不认识的文件不硬推」拿 `a.zip` 当反例——**zip 现在是能被认出的文件了**，所以反例换成 `a.xyz`，并补两条正向断言（`.zip` / `.iso` 必须路由到哈希工具）。

### 1. 表单：把留白还给按钮

| 项 | 改前 | 改后 |
|---|---|---|

一个诚实的说明：**tax-calc 改前也在第二屏**，所以这条的净收益是 104px 和「按钮有了独立分隔线」，不是「从看不到变成看得到」。pdf-merge 只省 2px —— 它只有 4 个字段，省下的间隙被下面两条分段线抵掉了，这是有意的取舍。

### 2. 分组：不改 DOM 怎么做

`#tool-fields` 是扁平的 `.field` 列表，manifest 也不支持 `group` 字段（`docs/TOOL-CONTRACT.md` §2 写明「写了规范里没有的字段构建期拦下」）。所以分组只能靠**控件形态的连续段**推断：

```css
#tool-fields > .field:has(input:not([type=file])) + .field:has(select),
#tool-fields > .field:has(select) + .field:has(textarea, input[type=file]),
#tool-fields > .field:has(textarea, input[type=file]) + .field,
#tool-fields > .field + .field:has(textarea, input[type=file]) { border-top: 1px dashed; }
```

形态一变画一条虚线：个税切成「收入 ｜ 专项附加扣除」，pdf-merge 切成「操作 ｜ 文件」。**有意不切「下拉 → 数字框」**——个税末尾的「其他扣除（元/月）」是数字框，切开会把同一组扣除项拆到两段去。少一条规则，语义更准。

用了 `:has()`（Chromium 105+ / Safari 15.4+ / Firefox 121+）。代价要写清：**老浏览器上分段线整体失效，但不会破坏布局**，只是没有虚线。

### 3. 动作条与表格：两个真正会把内容吃没的地方

结果动作条原来是 flex 换行 + `nowrap` + 省略号。4～6 个动作挤一行，宽度参差（103/116/103），长文件名的下载按钮会被截掉后缀——而后缀恰恰是用户判断「下的是哪个文件」的唯一依据。改成两列等宽网格后是 143 / 143 / 293，文字换行显示完整，奇数个动作时最后一个占满整行。

### 1. 拆：93 条规则搬出首屏

问题是「哪些规则只服务工具页」不能靠眼睛判断。先写了 `scripts/css-coverage.mjs`，按类名在整个仓库的出现位置给每条规则判归属：出现在 `index.html` / 内容页 / `app.js` 里的留基础表，只出现在 `tools/**.html`、`tool-page.js`、`tools/**.js` 里的搬走。

这个脚本现在是这套资产的体检仪：跑一遍 `style.css` 应该报「仅工具页 0 条、无引用 0 条」，跑一遍 `style.tool.css` 应该报「仅工具页 93 条」。数字不对就说明有人把规则放错了地方。

## v3.4：首页收口——把入口并成一行，把长列表截断（2026-10-26）

上一版把代码拆细了，这一版处理首页本身的堆叠问题。起点是六条具体意见，逐条都有结论：该改的改了，需要判断的写清了理由。

### 1. 四个入口并成一行

原来 `.route-cards` 是 **3 列网格塞 4 张卡**——第 4 张永远孤零零占第二行，看着像漏了一张。改成 4 列，每块给一个图标徽章加一个板块标签（工具箱 / 资源库 / 对比台 / 评测室），四种颜色分开（蓝 / 青 / 紫 / 琥珀）。卡片底部那行「浏览工具 →」用 `margin-top: auto` 压到底，描述长短不一时链接也对齐。

### 2. 高频推荐：13 → 8 条，换列表形式

原来是 13 张卡片、4 列排成 3.25 行，**样式和下面的工具网格几乎一样**——读者会以为这是同一份列表重复了两遍。现在取前 8 条，改成两列行式列表：编号 + 名称 + 单行描述 + 右侧标签，行间用细线分隔，没有卡片边框。一眼能看出「这是精选摘要，下面才是全集」。

### 3. 工具列表：分页，不是加载更多

94 个工具一次全铺是 20 多行、页面约 7000px，页脚的信任说明和「更多」全被埋掉。**选了分页而不是加载更多**，理由：

- 目录站的使用方式是「快速定位」，不是「无限刷」。筛选、搜索、翻页三条路径已经够用；
- 分页让页脚可达；加载更多只是把长度问题往后推，越刷越不知道自己在哪；
- 页码可以进 URL（`?page=2`），能分享、能刷新、返回时不丢位置。

每页 24 个，宽屏 5 列、常见笔记本 4 列都不留孤行。筛选 / 搜索 / 排序 / 切分类一律回到第 1 页，否则会停在已经不存在的第 4 页。

同时把 `.container` 从 1000px 放到 1160px——宽屏下工具卡从 4 列变 5 列。正文页有自己的 `.page{max-width:720px}` 兜着，长文行宽不受影响。

### 4. 两个搜索框：合并成一个入口

首屏原本同时显示头部输入框和 hero 大框，**行为完全一样**——hero 的每个输入都直接镜像进头部框，两者都在筛选同一份列表。这确实是重复。

改法不是删掉一个，而是让它们各管一件事：

- **hero 大框**留下，负责就地筛选 + 粘贴识别（粘一段 JSON 会提示「格式化这段 JSON」）+ 意图直达（「把 2.5 米转成英尺」直接进工具并预填参数）；
- **头部的输入框在首页收起**，换成一个放大镜按钮，点开的是命令面板——它搜的是全站（工具 / 资源 / 专题 / 评测 / 页面），和「筛选当前列表」不是一回事；
- 其他页面（工具页、内容页）没有 hero 框，头部输入框照旧显示。

这样首屏只有一个可编辑输入框，滚到下面想搜索也有入口，而且那个入口给的是更强的全站搜索。

### 5. 「为什么本地执行更放心」下移到页尾

原来它夹在资源区和工具列表之间——这是本站跟其他工具站的根本区别，却放在了一个大部分人不会回头读的位置。挪到工具列表之后、页脚之前收口。

`body[data-view]` 在**构建期**就写对（首页 `home`，其余页面 `page`，工具页由 `tool-page.js` 运行时改成 `tool`）。否则静态 HTML 会先画出一个搜索框、脚本跑起来再收掉，顶一下布局。改完 CLS 仍是 **0.000**。

顺手修了测试自身的脆弱点：离线页那两条断言是「取一次值」而不是等挂载完成，机器慢一点就误报功能坏了——现在改轮询，慢机器上也稳。

**验收**：五套 + 体检全绿（44 / 49 / 161 / 84 / 122，体检 0 高优、0 中优）；首屏 94.3 KB / 9 请求；样式预算 11.7 → 12.6 KB 并冻结——v3.0–v3.2 加了批量页、离线页、拖放浮层、口令弹层四套界面，样式变厚是结果不是意外，但这条线再超就该做 CSS 分片，而不是继续抬数字。

## v3.1：入口——文件拖进来、内容粘进来（2026-10-25）

v3.0 让站内能做的事变多了，但**入口仍然只有一个搜索框**，而搜索框要求你先知道工具叫什么。
这一版把方向反过来：给一个文件或一段文本，让站自己说该去哪儿。

- **拖进来就能用**：文件拖到窗口任意位置 → 全屏「松手，帮你找工具」→ 松手给 2–3 个候选，点一个带着文件跳过去。文件在内存里接力（同一个 `File` 对象），不读盘、不上传、不留副本。
- **只推真的吃得下的**：注册表新增构建期派生的 `accepts` / `fileMultiple`，从每个工具的 manifest 算出——不是「名字里有 PDF 就推荐」。这类猜测的代价很具体：点进去发现拖不进去。
- **多文件优先推能一次吃完的**：拖 3 张图先推「图片转 PDF」，而不是只能选 1 个的压缩工具；图片和 PDF 混着拖时退化成「只用第 1 个」，但面板会**明说**，不默默丢弃。
- **粘贴即问**：把 JSON / JWT / CSV / 时间戳 / 颜色值 / Base64 / 链接 / Markdown 粘进搜索框，不再被当成关键词，而是一条「检测到 JSON · 格式化这段 JSON」，点一下直达、预填、自动运行。认不出来就原样粘贴，绝不拦截正常输入。
- **规则全在本地**：8 条粘贴规则按「越具体越先判」排序（JWT 不会被当成 Base64，订单号不会被当成时间戳），与意图解析共用同一条原则——为了猜工具把输入发给大模型，等于把「输入不上传」换掉。

顺手修掉两个不显眼但真的会咬人的问题：

- **离线包其实不完整**：`sw.js` 只收了工具页与 `run.js`，漏掉按需加载的应用模块（批量处理、拖放、ZIP 打包、加密分享、意图解析）。表现不是白屏，而是「断网打开批量页，点一下没反应」。现在扫描 `assets/` 自动进包，校验里加了「每个应用模块都必须在清单里」。
- **`sync-tools --check` 本地静默失效**：本机工作区是目录联接（`C:\...\WorkBuddy\` → `D:\WorkBuddyProjects\`），`import.meta.url` 是真实路径而 `argv[1]` 是联接路径，字符串永不相等——脚本一行没跑、退出码 0。CI 上没有联接，所以「线上绿、本地也绿，本地其实没执行」。改用 realpath 判断。

**验收**：校验 44 / SPA 49 / 功能 161 / 冒烟 84 / 浏览器 122，五套全绿；首屏 93.7 KB / 9 个请求，仍在预算内；离线包 107 个地址约 2.5 MB。

## v3.0：差异化——断网也能用、一次处理一批、加密后再分享（2026-10-25）

前九个版本都在把「在线工具」做得更规范。这一版回答一个不同的问题：**当别人也能提供同样的工具时，凭什么用这个**。

- **完整离线包**：`sw.js` 改由构建期生成，预缓存清单从 `tools/tools.json` 派生——新增工具自动进包，不会出现「装到桌面后那个工具离线打不开」。清单只收录磁盘上真实存在的路径（`install` 的 `addAll` 是全有或全无，一个 404 会让整个装包失败）。
- **下载与进度**：`/offline/` 页点「下载离线包」后，SW 逐个抓取并每 5 个回报一次进度；失败只记录不中断，可以再点一次补全。实测 97 个地址约 2.4 MB。
- **可安装（PWA）**：补齐 192/512/maskable 图标与 manifest 快捷方式，`beforeinstallprompt` 在 `app.js` 里全局捕获后交给页面消费。页面明确区分两件事：**安装**解决「从桌面图标打开」，**离线包**解决「没有网络也能打开」，两者互不替代。
- **刻意不把 Python 运行时塞进离线包**：核心 13MB、含 pandas 36MB，硬塞会让首次安装变成几分钟。改为第一次用 Python 工具时单独下载并缓存，但 **`pyodide-loader.js` 必须进包**——否则离线打开 Python 工具连报错都报不出来（校验里专门断言了这一点）。
- **加密分享**：结果用 AES-GCM 256 在本地加密后放进链接的 `#` 片段。片段不随请求发送，所以服务器与 CDN 日志里没有明文；可选口令走 PBKDF2-SHA256 12 万次迭代。收到链接的人打开即自动解密回填（带口令时弹口令框），非文件类工具直接自动重跑。
- **批量处理图片**：一次拖入多张，统一最大边长 + 输出格式 + 压缩质量，逐张显示状态与体积变化，结果打包成一个 zip 或逐个下载。全部在浏览器内完成。
- **ZIP 抽成共享库**：`assets/lib/zip.js`（STORE + CRC32 + UTF-8 文件名标记）被批量页、结果区「打包下载」、工具包生成器三处复用。测试直接按字节解析中央目录，验签名、条数、CRC 与中文文件名，而不是「看起来像个 zip」。
- **自然语言 → 工具**：命令面板与首页搜索框能听懂「把这张图压到 200KB」「帮我算下月薪两万的个税」，命中就在顶部给出「也许你要」并带预填参数跳转。规则表约 35 条，**完全在本地跑**——为了猜工具把用户输入发给大模型，等于把「输入不上传」这个立站之本换掉。
- **两页新的说明**：`/offline/`（离线与安装的边界、包含与不包含、怎么自己验证）与 `/batch/`（批量与单图工具的关系），都有长尾正文，可被搜索引擎单独收录。

**验收**：校验 44 / SPA 49 / 功能 137 / 冒烟 84 + 内容抽查 / 浏览器 108，五套全绿；真浏览器里跑通了「下载离线包 → 断网 → 打开工具 → 出结果」，缓存 97 个文件、LCP 88ms、CLS 0.000。

## v2.9：质量与运维——把「上线之后」也纳入版本纪律（2026-10-25）

前面八个版本一直在加功能、加内容、加规范，这一版补的是另一半：**怎么知道线上没坏**。

- **一条 CI 链路管到底**：`.github/workflows/ci.yml` 依次跑 清单漂移 → 清单闸门 → 构建 → 校验 → SPA → 功能 → 性能预算 → 冒烟 → 真浏览器 E2E。PR 不绿不合，main 自动部署。
- **本地也能测 CSP**：新增 `scripts/serve.mjs`，按线上规则发安全响应头，和 Worker **共用同一份** `assets/lib/security-headers.js`。此前的本地静态服务器不带任何头，「本地没问题、线上被 CSP 拦掉」这类问题根本测不出来。
- **安全头从 `_headers` 搬到 `_worker.js`**：`_headers` 只能按路径匹配，给不了「工具页允许被嵌入、其他页只允许同源」这种规则。顺带修掉一个躺了三版的矛盾——`X-Frame-Options: SAMEORIGIN` 让「复制嵌入代码」给出的 iframe 从来没生效过。
- **性能从体感变成闸门**：`perf-budget.json` 卡首屏 gzip 与请求数；真浏览器里断言 LCP/CLS/CSP 违规数。查出两个真问题：
  - 首屏一直加载着二维码、marked、DOMPurify、Pyodide loader 四个库（约 90KB 原始体积），而只有 3 个工具用得到 → 改为工具内按需加载；
  - 首页的统计条、路线卡、推荐位、筛选栏全靠 JS 在首帧后插入，把下面的内容整体下推，**CLS 0.249** → 改为构建期静态化，**CLS 0.000**。
- **统计可配置可退出**：`analytics.json` 支持 none / cloudflare / plausible / umami，默认 none（零第三方请求），尊重 DNT，`/privacy/` 页可一键退出。校验会检查「开了统计但 CSP 没放行」这种静默失败。
- **巡检有节奏**：`health-check.mjs` 输出 JSON + Markdown，每周一自动跑，有死链开 issue。

**验收**：校验 39 / SPA 39 / 功能 116 / 冒烟 73 + 内容抽查 / 浏览器 85，全绿；LCP 600ms、CLS 0.000、零 CSP 违规、零第三方请求。
