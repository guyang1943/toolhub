# ToolHub — 开源项目工具化平台（v3.5）

把 GitHub 上好用的开源工具"工具化"：无需安装环境、无需命令行，打开网页填参数即出结果。

**当前收录 94 个工具**：34 个本地执行（浏览器内完成，数据不上传）+ 60 个在线直达（知名开源项目官网，URL 已逐个拨测验证）。另有 6 个资源合集（50 条）、10 个专题、5 篇工具横评、34 篇使用教程。

## 架构（可扩展核心）

- **平台本体零工具**：所有工具通过 **Manifest 规范** 接入，平台自动渲染表单 UI 与结果区。
- **纯浏览器执行**：所有计算在用户本地完成，数据不上传（隐私卖点 + 零服务器成本）。
- **接新工具 = 新建目录**：`tools/<工具id>/run.js`，导出 `manifest`（声明输入参数）和 `run()`（执行逻辑），平台代码零改动。

```
toolhub/
├── index.html            # SPA 骨架（History API 路由）
├── assets/
│   ├── style.css
│   ├── app.js            # 注册表 / 搜索 / Manifest→表单渲染 / 路由 / 命令面板
│   ├── pyodide-runtime.js  # Pyodide 共享运行时（多 Python 工具复用）
│   ├── offline.js / batch.js  # 离线包页与批量处理的控制器（按需加载，不进首屏）
│   ├── lib/              # 共享能力：zip 打包 / 加密分享 / 意图解析 / 安全头定义
│   └── icon-*.png        # PWA 图标（192 / 512 / maskable）
│   └── vendor/           # 本地化的开源库（qrcode / marked / purify / jsQR / pdf-lib / pyodide）
├── tools/
│   ├── registry.json     # 分类 / 推荐位 / 排序（手写）
│   ├── tools.json        # 本地工具注册表（由各工具 tool.json 派生的产物）
│   ├── schema.json       # Manifest 与 tool.json 的 JSON Schema（构建期闸门）
│   ├── directory.json    # 在线目录：60 个开源项目官网（URL 已验证）
│   └── <工具id>/         # tool.json（身份）+ run.js（manifest + run）
├── topics.json           # 10 个专题（按场景打包工具 + 资源 + FAQ）
├── evaluations.json      # 5 篇工具横评（隐私/速度/功能取舍）
├── articles.json         # 34 个本地工具的长尾教程（简介+步骤+常见错误+FAQ）
├── resources.json        # 6 个资源合集 / 50 条（逐条标注授权）
├── changelog.json        # 更新日志数据
├── sw.js                 # Service Worker（由 scripts/gen-sw.mjs 构建期生成，勿手改）
├── scripts/              # build-pages / gen-sw / verify / smoke-test / health-check / spa-render-test / new-tools-test / browser-test / serve / perf-budget
├── topics/ evaluations/ resources/ tools/<id>/   # 构建生成的静态 SEO 页
└── wrangler.toml         # Cloudflare Workers 静态资源部署配置
```

## 加一个工具（第三方接入）

三条硬规则：**不发起任何网络请求**、**单工具体积 ≤ 200KB**、**manifest 必须是对象字面量**。
违反任一条，构建阶段就会失败（不会流到线上）。

```bash
node scripts/new-tool.mjs my-tool --name "我的工具" --cat 文本   # 生成可跑目录并自动登记
node scripts/lint-tools.mjs my-tool        # 清单合规（秒级，错误精确到 file:line）
node scripts/build-pages.mjs               # 生成静态页（开头会再跑一次闸门）
node scripts/verify.mjs                    # 全量校验
```

也可以直接在站内 `/submit/` 填表单：生成器会产出 `tool.json` + `run.js` + `README.md` 并打包下载，
校验规则与构建期完全一致（同一份 `assets/lib/json-schema.js` + `tools/schema.json`）。
完整约定见 [`docs/TOOL-CONTRACT.md`](docs/TOOL-CONTRACT.md)。

## Manifest 字段

输入类型：`text` / `textarea` / `number` / `select` / `range` / `file`（`multiple: true` 支持多选）
工具可选导出 `onForm(form)`：表单渲染后做联动（如单位换算的「类型 → 单位」下拉、PDF 工具的按模式显隐字段）
运行时：`browser` / `pyodide`（浏览器内 Python）

## 本地运行

```bash
cd toolhub
python -m http.server 8765
# 打开 http://localhost:8765
```

## 已知技术债（重要）
1. **hash 路由不利于 SEO**：`#/tool/xxx` 不会被搜索引擎独立收录，`document.title` 的 JS 动态修改爬虫也常忽略 → 需改为 path 路由 + SPA fallback，或为每个工具生成静态落地页
2. 缺 `sitemap.xml` / `robots.txt`
3. 目录链接巡检脚本需手动运行（可挂 GitHub Action 定时）
4. i18n 覆盖率无自动校验（工具新增时容易漏翻译）

## v2.8：平台化——让别人也能加工具，而且加不坏（2026-10-25）

这一版没做用户可见的新功能（除了一个新工具），重点是把「加工具」这件事从口头约定变成构建期约束。

- **Manifest 规范**：`tools/schema.json` 用 JSON Schema 写死 shape（字段白名单、类型、长度、枚举、默认值与选项的对应关系）。配套 `assets/lib/json-schema.js` 是 200 行零依赖校验器，**构建期与浏览器提交页共用同一份代码**——页面里过了，构建就不会拦。
- **构建期闸门**：`build-pages.mjs` 第一件事就是校验全部清单，不合规 `exit 1`。错误长这样：`tools/x/run.js:11  [inputs[0].options] select 必须提供 options`，行号来自一个专门写的定位解析器（纯数据字面量给精确行，`ZONES.map(...)` 这类表达式退化成字段起始行，不误导）。
- **注册表拆分**：元数据从中心的 `tools/tools.json` 拆到每个工具的 `tool.json`，中心文件降级为派生产物（`scripts/sync-tools.mjs --check` 查漂移）。两个人同时加工具不再冲突。
- **接入契约变成硬约束**：禁止 `fetch`/`XHR`/`WebSocket`/`EventSource`/`sendBeacon`（本地执行是本站唯一的差异化承诺）、单工具体积 ≤ 200KB、manifest 必须是对象字面量。违反即构建失败。
- **新工具「照片元数据剥离」**：只按公开契约实现，读 EXIF + GPS 坐标；剥离时直接裁掉 APP1/APP13/COM 段而**不重编码**，画质一位不变，ICC 色彩配置保留（删掉它苹果设备拍的 P3 照片会偏色）。

### 1. 拆：93 条规则搬出首屏

问题是「哪些规则只服务工具页」不能靠眼睛判断。先写了 `scripts/css-coverage.mjs`，按类名在整个仓库的出现位置给每条规则判归属：出现在 `index.html` / 内容页 / `app.js` 里的留基础表，只出现在 `tools/**.html`、`tool-page.js`、`tools/**.js` 里的搬走。

```bash
node scripts/css-coverage.mjs          # 汇总 + 无引用清单
node scripts/css-coverage.mjs --all    # 连「仅工具页」清单一起看
```

这个脚本现在是这套资产的体检仪：跑一遍 `style.css` 应该报「仅工具页 0 条、无引用 0 条」，跑一遍 `style.tool.css` 应该报「仅工具页 93 条」。数字不对就说明有人把规则放错了地方。

搬到 `assets/style.tool.css` 的是这些：结果导出条、结果表格、个税大数字卡、二维码结果布局、教程与常见错误、diff 配色、Markdown 预览排版、口令弹层、目录工具页正文……共 **93 条规则、9.3 KB**。

留下的 `.panel` / `.field` / `.btn` / `.result` 是工具页与内容页共用的基础件，**故意不搬**——搬了内容页就塌了。

首屏样式 **12.2 → 10.4 KB**，全站首屏 82.9 → **81.4 KB**。

### 2. 两条加载路径都得堵上

拆出来最大的风险不是体积，是「路由过去了，样式没到」：

- **整页加载 `/tools/<id>/`**：构建期就把 `<link>` 写进 `<head>`，不可能闪。
- **从首页点卡片进工具（SPA）**：首页没带这张表，得现取。这里**不能 fire-and-forget**，否则先画一堆裸结构再补样式，等于把省下的字节以「闪一下」还回去。所以 `openTool()` 里 `await` 样式就位后才翻视图。

关键是**没有另造一套加载器**：v3.3 给批量 / 离线 / 提交三页写的 `ensureCss()` 本来就有，只是「塞进去就不管」。这版把它改成返回 Promise——工具页 `await` 它，内容页仍旧不管（少几处样式不影响用）。一个机制两种用法，不是两份代码。

### 3. 删：4 条死规则，以及一个错误的结论

删掉 `header-note`、`usage-example`（含深色变体）共 4 条确认无引用的规则。

**同时纠正上一版的错误**：v3.4 的遗留说明里写「已扫出 `header-note`、`pv-ok`、`pv-mid` 三个确认无引用的类」——后面两个是错的。它们由 `pv-${pvClass(x)}` 这种模板字符串拼出来，纯文本搜索天然搜不到，但页面上真的在用（评测页的隐私徽章）。这类「动态拼出来的类名」现在被钉在分析脚本的白名单里，注释也写清了为什么。

这件事值得记下来：**「搜不到」和「没人用」不是一回事**。靠 grep 判断死代码，必须先排除字符串拼接。

拆分只是手段，收紧才是目的——不收紧的话省下来的空间迟早被下一次「顺手加一点」吃回去。

## v3.0：差异化——断网也能用、一次处理一批、加密后再分享（2026-10-25）

前九个版本都在把「在线工具」做得更规范。这一版回答一个不同的问题：**当别人也能提供同样的工具时，凭什么用这个**。

- **完整离线包**：`sw.js` 改由构建期生成，预缓存清单从 `tools/tools.json` 派生——新增工具自动进包，不会出现「装到桌面后那个工具离线打不开」。清单只收录磁盘上真实存在的路径（`install` 的 `addAll` 是全有或全无，一个 404 会让整个装包失败）。
- **下载与进度**：`/offline/` 页点「下载离线包」后，SW 逐个抓取并每 5 个回报一次进度；失败只记录不中断，可以再点一次补全。实测 97 个地址约 2.4 MB。
- **可安装（PWA）**：补齐 192/512/maskable 图标与 manifest 快捷方式，`beforeinstallprompt` 在 `app.js` 里全局捕获后交给页面消费。页面明确区分两件事：**安装**解决「从桌面图标打开」，**离线包**解决「没有网络也能打开」，两者互不替代。
- **刻意不把 Python 运行时塞进离线包**：核心 13MB、含 pandas 36MB，硬塞会让首次安装变成几分钟。改为第一次用 Python 工具时单独下载并缓存，但 **`pyodide-loader.js` 必须进包**——否则离线打开 Python 工具连报错都报不出来（校验里专门断言了这一点）。
- **加密分享**：结果用 AES-GCM 256 在本地加密后放进链接的 `#` 片段。片段不随请求发送，所以服务器与 CDN 日志里没有明文；可选口令走 PBKDF2-SHA256 12 万次迭代。收到链接的人打开即自动解密回填（带口令时弹口令框），非文件类工具直接自动重跑。
- **批量处理图片**：一次拖入多张，统一最大边长 + 输出格式 + 压缩质量，逐张显示状态与体积变化，结果打包成一个 zip 或逐个下载。全部在浏览器内完成。
- **ZIP 抽成共享库**：`assets/lib/zip.js`（STORE + CRC32 + UTF-8 文件名标记）被批量页、结果区「打包下载」、工具包生成器三处复用。测试直接按字节解析中央目录，验签名、条数、CRC 与中文文件名，而不是「看起来像个 zip」。
- **自然语言 → 工具**：命令面板与首页搜索框能听懂「把这张图压到 200KB」「帮我算下月薪两万的个税」，命中就在顶部给出「也许你要」并带预填参数跳转。规则表约 35 条，**完全在本地跑**——为了猜工具把用户输入发给大模型，等于把「输入不上传」这个立站之本换掉。
- **两页新的说明**：`/offline/`（离线与安装的边界、包含与不包含、怎么自己验证）与 `/batch/`（批量与单图工具的关系），都有长尾正文，可被搜索引擎单独收录。

**验收**：校验 44 / SPA 49 / 功能 137 / 冒烟 84 + 内容抽查 / 浏览器 108，五套全绿；真浏览器里跑通了「下载离线包 → 断网 → 打开工具 → 出结果」，缓存 97 个文件、LCP 88ms、CLS 0.000。

## v2.9：质量与运维——把「上线之后」也纳入版本纪律（2026-10-25）

前面八个版本一直在加功能、加内容、加规范，这一版补的是另一半：**怎么知道线上没坏**。

- **一条 CI 链路管到底**：`.github/workflows/ci.yml` 依次跑 清单漂移 → 清单闸门 → 构建 → 校验 → SPA → 功能 → 性能预算 → 冒烟 → 真浏览器 E2E。PR 不绿不合，main 自动部署。
- **本地也能测 CSP**：新增 `scripts/serve.mjs`，按线上规则发安全响应头，和 Worker **共用同一份** `assets/lib/security-headers.js`。此前的本地静态服务器不带任何头，「本地没问题、线上被 CSP 拦掉」这类问题根本测不出来。
- **安全头从 `_headers` 搬到 `_worker.js`**：`_headers` 只能按路径匹配，给不了「工具页允许被嵌入、其他页只允许同源」这种规则。顺带修掉一个躺了三版的矛盾——`X-Frame-Options: SAMEORIGIN` 让「复制嵌入代码」给出的 iframe 从来没生效过。
- **性能从体感变成闸门**：`perf-budget.json` 卡首屏 gzip 与请求数；真浏览器里断言 LCP/CLS/CSP 违规数。查出两个真问题：
  - 首屏一直加载着二维码、marked、DOMPurify、Pyodide loader 四个库（约 90KB 原始体积），而只有 3 个工具用得到 → 改为工具内按需加载；
  - 首页的统计条、路线卡、推荐位、筛选栏全靠 JS 在首帧后插入，把下面的内容整体下推，**CLS 0.249** → 改为构建期静态化，**CLS 0.000**。
- **统计可配置可退出**：`analytics.json` 支持 none / cloudflare / plausible / umami，默认 none（零第三方请求），尊重 DNT，`/privacy/` 页可一键退出。校验会检查「开了统计但 CSP 没放行」这种静默失败。
- **巡检有节奏**：`health-check.mjs` 输出 JSON + Markdown，每周一自动跑，有死链开 issue。

**验收**：校验 39 / SPA 39 / 功能 116 / 冒烟 73 + 内容抽查 / 浏览器 85，全绿；LCP 600ms、CLS 0.000、零 CSP 违规、零第三方请求。
