本机能跑多大模型

当场检测 WebGPU、内存与核数，算出你的机器能跑多大的本地模型（3B 到 70B、四档量化）

关于本机能跑多大模型

「我这台电脑能跑多大的模型」这个问题，答案由四个数决定：参数量、量化位数、上下文长度、可用内存。前三个你自己选，第四个得当场量。这个工具不下载任何模型，只用浏览器原生接口读出 WebGPU 是否可用、系统内存多大、几个核、磁盘还剩多少，再把「模型要多大」和「你有多少」摆在一张表上。它存在的理由很简单：网上的答案大多是「16G 能跑 7B 吗」这种经验之谈，而实际上同一个 7B，FP16 要 14GB、Q4_K_M 只要 4.4GB——不谈量化的答案，没有参考价值。

使用步骤

  1. 选模型规模（3B 到 70B）、量化档与上下文长度。不确定就先用默认的 7B / Q4_K_M / 4K
  2. 点「检测并估算」。浏览器会当场向 WebGPU 申请一个适配器，不会弹权限框，也不下载任何东西
  3. 看结论：需要多少、可用多少、差多少。差得不多就先降量化，差得远再降规模
  4. 同一规模下四档量化的对照表就在下面，直接看「换一档能省多少」

常见错误

只看参数量，不看量化

同一个 7B，FP16 要 14GB，Q8 约 7.4GB，Q4_K_M 只要 4.4GB。「7B 要 8GB 内存」这句流传很广的话，漏掉的正是量化这一项，它决定了能不能跑。

把系统内存当成显存

独显机器上，模型要装进显卡自己的显存，和系统内存不是一回事；核显共享系统内存，才接近这里的估算。所以同一台 32GB 内存的机器，有独显和没独显，能跑的规模可能差一倍。

忽略上下文长度

KV cache 随上下文线性增长。32K 上下文的 7B 比 4K 多占 1GB 以上，在临界配置上，这一项就是「能跑」与「OOM」的分界。

常见问题

浏览器不告诉我显存，这个估算准吗？

按系统内存估算，误差约 ±20%。WebGPU 规范不暴露显存总量，只暴露单个缓冲的上限，所以拿不到「8GB 显卡」这个规格书数字。结论当参考，实际以跑起来为准；这也是为什么结果里把「按什么估的」一并写出来，而不是只给一个漂亮数字。

没有 WebGPU 就不能跑吗？

能跑，走 CPU 的 WASM 后端（Ollama、llama.cpp 都支持），只是慢：7B 大约每秒几个字。读文档、改邮件够用；要流畅对话就得有 GPU 加速。

为什么显示系统内存 8GB，我明明有 32GB？

navigator.deviceMemory 是故意做成粗粒度的，只报 0.5、1、2、4、8 这几档，用来防止被拿去做指纹识别。所以「8」的意思是「8GB 或更多」，不是精确值。

检测到的硬件信息会上传吗？

不会。全是页面内的原生 API 调用，没有任何请求发出去。断网也能用。

为什么 70B 基本都显示跑不动？

因为这是事实。70B 即使压到 Q4_K_M 也约 43GB，单机要么 48GB 内存，要么两张 24GB 显卡。报「跑不动」不是保守，是免得你花两小时下载一个 40GB 的文件，最后发现加载就失败。
