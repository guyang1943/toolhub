UUID / ULID 生成

UUID v4、ULID、Nano ID 批量生成，可作数据库主键

关于UUID / ULID 生成

UUID 是 128 位的唯一标识符，v4 版本完全随机，碰撞概率可以忽略。ULID 则是 48 位时间戳加 80 位随机的组合，同样是 26 个字符，但按时间有序——这对数据库索引非常友好，因为新记录总是追加在末尾，不会像随机 UUID 那样造成页分裂。Nano ID 更短（默认 21 字符），适合对长度敏感的场景。

使用步骤

  1. 选择类型：UUID v4、UUID v7、ULID 或 Nano ID
  2. 设置数量（批量生成数据库种子数据很有用）
  3. 选择格式：带连字符、去连字符或大写
  4. 复制结果，直接用作主键、追踪 ID 或幂等键

常见错误

把随机 UUID 当安全令牌

UUID v4 不是密码学凭据，格式可预测性虽低但不保证不可枚举。邀请码、重置令牌请用密码学随机串。

随机 UUID 做聚类索引主键

无序主键会让插入总是发生在索引中间，造成页分裂和写放大。按时间有序的 ULID/v7 或自增 ID 更合适。

以为 UUID 全局唯一就万能

UUID 保证“ practically unique”，不是密码学承诺。对唯一性有强要求的账务场景仍要加数据库唯一约束兜底。

常见问题

数据库主键该用 UUID 还是自增 ID？

需要分布式生成、不暴露业务量时用 UUID/ULID；单库单表且追求极致索引性能时自增 ID 仍然简单有效。用 UUID 时优先 ULID 或 UUID v7 这类时间有序版本。

同一毫秒生成多个 ULID 会重复吗？

理论上同毫秒的随机部分可能碰撞。本工具做了单调递增处理，保证同一毫秒内连续生成也不重复。
