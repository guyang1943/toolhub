XML 格式化

XML 美化压缩并校验合法性，报错给出行号

关于XML 格式化

XML 的问题从来不是「看不懂」，而是「看不出来」：接口返回的 XML 常被压成一行，几百个标签连在一起，靠编辑器折行去找一个没闭合的 ，效率极低。格式化的价值不只是好看，而是把结构摊开，让错位的闭合标签一眼可见；再加上行号，报错位置就能直接跳过去。

使用步骤

  1. 把 XML 粘进输入框（可以是一整行，也可以是已经排过版的）
  2. 选「美化」并指定 2 或 4 空格缩进，或选「压缩」
  3. 解析失败时会给出第几行、什么原因，例如闭合标签对不上
  4. 复制结果；如果 XML 里有混合内容（文字与子元素混排），那部分会保持原样不被重排

常见错误

把压缩当成「去所有空格」

压缩只删元素之间的空白节点，文字内部的空格原样保留。看到压缩后仍有空格，那不是没生效，而是那些空格属于内容。

对混合内容期待自动排版

文字粗文字

这种结构如果重排，文字之间的空白会被改动，渲染结果就可能从「文字粗文字」变成多了几个空格。本工具选择不动它——需要重排请自己决定是否接受内容变化。

常见问题

为什么不直接用浏览器的 DOMParser？

DOMParser 只能告诉你「有错误」，行号藏在解析器内部，取不到稳定位置。这个工具自己扫一遍标签，所以每个错误都能落在具体的行上——而定位正是它主要的用途。

美化会不会改变内容？

会改变元素之间的空白（那本来就是排版），但不会动文字内部。遇到混合内容——同一个元素里既有文字又有子元素——整段保持原样，因为那里的空白在 XML 里是有意义的。

能校验 XSD 或 DTD 吗？

不能。这里只做「标签是否合法闭合」这一层：不加载 DTD、不检查命名空间、不展开自定义实体。需要 schema 校验请用 xmllint 这类工具。

原文件的 Tab 缩进会保留吗？

不会。美化统一用你选的 2 或 4 个空格重排，原缩进被丢弃；属性之间的换行也会被规整成单个空格。

为什么报错说「出现第二个根元素」？

XML 只允许一个根元素。常见原因是把两份 XML 拼在了一起，或者复制时把上文另一个文档的片段也带进来了。
