颜色对比度检查

按 WCAG 标准检查文字与背景的对比度是否达标

关于颜色对比度检查

对比度决定文字是否可读，是 WCAG 无障碍规范里最容易被忽略也最容易被审计卡住的一项。计算基于相对亮度：先按 sRGB 公式把通道线性化，再按 0.2126/0.7152/0.0722 加权求和，两份亮度的比值即对比度。

使用步骤

  1. 输入前景色（文字）与背景色，支持 HEX / RGB 直接粘贴
  2. 查看对比度数值与达标判定（AA / AAA）
  3. 选择文字规格：正文或大号文字，标准不同
  4. 按提示调整颜色，直到达标后再定稿设计规范

常见错误

只测静态忽略叠加态

hover、禁用、透明蒙版上的文字颜色会变，测的时候要把实际叠加后的颜色算进去，别只测设计稿里的基础态。

placeholder 用浅灰

输入框提示文字是最常见的对比度重灾区。placeholder 也要按正文标准达标，别用 #ccc 一类颜色。

只满足 AA 就收工

面向公众的服务、适老化界面建议直接按 AAA（7:1）设计，成本低一截，审计和投诉都少很多。

常见问题

4.5:1 和 7:1 分别是什么？

4.5:1 是 AA 级正文要求，7:1 是 AAA 级。大号文字（18pt 以上或 14pt 粗体）AA 只要求 3:1。

通过对比度就一定好读吗？

不一定。极高对比度（如纯黑配纯白）长时间阅读会疲劳，很多设计系统用 #1f2328 这类深灰替代纯黑。

AA 和 AAA 有什么区别？

WCAG 分三档：A 是最低要求，AA 是大多数法规和平台的实际标准（正文 4.5:1、大字 3:1），AAA 是增强级（正文 7:1）。把 AAA 当默认目标会让设计变得很灰，通常 AA 就够。

为什么大字号的标准更宽松？

因为笔画更粗，同样对比度下更容易辨认。WCAG 把「大字」定义为 18pt（约 24px）常规字重，或 14pt（约 18.66px）粗体以上。正文用 16px 时仍然按 4.5:1 要求。

色盲用户怎么考虑？

对比度只解决「亮度差」，不解决「颜色差」。红绿配色对红绿色盲几乎不可辨，即使对比度达标。所以状态不能只靠颜色区分，要同时加图标或文字——对比度检查管不到这一层。
