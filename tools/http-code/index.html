HTTP 状态码速查

输入状态码看含义、常见场景与排查方向

关于HTTP 状态码速查

状态码是服务端与客户端之间最省事的一次沟通：三位数字说清了「谁的问题、要不要重试、往哪查」。但实际排障时，人手里往往只有一个现象——页面发白、上传失败、网关报超时——而不是一个码。所以这份手册既能按码查，也能按现象反查，并且每条都写了「往哪查」，因为知道 504 叫网关超时并不解决问题。

使用步骤

  1. 手里有码就输三位数字，例如 404；手里只有现象就输关键词，例如「超时」「上传」
  2. 看返回的条目：含义、常见场景、排查方向
  3. 一次命中多个时，注意区分方向相反的码——408 是客户端发得慢，504 是上游回得慢
  4. 输入 4 或 50 这样的前缀，可以一次列出整组状态码

常见错误

只看状态码不看响应体

500 的背后可能是空指针，也可能是数据库连不上，状态码本身不区分。真正的原因在日志与响应体里，状态码只决定你从哪一层开始查。

拿 301 调试重定向

301 会被浏览器长期缓存，改回来时旧缓存仍然生效，看起来像「改了没用」。调试阶段先用 302，确认稳定后再换 301。

常见问题

502 和 504 到底差在哪？

502 是网关从上游收到了无效响应（进程崩了、端口没起、返回了非法内容）；504 是网关等上游响应等到超时。前者是「上游给了坏东西」，后者是「上游太慢或卡死」，排查顺序完全不同。

401 和 403 怎么快速区分？

401 是「你是谁不清楚」——没带凭证或凭证过期；403 是「知道你是谁，但不许」。看到 401 先查 Token，看到 403 先查权限与黑名单。

为什么我的接口返回了自定义码？

很多团队会在业务层定义 4 位或 5 位错误码，放在响应体里，HTTP 状态码仍然用 200。这类码不在本手册范围内，要看对应接口的文档。

状态码和业务错误码是什么关系？

两层。HTTP 状态码说协议层发生了什么，业务错误码放在响应体里说具体原因。很多接口一律返回 200、把失败写进 body，这时只看状态码会误判。

遇到 429 该等多久？

看响应头 Retry-After：可能是秒数，也可能是时间点。没有这个头时按指数退避重试（1s、2s、4s…），别原地死循环，那会让限流持续更久。
