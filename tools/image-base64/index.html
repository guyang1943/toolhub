图片转 Base64

图片与 Data URI / Base64 双向转换

关于图片转 Base64

Base64 把图片二进制编码成文本，从而能直接嵌进 HTML、CSS 或 JSON，省掉一次请求。代价是体积增加约 33%，因此只适合小图标；大图内联会拖慢首屏，得不偿失。反向操作（Data URI 还原成图片）在调试接口和邮件素材时同样常用。

使用步骤

  1. 选择图片，自动生成 Data URI（含 MIME 类型前缀）
  2. 复制结果，直接粘进 CSS 的 url() 或 HTML 的 src
  3. 反向模式：粘贴 Data URI 或纯 Base64 串，还原并下载图片
  4. 核对体积变化，超过 5KB 的图改用外链更划算

常见错误

大图内联

1MB 的图编码后约 1.33MB 全量进 HTML/CSS，首屏直接被拖慢。头像、banner 这类图老老实实走外链。

Data URI 中间换行

为了可读性手动折行会破坏编码，浏览器直接解析失败。要么不换行，要么用构建工具处理。

丢了 MIME 前缀

只有 Base64 串没有 data:image/png;base64, 前缀时，浏览器不知道按什么类型渲染，容易变成乱码或下载。

常见问题

多大的图片适合内联？

经验值是 5KB 以下。超过这个量级，单独的图片文件配合缓存反而是更优选择。

Data URI 在 CSS 里怎么用？

写成 background-image: url("data:image/png;base64,...")，注意引号包裹，且不要在中间换行。

和图片压缩配合怎么用？

典型流程是先用「图片压缩」把体积降到位，再转 Base64 内联。顺序反过来没有意义——Base64 只是换编码，不会让图变小，反而大 33%。所以先压后转，能得到的内联字符串最短。

Base64 会让文件变大多少？

固定约 33%，因为每 3 字节编码成 4 个字符。除了体积，它还有两个隐性代价：无法单独缓存（跟着 HTML/CSS 一起过期）、会阻塞渲染。所以只适合几 KB 的小图标。

能反向还原成图片吗？

能，把 data:image/...;base64, 开头的字符串粘回去即可下载成文件。排查「这个内联图到底是什么」时有用，也能用来恢复误删的图标资源。
