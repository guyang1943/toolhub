CSS 渐变生成器

可视化调 CSS 渐变，复制即用的 background

关于CSS 渐变生成器

CSS 渐变是最省成本的视觉效果：一行 background 就能让扁平的按钮有层次。麻烦的是角度——0deg 是从下往上，90deg 是从左往右，和很多人脑子里的「顺时针从右边开始」正好差 90 度。这里把预览和输出绑在同一套计算上，看到什么就贴什么。

使用步骤

  1. 填起始色与结束色（十六进制）
  2. 拖角度滑杆，预览实时更新
  3. 需要中间亮、四周暗就切径向
  4. 点「生成 CSS」，复制那一行 background

常见错误

把 0deg 当成「从左到右」

0deg 是从下往上。想左右过渡要用 90deg，这是最常见的错位来源，预览里一眼能看出来。

浅色渐变配白字

渐变两端的亮度差很大时，白字在某一段会读不清。按钮上的渐变要让整段都足够深，或者给文字加一层阴影。

常见问题

角度到底是什么方向？

0deg 从下往上（颜色从底部开始），90deg 从左往右，180deg 从上往下，270deg 从右往左。这是 CSS 规范的定义，和设计软件里的角度盘方向不一定一致。

为什么切到径向后角度没用了？

径向渐变的方向由圆心位置决定，这里是 circle at center（居中正圆），没有方向可言。角度参数对它无效，结果区会注明这一点，而不是假装它生效了。

颜色能写 rgb() 或颜色名吗？

不能，只认十六进制：3 位、6 位、8 位（带透明度）都行。不是偷懒——猜错颜色比直接报错更难查，而且十六进制是所有设计工具都能导出的格式。

为什么色标都写成 0% 和 100%？

省略位置时浏览器会自己插值，不同引擎的结果可能差一点。写死 0% / 100% 让输出在任何浏览器上都一样。

能加第三个颜色吗？

这个工具只做两色。三色以上建议手写 multi-stop，或者把两段渐变叠起来——参数一多，可视化界面反而比手写慢。
