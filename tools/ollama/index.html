Ollama · 官方在线版

一条命令在本机跑开源大模型

它解决什么问题

Ollama 解决的是「本地跑模型最后一百米」的问题：模型量化、显存分配、上下文窗口、OpenAI 兼容接口，这些原本要自己配的东西它都收进了一条命令里。官方首页第一句写的是 zero data retention——提示词不被存储、不被训练，因为推理压根没离开你的机器。代价也很实在：模型文件几 GB 起，第一次拉取要联网，跑多大的模型取决于你有多少内存。

装完在终端敲一行 ollama run 就能对话，不用注册、不用 Key、断网也能用；代价是模型文件几个 GB，7B 级别大约要 8GB 内存才跑得舒服。

数据边界

怎么用上：💻 需安装客户端（桌面应用，官网 ollama.com）

数据边界：本机处理 —— 模型权重下载到本机后推理全程在本机完成，官方首页写明「zero data retention / your prompts are never stored or trained on」。只有你主动改用 ollama.com 的云端模型，内容才发到他们的服务器。

你的提示词会去哪里

提示词进本机的推理进程，不出机器；显式切到云端模型才会外发。

三个典型使用场景

  1. 把一段不方便发给云端的合同或病历贴进去，让它总结要点
  2. 断网环境下（飞机上、内网机房里）需要一个能对话的模型
  3. 给本地写的小工具接一个 OpenAI 兼容的接口，不申请任何 Key

和 ToolHub 本地工具怎么配合

JSON 格式化：模型吐出来的 JSON 经常带多余的解释文字或少了逗号，贴进站内格式化工具校一遍，比在终端里逐字符找错快（本地工具，文件不上传）

字数统计：让它改写一段文案后，用字数统计确认没被悄悄删减或灌水（本地工具，文件不上传）

同类可替代方案

  • GPT4All —— 全本地的桌面 AI 客户端，文档问答也在本机
  • AnythingLLM —— 全本地的 AI 助手，文档问答与会议记录都在本机跑
  • ComfyUI —— 节点式图像生成工作流，本地跑扩散模型

使用时要注意什么

7B 级别的模型在 16GB 内存的机器上能跑，但速度只有每秒十几个字，长文档总结会很慢；模型能力与云端大模型有明显差距，别指望它一次写出能用的长代码。

常见问题

Ollama 是免费的吗？

Ollama 是开源项目，采用 MIT 许可证，官方在线版可以免费使用，不需要为基本功能付费。ToolHub 只做收录与说明，不代管你的数据，也不提供账号或存储服务。

Ollama 适合什么场景？

最常见的是这几种：把一段不方便发给云端的合同或病历贴进去，让它总结要点；断网环境下（飞机上、内网机房里）需要一个能对话的模型；给本地写的小工具接一个 OpenAI 兼容的接口，不申请任何 Key。判断标准很简单——如果你现在正为了这件事装一个几百 MB 的桌面软件，先用它试一次。

它和 ToolHub 的本地工具有什么区别？

ToolHub 的本地工具把代码放在你的浏览器里执行（WebAssembly 或原生 JS），文件不经过服务器；Ollama 由项目作者维护，数据在其服务器或你的浏览器中处理，具体取决于项目实现，使用前建议先看对方的数据政策。需要「绝对不上传」时可以改用站内同类工具。

用 Ollama 有什么限制？
