文本去重排序

按行去重、排序、去空行，适合清洗名单与日志

关于文本去重排序

去重与排序是数据清洗里最基础也最高频的操作：名单去重、日志归类、关键词整理、URL 清单合并。关键细节在于是否忽略大小写和首尾空格——严格模式下 Alice 与 alice 会被当成两条，往往不是想要的结果。

使用步骤

  1. 粘贴待处理的文本，一行一条
  2. 按需开启：忽略大小写、去除首尾空格、删除空行
  3. 选择排序方式（字典序 / 数字感知 / 长度）或保持原顺序
  4. 复制去重后的结果，或直接下载为 txt

常见错误

该忽略大小写时没开

名单里 Alice 和 alice 常被当成两条，统计人数虚高。清洗前先想好“重复”的定义。

看不见的空格

行尾半角空格让两条看起来一样的内容被判为不同。开“去除首尾空格”再对比。

排序规则不统一

同一次分析里别混用字典序和数字感知序，v2 和 v10 的相对位置会变，结论会自相矛盾。

常见问题

去重会保留哪一条？

保留首次出现的那条。开启忽略大小写后，输出的内容是按首次出现的原始写法，而不是全小写。

为什么排序结果和我预期不同？

中文排序依赖区域规则（localeCompare），数字与字母混排时也需要注意。需要严格 ASCII 序时请自行调整。

能忽略大小写去重吗？

可以。开启后 Apple 和 apple 视为同一条，保留首次出现的那条原文。这和直接转小写再比不同——输出保留原样，只是判断相等时忽略大小写，不会把你的数据改成小写。

能只去重不排序吗？

能。默认保留原始顺序，排序是独立的开关。顺序在很多场景下有意义（比如按时间追加的日志），去重时顺手排序会把这个信息毁掉。

空行和首尾空格怎么算？

空行默认会被去掉；首尾空格可以先清理再比对，否则「apple」和「apple 」会被当成两条。这是去重最常见的假阴性来源，处理名单类数据时建议默认打开。
