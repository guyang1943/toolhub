JWT 解码

解码 JWT 的 Header/Payload，标注过期时间，本地不上传

关于JWT 解码

JWT 由三段 Base64URL 组成：头部声明算法，载荷携带业务信息（用户 ID、权限、过期时间），签名用于验证来源。解码只是把前两段还原成 JSON，任何人都能做——所以解码成功不代表令牌有效，签名校验必须在服务端完成。

使用步骤

  1. 复制完整的 JWT（eyJ 开头的三段式字符串）
  2. 粘贴后自动分开显示 Header / Payload / Signature
  3. 重点核对 exp（过期时间）、iat（签发时间）与 scope 权限字段
  4. 过期或权限不符时联系签发方重新获取，不要手工改内容

常见错误

把解码当验签

解码零门槛，任何人都能构造一个能解码的假令牌。判断令牌可信度只能靠服务端验签。

在 JWT 里放敏感信息

Payload 只是 Base64，不是加密。手机号、内部标识这类信息不要放进去，只放非敏感的身份声明。

过期时间不看时区

exp 是秒级 UTC 时间戳，和本地时间对比前先换算。联调时“莫名 401”多半是这里差了几小时。

常见问题

解码出来的内容能直接用来判断权限吗？

不能。攻击者可以伪造任意载荷，只有服务端验签通过后的内容才可信。前端解码仅用于调试。

exp 是秒还是毫秒？

JWT 规范的 exp/iat/nbf 都是秒级时间戳。看到 10 位数字是正常的，13 位通常是实现方用了毫秒，需与签发方确认。
