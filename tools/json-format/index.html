JSON 格式化

美化/压缩 JSON，自动校验语法错误

关于JSON 格式化

JSON 格式化是把一段压缩或混乱的 JSON 文本，按照固定的缩进规则重新排版的过程。原始 JSON 常常是一整行，人眼几乎无法阅读；格式化之后每个键值对单独成行，嵌套层级用缩进表示，出错的括号位置也更容易定位。反过来，压缩（minify）会去掉全部空白字符，通常能把体积减少 30% 以上，适合放在请求体和配置文件里。

使用步骤

  1. 把接口返回、日志或配置里的 JSON 文本粘贴进左侧输入框
  2. 选择「格式化」（美化缩进）或「压缩」（去空白），可指定 2/4 空格或 Tab 缩进
  3. 有语法错误时，按提示的行列号定位到问题字符附近修改
  4. 用右侧折叠视图逐层检查结构，确认无误后复制结果

常见错误

尾随逗号

最后一对花括号前多写的逗号在 JavaScript 里合法，在 JSON 里直接报错。复制自代码对象时最常见。

全角标点冒充半角

中文输入法下的引号“”、冒号：形状和半角几乎一样，但 JSON 只认英文双引号和冒号，报错信息往往只指向行尾。

把压缩结果当成“另一种数据”

压缩不改变语义，只是去掉空白。不要因为压缩后“变短了”就以为内容被裁剪过。

常见问题

格式化会不会改变 JSON 的内容或语义？

不会。JSON 规范中空白字符不参与语义，格式化只改变排版，键值顺序和数据内容完全不变。

遇到 Unexpected token 报错怎么办？

把光标定位到报错提示的位置附近，常见原因包括：多了一个尾随逗号、用了单引号而不是双引号、注释（JSON 标准不支持注释）、中文全角标点。

粘进来的 JSON 会传到服务器吗？

不会。格式化、校验、折叠全部在浏览器里用 JavaScript 完成，页面没有任何把文本发出去的请求。断网之后这个工具照样能用——这一点你可以自己验证：拔掉网线再打开它。

支持多大的 JSON？

几十 MB 的文本能解析，但折叠视图会明显变卡，因为它要为每个节点生成 DOM。超过 10 MB 建议先压缩看整体结构，或者改用命令行的 jq。浏览器里做单次文本解析，几万行是舒服的区间。

JSON5、JSONC 和标准 JSON 有什么区别？

标准 JSON 不允许注释和尾随逗号；JSON5 允许注释、单引号、不加引号的键名；JSONC 是「JSON + 注释」，VS Code 的配置文件用它。本站按标准 JSON 校验，所以带注释的配置文件会报错——那不是文件坏了，是格式本来就不合法。
