音视频信息

本地读取音视频时长分辨率与体积，不上传

关于音视频信息

发视频前最常问的两个问题是「会不会超时长」「会不会超体积」。这两个数不用上传、不用转码就能读出来：浏览器自己的解码器在加载元数据时就会给出时长与分辨率。代价是它读不出编码格式——那需要解容器，浏览器没把这件事暴露给页面。

使用步骤

  1. 选一个视频或音频文件
  2. 等元数据加载（通常一瞬间）
  3. 看时长、分辨率、体积与平均码率
  4. 读不出会直接给一句人话，不会一直转圈

常见错误

把平均码率当成平台上限

平台限制通常写的是「码率不超过 X」，指的是峰值。平均码率达标不代表不会被打回，转码时把峰值也压住才稳。

竖屏视频宽高看反

1080×1920 是竖屏，1920×1080 是横屏。看到前者不用奇怪，那是正常的竖屏分辨率。

常见问题

文件会上传吗？

不会。用 object URL 交给 video / audio 元素读元数据，文件始终在本机内存里，读完即释放。

为什么读不到编码格式（H.264 / AAC）？

那要解析 MP4 的 moov 或 WebM 的 EBML 容器结构，浏览器不给页面这个能力。能拿到的是解码器解码后的元数据：时长、分辨率、是否有音轨。

平均码率是怎么算的？

体积 × 8 ÷ 时长。这是平均值：可变码率（VBR）的视频，峰值可能比它高不少。要判断平台限流，看这个数和时长就够。

MKV / AVI 为什么读不出来？

Chrome 与 Edge 不带这些容器的解码器。这里会等 8 秒然后给一句提示，而不是无限转圈。想看得先转成 MP4。

时长显示得和我印象里不一样？

有两种可能：文件被截断过（元数据里的时长比实际长），或者 VBR 音频的估算时长有偏差。差一两秒正常，差很多就是文件本身的问题。
