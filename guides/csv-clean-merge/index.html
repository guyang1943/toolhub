把一堆乱 CSV 洗成一张能用的表

编码乱码、表头不一致、日期三种格式、还要多表合并——按顺序洗一遍，比在 Excel 里手改快十倍。

教程 / 把一堆乱 CSV 洗成一张能用的表
难度 入门约 35 分钟风险 低最后核对 2026-11-26
从系统导出的 CSV 几乎不会是干净的：中文变乱码、表头每张表都不一样、日期有「2026/11/26」「2026-11-26」「11/26/2026」三种、金额带千分位和全角空格。手工在 Excel 里改十行还行，一千行就是折磨，而且改到第三遍必然会漏。清洗的顺序是有讲究的——编码不对，后面看到的全是乱码；表头不统一，合并时就对不上列。这篇按固定顺序过一遍，每一步只解决一类问题，做完的表格能直接拿去分析或导入别的系统。

为什么值得折腾

  • 顺序错了会白干。先改日期再修编码，日期格式的判断会因为乱码而失效，改完还得重来一遍。
  • 手工改的东西没法复用。下个月再来一份同样的导出，脚本和工具链可以重跑，手改要从头开始。
  • 合并出错最难发现。两张表拼起来行数不对、金额对不上，往往到出报表时才被发现。留下校验步骤能提前拦住。

开工前要有的

  • 原始 CSV 文件，并且**先复制一份留底**。后面所有操作都在副本上做。
  • 知道这张表的主键是什么（订单号、身份证号、手机号），或者至少知道哪几列组合起来唯一。没有主键的话，去重只能靠整行比对，效果差很多。
  • 能打开终端，或者愿意用站内的表格工具。纯 Excel 也能做，但一千行以上会明显变慢。

步骤

  1. 先留底，再动手

    复制一份命名为 xxx.raw.csv，之后只改 xxx.csv。这不是形式主义：清洗最常见的翻车是「改到一半发现过滤器写错，删了不该删的行」，而 CSV 没有撤销历史。

    留底还有个附带好处——最后校验时，用原始文件的行数、金额合计去对，能发现中间某一步是否误删。

  2. 第一步永远是编码

    中文 Excel 导出的 CSV 默认是 GBK，而大部分工具按 UTF-8 读，于是出现「鍏徃鍚嶇О」这种乱码。判断方法：用文本编辑器打开，中文正常就说明编码对；乱码就换编码再打开。

    转换（命令行，Windows 下用 Git Bash）：

    iconv -f GBK -t UTF-8 input.csv > output.csv

    另一个坑是 UTF-8 BOM：Excel 打开带 BOM 的文件才会正确显示中文，但很多程序读第一列时会带上一个不可见的 \ufeff，导致「列名匹配不上」。如果下游是程序，存成不带 BOM 的 UTF-8；如果下游是人用 Excel 看，带 BOM 更省事。这是两种用途，别混。

  3. 统一表头：改列名，不动数据

    多张表合并前，先把列名统一成一套。原则是「改列名，不改数据」——数据一旦被改，原始含义就丢了。

    常见的不一致：

    - 同一列在不同表里叫「手机号」「手机」「联系电话」。 - 表头带空格或换行：「 姓名 」「金额\n(元)」。 - 表头有合并单元格，导出后变成空列名或 Unnamed: 0。

    处理方式：先统一去掉首尾空格、把全角空格换成半角，再建立一张映射表（旧名 → 新名），批量替换。列的顺序也要统一，否则合并后会出现「有的行姓名在第二列、有的在第五列」。

  4. 拆列与并列：注意引号里的逗号

    CSV 里最经典的坑：地址是「北京市朝阳区, 建国路 1 号」，中间那个逗号如果没被引号包住，整行会多出一列，后面所有列都错位。

    正确的 CSV 会给含逗号的字段加双引号，字段内的双引号写成两个（""）。拆分时用能识别引号的解析器，不要用字符串 split(',')——那就是错位的来源。

    需要把「省市区」拆成三列时，按最后一个分隔符拆更稳；需要把两列拼成一列时，先确认两列都非空，否则会出现「北京市 null」。

  5. 去重：按主键，不按整行

    整行去重只能去掉完全相同的行。同一笔订单导出了两次，第二次可能只是时间戳差一秒，整行比对抓不到。

    正确做法是按主键去重，并决定保留哪一条：

    # 按第 1 列（订单号）去重，保留最后一次出现
awk -F, '!seen[$1]++' input.csv > dedup.csv

    但保留第一条还是最后一条，结果可能完全不同（状态字段会不一样）。业务上的规则要先想清楚：通常保留「最新状态」那条，所以导入前按时间排序，再取最后一条。

    去重之后必须核对行数：原始多少行、去重后多少行、去掉的是不是都是重复项。数字对不上就停下来查。

  6. 合并：纵向堆和横向连是两件事

    纵向合并（union）是把多张同结构的表摞起来。前提是列名和列顺序完全一致，否则会出现「A 表的金额跑到 B 表的备注列」。合并后加一列「来源文件」，出问题时能追溯。

    横向合并（join）是按主键把两张表拼宽。必须确认三件事：

    1. 两边的键类型一致（一边是文本「001」，一边是数字 1，就对不上）。 2. 有没有一对多（一个订单多条明细），那会让行数膨胀。 3. 匹配不上的行怎么处理——inner join 会静默丢掉它们。

    合并后立刻查两个数：行数是否等于预期，以及键的唯一性。

  7. 日期和数字：统一成一种能被机器读的格式

    日期统一成 YYYY-MM-DD。下面这些写法要全部归一：2026/11/26、2026.11.26、26-11-2026、2026年11月26日。

    有一类特别危险：11/12/2026，美式是 11 月 12 日，英式是 12 月 11 日，无法从数据本身判断。遇到这种必须问数据来源，不能猜——猜错会在月报里差出一个月。

    数字方面：去掉千分位逗号、去掉货币符号、把全角数字和全角空格转半角。金额保留两位小数，不要用四舍五入到整数，累加时会差钱。

  8. 校验：三个数字对得上才算洗完

    最后一定要跑一遍校验，不要凭「看起来没问题」交付：

    1. 行数：清洗后的行数 = 原始行数 − 确认删除的重复/无效行。 2. 合计：金额列求和，与原始文件的合计对比（允许分位差）。 3. 空值：关键列（主键、金额、日期）的空值数量，逐个确认为什么空。

    再抽 3–5 行人工核对，从原始文件里找对应的记录，看字段是否一一对上。抽样时优先挑边界值：金额最大的一行、日期最早的一行、名字最长的那个。

  9. 留痕：让别人（和半年后的自己）能复现

    在同目录放一个 README.txt，写清：原始文件从哪来、什么时候导的、做了哪几步处理、每一步删了多少行、校验结果是多少。

    如果处理用了命令或脚本，把命令也贴进去。半年后有人质疑数字，你能拿出来复现；没有这份记录，只能重做一遍，而重做的结果很可能不一样。

翻车了怎么办

  • iconv 报 illegal input sequence：说明文件里混了两种编码，或者本身不是 GBK。用 file -i 看它认为是什么，再用编辑器（VS Code 右下角可切换编码）打开另存为 UTF-8。
  • Excel 打开中文还是乱码：存成了不带 BOM 的 UTF-8。用 Excel 的「数据 → 从文本/CSV」导入，手动选 UTF-8，或者另存一份带 BOM 的。
  • 合并后列错位：某行有未转义的逗号。找出列数异常的行（awk -F, 'NF!=期望列数'），修好再合并。
  • 行数怎么都对不上：先查空行（末尾的换行会产生一行空记录），再查筛选条件是否把空值排除了。
  • 数据量大到 Excel 打不开：用目录里收录的 DuckDB（直接对 CSV 跑 SQL），或者站内的 pandas 工具，几百万行也没问题，别硬撑 Excel。

容易踩的坑

在 Excel 里直接打开 CSV 再保存
Excel 会按本地设置猜编码和日期格式，保存时还可能改掉前导零（001 变成 1）、把长数字转成科学计数法（身份证、银行卡号后四位变 0000）。要么用导入功能显式指定列类型，要么全程用文本工具处理。
用逗号 split 解析 CSV
字段里有逗号、引号、换行时全部错位，而且错得很隐蔽——前面几行正常，某一行开始整体偏移。用正经的 CSV 解析器，或者至少用能处理引号的工具。
inner join 之后没查丢了多少行
匹配不上的行会静默消失，报表数字看起来「合理」但其实少了一块。合并后第一件事就是对比左右两边的行数和键集合。
原始文件被覆盖
所有清洗都在同一个文件上做，改错了无法回溯。留一份 .raw 副本，成本是几 MB 磁盘。

常见问题

没有编程基础，只用 Excel 能做到吗？
能。编码用「数据 → 从文本/CSV」导入时选对编码；表头统一用查找替换；去重用「数据 → 删除重复值」；合并用 Power Query（数据 → 获取数据）。Power Query 的好处是步骤可保存，下次换一份同样的文件点一下刷新就重跑完。
几十万行，Excel 卡死了怎么办？
用目录里收录的 DuckDB，或者站内的 pandas 工具，直接对 CSV 跑 SQL，比如 SELECT 订单号, SUM(金额) FROM 'x.csv' GROUP BY 1。它不把整表加载到界面里，几百万行也是秒级。
怎么快速发现哪几行列数不对？
用 awk 按逗号数一下每行的字段数，和表头对比（先 print NF，再 sort | uniq -c 统计频次）。输出里除了正常列数之外的那个数字，就是异常行的数量；再用条件 NF != 正常列数 把它们单独列出来。命令和第 4 步是同一套，只是判断条件从「按主键去重」换成「列数不等于表头」。
导出的表每次列顺序都不一样，有办法吗？
有。固定一个目标列顺序，每次导入后按列名重新排列（pandas 的 df[cols] 或 Excel 的选择列）。不要按位置对列，按名字对——位置会变，名字相对稳定。
