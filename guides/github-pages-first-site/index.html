🌐 零基础发布第一个网站（GitHub Pages 篇）

注册 GitHub、建仓库、传一个 HTML 文件，45 分钟让网站在网上能打开，全程免费、不碰命令行。

教程 / 零基础发布第一个网站（GitHub Pages 篇）
难度 入门约 45 分钟风险 低最后核对 2026-11-05
GitHub Pages 是 GitHub 免费提供的静态网站托管：你把网页文件放进一个仓库，它就帮你发布成全世界都能打开的网站。不用买服务器、不用装软件、不用学命令行，全程在浏览器里点鼠标就能完成。做完这篇，你会得到一个属于自己的网址：https://你的用户名.github.io/仓库名/。

为什么值得折腾

  • 全程免费：公开仓库开 Pages 不花钱，个人主页、小作品、简历站都够用。
  • 不用买服务器：文件放在 GitHub，发布和 HTTPS 证书都由它负责。
  • 改了就自动更新：仓库里的文件一改，几分钟后网上的页面跟着变。

开工前要有的

  • 一个常用邮箱，用来收 GitHub 的验证码。
  • 一台能上网的电脑或手机，浏览器即可。
  • 一段想放上网的内容：自我介绍、简历、作品链接都可以，没有的话跟着第 3 步抄示例代码。

步骤

  1. 注册一个 GitHub 账号

    打开 github.com/signup。按顺序填三样：邮箱（常用邮箱，验证码发到这里）、密码（至少 8 位，包含数字和小写字母）、用户名（小写字母、数字和连字符；用户名会出现在你的网址里，起个你喜欢的）。点继续后，GitHub 会往邮箱发一个验证码，回到邮箱找到发件人是 noreply@github.com 的邮件，把验证码填回去点 Verify。接下来会问要不要选付费计划，选 Free（免费）即可；个性化问卷可以直接点 Skip personalization 跳过。看到页面左上角出现你的头像和 Dashboard（仪表盘），账号就建好了。术语解释：用户名（username）就是你在 GitHub 上的公开名字，别人通过 github.com/你的用户名找到你。

  2. 新建一个仓库（放网站文件的文件夹）

    登录后点页面右上角的 + 号，选 New repository（新建仓库）。Repository name（仓库名）填一个英文名，比如 my-first-site（小写字母、数字、连字符，不要用中文和空格）。下面选 Public（公开）——免费账号只有公开仓库能开 Pages，这一步别选错。再把 Add a README file（添加说明文件）勾上。最后点绿色的 Create repository（创建仓库）。成功后你会进入仓库页面，看到一个 README.md 文件。术语解释：仓库（repository）就是 GitHub 上放文件的文件夹，一个网站对应一个仓库；README.md 是项目的说明书，打开仓库第一眼看到的就是它。

  3. 把首页文件 index.html 传上去

    点仓库上方的 Code（代码）标签页，再点绿色的 Add file（添加文件）按钮，选 Upload files（上传文件）。把你准备好的 index.html 文件拖进虚线框。如果你没有现成文件，改用另一条路：点 Add file → Create new file（新建文件），文件名框里填 index.html，下面编辑框粘贴这段最简单的网页代码：

    <!DOCTYPE html>
<html lang="zh-CN">
<head><meta charset="utf-8"><title>我的第一个网站</title></head>
<body><h1>你好，这是我的第一个网站</h1><p>用 GitHub Pages 免费发布。</p></body>
</html>

    然后拉到页面下方，Commit changes（提交更改）区域不用改，直接点绿色的 Commit changes 按钮。成功后文件列表里出现 index.html。术语解释：index.html 是网站首页的固定文件名，浏览器打开网址时默认找的就是它；Commit（提交）就是把这次改动存成一个版本，之后随时能找回。

  4. 打开 Pages 开关

    点仓库名下方的 Settings（设置）标签页。在左侧菜单找到 Code, planning, and automation 这一组，点里面的 Pages。（若界面分组名略有不同，以 Pages 为准。）页面上方 Build and deployment（构建与部署）下面，Source（来源）选 Deploy from a branch（从分支部署）。Branch（分支）那里选 main，右边文件夹选 /(root)（根目录），点 Save（保存）。术语解释：分支（branch）是仓库里的一条文件线，默认就叫 main；/(root) 意思是网站文件放在仓库最外层，不用进子文件夹。

  5. 等几分钟，打开你的网址

    保存后页面上方会出现一行提示：Your site is live at https://你的用户名.github.io/仓库名/（你的网站已上线）。点这个链接打开，看到你写的页面就成功了。做完可把网址生成二维码印在名片上（ToolHub 的二维码生成工具）。如果点开是 404（找不到页面），先别慌：第一，确认文件名是 index.html 且在仓库根目录；第二，确认第 4 步的分支选的是 main；第三，等一等——官方说明改动后最多 10 分钟才生效，刷新几次或换个浏览器再试。

  6. 改一行字，验证它真的会更新

    回到仓库，点开 index.html 文件，再点右上角的铅笔图标（Edit，编辑）。改一行字，比如把标题改成你的名字，拉到下方点 Commit changes。等几分钟后刷新你的网址，看到新标题，就说明你已经掌握了“改文件 → 自动发布”的完整循环。以后想换内容，重复这一步就行。

  7. （可选）把仓库改名，做成个人主页

    如果你想让地址更短，可以把仓库名改成 你的用户名.github.io（比如用户名是 xiaoming，仓库名就叫 xiaoming.github.io）。改法：Settings → General → Repository name → Rename（重命名）。改完后网址变成 https://你的用户名.github.io/，不用再带仓库名。注意：改名后旧地址会失效，已经分享出去的链接要更新；而且一个账号只能有一个这样的“用户主页”仓库。术语解释：这种叫用户主页（user site），一个账号一个；前面做的叫项目主页（project site），一个仓库一个，可以有无数个。

翻车了怎么办

  • 打开是 404：先确认文件名是 index.html（不是 index.htm、不是 Index.html，大小写敏感），且放在仓库根目录；再确认 Settings → Pages 里分支是 main、文件夹是 /(root)；最后等满 10 分钟再刷新。
  • 页面还是旧内容：构建需要几分钟；按 Ctrl+F5（Mac 是 Command+Shift+R）强制刷新，绕开浏览器缓存。
  • Settings 里找不到 Pages：仓库必须是 Public（公开）；私有仓库开 Pages 要付费版——个人仓库需 Pro，组织仓库需 Team 及以上，免费账号不行。
  • 想删掉网站：Settings → Pages → 把 Source 改回 None（不部署），或直接删除仓库。

容易踩的坑

仓库名用了中文或空格
仓库名会直接出现在网址里，中文和空格会变成一串百分号编码，又长又难看。只用小写字母、数字和连字符。
把 Pages 当成动态服务器
Pages 只托管静态文件（HTML、CSS、JavaScript、图片），跑不了 PHP、Python、数据库，也不能收表单、做登录。想做这些要另外找后端服务，Pages 本身免费但能力边界就在这里。
公开仓库里放了隐私内容
Public 仓库人人可见：别放密码、密钥、身份证号、手机号。只放愿意公开的东西。
一个账号的网站数没概念
一个仓库对应一个网站，但一个账号可以建很多个仓库，也就是很多个网站。只有 用户名.github.io 那个是特殊的个人主页，一个账号只能有一个。

常见问题

真的全程免费吗？有什么限额？
免费账号的公开仓库开 Pages 不花钱。官方限额（以官网为准）：发布后的网站不大于 1 GB，仓库建议不大于 1 GB，每月流量软限额 100 GB，每小时构建软限额 10 次（用 GitHub Actions 部署的不计这 10 次）。个人主页和作品站离这些上限远得很。
网站能用来做网店或接单吗？
不行。GitHub 明确说明 Pages 不适合、也不允许用作在线商店、电商或主要面向商业交易的网站。个人主页、作品集、博客、文档站是它的正确用途。
改了文件多久能看到？
官方说明最多 10 分钟，通常几分钟。一直不变就按 Ctrl+F5 强制刷新，或检查是不是改错了文件。
以后想换个好看的主题怎么办？
GitHub Pages 内置 Jekyll 主题，在仓库里加一个 _config.yml 文件写一行 theme: jekyll-theme-minimal 就能换——但只对 Markdown 页面生效，本篇的纯 HTML index.html 不受它影响。这是进阶玩法，先把这篇跑通再说。
