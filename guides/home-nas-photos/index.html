把旧电脑变成家庭相册服务器

手机照片自动备份到自己的硬盘，按日期分好目录、去掉重复、再用虚拟内网在外面也能看。

教程 / 把旧电脑变成家庭相册服务器
难度 中等约 50 分钟风险 中最后核对 2026-11-26
手机相册是云盘里最贵的那部分：照片和视频体积大、增长快，免费额度撑不过两年，之后每月为「已经不看了的旧照片」付费。而这些照片真正的价值是「十年后还能打开」，不是「随时在云端」。这件事一台旧笔记本就能做：装一个 Linux，挂上硬盘，用 Syncthing 把手机相册目录单向同步过来，照片就落在自己的盘上。整个过程不需要公网 IP，也不需要买 NAS。

为什么值得折腾

  • 容量成本差一个数量级。1TB 移动硬盘两三百块，同等容量在云盘上是每年几百块的订阅，而且逐年续。
  • 照片不需要「随时在线」。它的使用场景是偶尔翻看和长期保存，本地盘 + 一份异地备份就够，不需要为随时随地的读取付钱。
  • 隐私边界清楚。原图不出门，分享时再单独处理（去掉位置信息、压缩），主动权在自己手里。

开工前要有的

  • 一台还能开机的旧笔记本或迷你主机，最好带一块能装的硬盘。笔记本的优点是自带电池，相当于内置 UPS，短暂停电不会伤盘。
  • 一块容量足够的硬盘。照片按每年 30–60GB 估（含视频会更多），2TB 起步比较从容；有第二块盘做备份更好。
  • 一个 U 盘用来装系统（Ubuntu Server 或 Debian，8GB 以上）。
  • 手机上装 Syncthing（Android 用 Syncthing-Fork，iOS 用 Möbius Sync）。iOS 的后台同步限制比 Android 严，需要有心理准备。

步骤

  1. 先定清楚：这不是 NAS，是「照片的家」

    别一上来就追求全功能 NAS（媒体库、虚拟机、下载器）。目标越窄越容易做成：手机相册自动备份 + 能按日期找到 + 外面能看 + 有第二份。这四个需求，Syncthing + 文件系统 + Tailscale + 一块备份盘就能全部覆盖，不需要任何 Web 界面。功能越少，三年后还在跑的概率越高。

  2. 装系统，只装 SSH 服务

    Ubuntu Server 安装时勾选 OpenSSH server，其余不装。装完第一件事是固定 IP：在路由器里给这台机器的 MAC 绑定一个局域网地址，别用 DHCP 碰运气——地址一变，手机上的同步目标就全断了。

    然后更新一次：

    sudo apt update && sudo apt upgrade -y
sudo apt install -y htop smartmontools

    smartmontools 用来读硬盘健康状态，后面会用到。

  3. 挂硬盘：用 UUID，不用 /dev/sdX

    先找到硬盘的 UUID：

    lsblk -f
sudo blkid

    然后在 /etc/fstab 末尾加一行（UUID 换成你自己的，挂载点先建好）：

    UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx /srv/photos ext4 defaults,nofail 0 2

    nofail 很重要：盘没插或坏了的时候，系统还能正常启动，不会卡在紧急模式。用 /dev/sdb1 这种名字迟早会错位——插拔一次 U 盘，顺序就变了，轻则挂载失败，重则把数据写到别的盘上。

  4. 目录结构：按年/月，别按相册名

    手机里的相册是「人建的分类」，会改名、会合并、会有同一个相册两套。落盘时按拍摄日期分：

    /srv/photos/
  2026/
    2026-11/
      IMG_20261126_183012.jpg

    按日期分的好处是十年后不依赖任何软件的数据库也能翻，而且备份、迁移、去重都以月为单位可控。文件名保留原始名，不要改成「旅行1.jpg」——原始名里通常带日期和设备信息，是最后的线索。

  5. 装 Syncthing：点对点，不经过第三方服务器

    Syncthing 的同步是设备之间直连（同一局域网内直接走内网），发现服务器只负责牵线，不传文件内容。装：

    sudo apt install -y syncthing
sudo systemctl enable --now syncthing@$USER

    然后打开 http://主机IP:8384 进 Web 界面，设一个 GUI 密码，添加文件夹：路径填 /srv/photos，文件夹 ID 自己起一个（比如 photos），类型选「仅接收」（Receive Only）——这一条是关键，免得哪天手滑在服务器上删了东西，反过来把手机里的删掉。

  6. 手机端：只同步相机目录，并且单向

    Android 的 Syncthing-Fork 里添加同一个文件夹 ID，本地路径选相机目录（DCIM/Camera），模式选「仅发送」（Send Only）。两个设备一个只发一个只收，方向就锁死了。

    iOS 的 Möbius Sync 只能同步应用沙盒里的目录，需要手动把照片「导出」进去；想要全自动，iOS 这条路会让人失望，老老实实用 iCloud 或换 Android 旧手机当备份端更现实。

    iPhone 用户还有个折中：把旧手机留在家里插着电当同步端，相册直接同步到服务器。

  7. 去重与清理：按内容哈希，不按文件名

    同一个视频被转发、截图、再保存一遍，会得到三个不同的文件名和相同的内容。清理时按 SHA-256 比，不按名字和大小：

    find /srv/photos -type f -size +1M -print0 \
  | xargs -0 sha256sum | sort | uniq -w64 -d

    站内的文件哈希工具可以在浏览器里对单个文件算，适合抽查。批量清理前务必先备份——去重脚本写错一个参数就是批量删除，没有撤销。

  8. 在外面也能看：虚拟内网，不开端口

    不要在路由器上给 Syncthing 或 SMB 开端口。用 Tailscale：

    curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

    装完这台机器会拿到一个 100.x 开头的虚拟内网地址。手机装同一个客户端、登录同一账号，就能在 4G 下直接访问 http://100.x.x.x:8384，或者在手机文件管理器里挂 SMB。没有公网 IP、没有端口映射、没有暴露面——扫描器根本看不到这台机器。

  9. 备份：第二块盘，加上「能不能恢复」的验证

    同步不是备份。手机误删会在几秒内同步到服务器，所以你还需要一份不会被同步改写的副本。最省事的做法是第二块盘 + rsync：

    rsync -a --delete /srv/photos/ /srv/backup/photos/
smartctl -H /dev/sda

    注意 --delete 只在「备份盘的目标目录」上生效，源和目标写反就是灾难。smartctl 每季度看一次，出现 FAILED 或重映射扇区增长就换盘——硬盘坏之前通常有征兆，只是没人看。

翻车了怎么办

  • 手机连不上服务器：先在同一个 Wi-Fi 下用浏览器打开 http://主机IP:8384 确认服务活着；再看防火墙（ufw status）是否放行 8384 和 22000；最后检查两台设备的文件夹 ID 是否完全一致。
  • 同步了但看不到文件：检查「仅接收」模式下对方是否还在传输，Web 界面里会显示进度。卡在 99% 通常是某个大视频的权限或磁盘空间问题。
  • 硬盘挂载失败：dmesg | tail 看内核报错。文件系统损坏时先 umount 再做 fsck，不要在挂载状态下修。数据重要的话，先把盘接到另一台机器上只读拷贝一遍再动手。
  • 手机端耗电明显：把同步限制为「仅充电时」和「仅 Wi-Fi」，这两个开关能解决大部分耗电投诉。

容易踩的坑

把同步当成备份
同步是「两边一样」，包括一样地被删掉。误删、勒索软件加密、脚本写错，都会在几秒内同步到每一台设备。备份必须是「只增不改」的副本：另一块盘、另一个目录、或者对象存储。
用 /dev/sda 写 fstab
盘符由内核枚举顺序决定，插一块新硬盘或改一次 BIOS 启动顺序就可能变。写错的结果轻则开机进紧急模式，重则挂载到错误的盘上。UUID 不会变，这是唯一正确的写法。
iOS 上期待全自动
iOS 不允许第三方应用在后台长期访问相册，所以「自动同步」在 iPhone 上做不到真正无感。要么定期手动导出，要么留一台 Android 设备或旧 iPhone 在家当同步端。先接受这个限制，再选方案，不然会在工具之间来回换。
只在局域网里能用，就以为够了
照片服务器最大的价值在于「很多年后还打得开」。如果它只在家里的路由器后面，那么搬家换网络、路由器重置、IP 变更都会让它消失。把访问方式（Tailscale）和发现方式（固定 IP + 记号）一起写下来，贴在机器上。

常见问题

一定要用 Linux 吗？Windows 行不行？
行。Windows 上装 Syncthing 一样能用，照片放在 D 盘。但 Windows 自动更新会重启、休眠会断同步、盘符会变，长期 24 小时跑没有 Linux 稳。如果这台机器只干这一件事，装 Linux 更省心；如果还想当日常电脑用，Windows 也能接受，记得关掉自动休眠。
手机照片备份完，能删掉手机里的吗？
确认两件事再删：服务器上能看到原图（不是缩略图）、并且备份盘上也有了一份。然后建议先删一小批试试，确认恢复路径可用（从服务器拷回手机能打开），再批量清理。手机空间不够时，优先删视频，照片留着更省事。
照片要不要按人脸/地点分类？
想要的话有现成的：Immich 提供类似 Google 相册的界面和人脸聚类，可以跑在同一台机器上。代价是它吃内存和 CPU（人脸识别首次扫描会比较久），并且它的数据库也需要一起备份。先把「照片不丢」做扎实，再考虑加界面。
旧笔记本的电池会不会鼓包？
长期插电确实有风险，尤其是老机器。处理办法：把电池拆下来（如果可拆），或者用 BIOS 里的电池保护模式（限制充到 60%）。放在通风处、别垫在布上，每季度摸一下底面温度。这类机器当服务器，散热比性能更值得关心。
