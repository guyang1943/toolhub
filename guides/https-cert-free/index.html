免费 HTTPS 三条路，按你的情况选一条

托管平台自带、Cloudflare 一键、Let's Encrypt 自动续期——证书不花钱，坑在回源和混合内容。

教程 / 免费 HTTPS 三条路，按你的情况选一条
难度 入门约 35 分钟风险 低最后核对 2026-11-26
现在拿一张 HTTPS 证书已经不需要花钱，难的是选对路径：站点托管在 GitHub Pages 或 Vercel 上，证书是平台送的，你什么都不用做；套了 Cloudflare，证书在边缘就有，但回源那一段可能是明文；自己管服务器，就得让证书自动签、自动续。三条路对应三种处境，选错会出现「浏览器有小锁，但数据在链路上裸奔」或者「三个月后证书过期，站点打不开」。这篇先把证书到底在证明什么说清楚，再按处境给三条可执行的路。

为什么值得折腾

  • 不加密的站点在现代浏览器里已经被标记为「不安全」，登录框、表单都会被警告，输入法插件也会提醒用户。这不是形象问题，是转化问题。
  • 搜索引擎把 HTTPS 当排名因素，Chrome 也会对 http 页面做降级提示。免费能拿到的东西，没有理由不做。
  • 证书自动化之后是零维护。真正会出事的不是「没配」，而是「配了但忘了续」——三个月后过期当天才发现的站点，每年都有。

开工前要有的

  • 先确认你的站点在哪：托管平台（GitHub Pages、Vercel、Netlify）、CDN 后面、还是自己的服务器。三条路的分岔就在这里。
  • 有自己的域名，并且能改 DNS 记录。没有域名就没有证书申请的主体，这一步绕不开。
  • 如果是自己的服务器：能 SSH 登录、能改 Nginx/Caddy 配置、80 和 443 端口对公网开放（家用宽带常被封 80，见第 5 步）。
  • 会用 curl -I 看响应头，会用 openssl s_client 看证书。两条命令，本篇只用这两个工具做验证。

步骤

  1. 先搞清楚证书在证明什么

    证书只证明一件事：你连上的这个域名，确实由持有域名控制权的人提供服务。它不证明站点内容可信，也不证明网站是正规公司。所以「有小锁」只代表链路加密 + 域名对得上，看到小锁就往里填身份证号仍然是错的。

    顺带一个概念：证书是绑定域名的，www 和裸域是两张证书（或一张多域名证书）。只配了 www，访问裸域照样报错。

  2. 路线 A：托管平台自带，什么都不用做

    GitHub Pages、Vercel、Netlify、Cloudflare Pages 都给免费证书，签好自动续。你要做的只有两件事：在平台后台确认「强制 HTTPS」是开的，以及确认自定义域名已经验证通过。

    验证方法：

    curl -sI http://你的域名 | head -3

    返回 301 或 308 且 Location 指向 https，就对了。返回 200 说明还在用 http 提供服务，去后台打开强制跳转。这一条经常被忽略——HTTPS 能用，但用户从 http 进来时没有跳转。

  3. 路线 B：Cloudflare，注意回源那一段

    把域名 NS 交给 Cloudflare，开代理（橙色云），边缘就有了证书，浏览器到 Cloudflare 这一段是加密的。关键在「Cloudflare 到你的服务器」这一段，SSL/TLS 模式有四个选项：

    - Flexible：回源走 http，明文。不能用。它会让「浏览器显示安全」成为假象，而且容易造成重定向死循环。 - Full：回源走 https，但不校验证书真假。能用，比 Flexible 好。 - Full (strict)：回源 https 且校验证书。推荐，服务器上要有一张有效证书（可以是 Let's Encrypt，也可以是 Cloudflare 的 Origin Certificate）。 - Off：全明文。

    选 Full (strict)，然后在服务器上装一张 15 年有效期的 Origin Certificate（Cloudflare 后台生成，只对 Cloudflare 回源有效）。这样回源也是加密的，且不用管续期。

  4. 路线 C：自己的服务器 + acme.sh + Nginx

    装 acme.sh，用 HTTP-01 验证（需要 80 端口可达）：

    curl https://get.acme.sh | sh -s email=you@example.com
~/.acme.sh/acme.sh --issue -d example.com -d www.example.com -w /var/www/html
~/.acme.sh/acme.sh --install-cert -d example.com \
  --key-file /etc/nginx/ssl/example.key \
  --fullchain-file /etc/nginx/ssl/example.crt \
  --reloadcmd "systemctl reload nginx"

    --reloadcmd 是关键：没有它，证书续了新文件，Nginx 还在用内存里的旧证书，到期照样报警。验证续期是否真的生效：

    sudo ~/.acme.sh/acme.sh --cron --force
curl -sI https://example.com | head -1

    acme.sh 装完会自己加一条 cron（或 systemd timer），每天检查一次，到期前 30 天续。

  5. 路线 C 的备选：Caddy，两行配置全自动

    不想碰 certbot/acme.sh 的续期逻辑，用 Caddy。它的默认行为就是「自动申请 + 自动续期 + 自动跳转 HTTPS」：

    example.com {
  root * /var/www/html
  file_server
}

    就这两行，HTTPS 就有了。Caddy 把 ACME 流程内置了，证书放在 /var/lib/caddy/.local/share/caddy 下，续期不需要额外配置。代价是它自带一个 Web 服务器（要换掉 Nginx），以及反代语法和 Nginx 不一样。新机器上直接选 Caddy，比装 Nginx 再配 certbot 省一半时间。

  6. 家用宽带没有 80 端口怎么办

    很多家用宽带封了 80 和 443 的入站，HTTP-01 验证会失败。三条出路：

    1. 用 DNS-01 验证：acme.sh 支持通过 DNS API 加一条 TXT 记录来验证，完全不需要 80 端口。用 Cloudflare 托管 DNS 时最省事，配一个 API Token 就行。 2. 套 Cloudflare 代理：边缘证书由 Cloudflare 提供，源站用 Origin Certificate，不需要自己申请。 3. 用内网穿透（Cloudflare Tunnel / frp），由隧道服务端处理 HTTPS。

    判断方法：从外网 curl 你的公网 IP 的 80 端口，连不上就是被封了。

  7. 验证：别只看浏览器的小锁

    浏览器对小锁很宽容，过期证书在强制刷新前也可能显示正常。用命令看真实情况：

    echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null \
  | openssl x509 -noout -subject -dates

    看两个日期，以及 subject 里的域名对不对。再看协议版本和跳转：

    curl -sI http://example.com | head -3
curl -sI https://example.com | head -3

    顺带把 HSTS 想清楚再加：Strict-Transport-Security 一旦下发，浏览器在 max-age 内拒绝用 http 访问这个域名。先设一个短值（比如 300 秒）试两天，确认全站资源都是 https 之后再改长。设错了没有撤销按钮，只能等它过期。

  8. 混合内容：小锁旁边的那个警告

    页面是 https，但里面加载了 http 的图片、脚本或接口，浏览器会把整页降级标记为「部分不安全」，并且直接拦掉脚本。排查方法：打开开发者工具 Console，搜 Mixed Content，或者在页面源码里找 http:// 开头的资源地址。

    常见的三处：老主题里的 Google Fonts、图床返回的 http 链接、硬编码的 http 接口地址。改成 // 开头（协议相对）或直接写 https。上线前用 curl 抓一次首页，grep 一遍 http:// 能省掉很多来回。

翻车了怎么办

  • 证书申请失败：先看 acme.sh 的日志（~/.acme.sh/acme.sh.log）。最常见的三种是 80 端口不通、DNS 还没生效、以及域名已经有一张短期证书导致触发速率限制（Let's Encrypt 对同一域名每周有签发次数上限，等一周或换 staging 环境调试）。
  • 配完打不开、报重定向次数过多：多半是 Cloudflare 的 SSL 模式选了 Flexible，而源站又强制跳 https，两边互相踢。改成 Full (strict)，或者先关掉源站的强制跳转。
  • 证书续了但浏览器还显示旧的：服务器进程没 reload。检查 reloadcmd 是否执行成功，手动 systemctl reload nginx 再看一次日期。
  • 彻底搞不定：先退回托管平台。把站点放 GitHub Pages 或 Cloudflare Pages，证书问题自动消失，等服务能稳定跑了再回来折腾自建服务器。

容易踩的坑

用 Flexible 模式，以为就安全了
浏览器到 Cloudflare 加密，Cloudflare 到源站明文。用户的密码在公网最后一段是裸的，而站长看到的却是「小锁正常」。这是最危险的一种「看起来配好了」。要么 Full (strict)，要么源站也上一张证书。
只配了 www，裸域打不开
证书是绑域名的，www.example.com 的证书对 example.com 无效。申请时两个都带上（-d example.com -d www.example.com），DNS 也两条都解析到同一处。这个错误在手机上特别容易漏——很多人只在自己的浏览器里试过 https://www。
证书自动续期了，但服务没重载
acme.sh 续期成功不等于生效。没有 --reloadcmd，Nginx 会一直用启动时加载的那张证书，直到你重启它——而那时候证书已经过期了。装证书时就把 reload 命令写进去，并且每季度手动 --cron --force 跑一次确认。
HSTS 一上来就设一年
HSTS 是浏览器端的强制策略，max-age 一年意味着一年内这个域名只能用 https 访问，用户无法点「继续访问」。如果站内还有 http 资源或某个子域没证书，用户会直接打不开，且你无法远程撤销。先短后长，是唯一安全的顺序。

常见问题

免费证书和付费证书差在哪？
加密强度没有差别（都是同样的算法和密钥长度）。差别在：付费证书通常带组织信息（OV/EV）、有赔付条款、有效期更长、支持更多域名和通配符的方式更灵活。个人站和大多数企业展示站，Let's Encrypt 完全够用；需要向客户出示「我们是已验证的公司」时才考虑付费。
三个月一续会不会哪天忘了就挂？
自动化之后不需要人记。acme.sh 装完自带定时任务，Caddy 内置续期。真正要防的是「自动任务悄悄失败了」——所以装一个到期提醒：用站内的日期计算工具算出入到期日的天数，或者用 Uptime Kuma 的证书到期监控，剩 14 天告警。
多个子域要各申请一张吗？
可以用一张通配符证书（*.example.com），但通配符只能用 DNS-01 验证，必须能改 DNS 的 TXT 记录。子域不多的话，一张证书带多个 -d 参数更简单，也便于单独吊销某一个。
套了 CDN 之后，源站还需要证书吗？
要。只要 CDN 到源站这一段走 https（Full 或 Full strict），源站就必须有证书。Cloudflare 的 Origin Certificate 是免费且 15 年有效的，专门用在这一段，不占 Let's Encrypt 的签发额度。
