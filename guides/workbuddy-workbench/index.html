🗂️ 用 WorkBuddy 搭一个带后台的工作台

一句话建数据表、生成看板页面、发布成链接；资料、页面与 Agent 在同一处接力，不写一行代码。

教程 / 用 WorkBuddy 搭一个带后台的工作台
难度 入门约 30 分钟风险 中最后核对 2026-11-07
这里说的工作台不是再装一个软件，而是资料库里的三样东西拼起来的：一张结构化数据表当后台，一个绑定它的页面当门面，一份能随时带进任务的资料当上下文。改内容不用改代码、改数据页面自己跟着变；下一轮任务里让 Agent 接着干，也不用把背景重讲一遍。先说风险：资料库是云端空间，不是你电脑上的文件夹，上传的文件会离开本机；页面默认只有自己能看，但一旦主动发布成公开链接，拿到链接的人不需要登录就能打开。所以先用一份不含个人信息的示例清单练手，敏感内容在第 7 步发布之前全部摘出去。本文按 WorkBuddy 官方功能文档写，功能名照官方叫法，具体按钮位置与文案以你当前版本的界面为准。

为什么值得折腾

  • 改内容不用改代码：数据存在表里，页面运行时读取。加一条记录、改一个状态，刷新页面就变；换封面图要改数据表里的图片字段，直接改 HTML 里的地址会在下次生成时被覆盖。
  • 资料不是一次性上传：从资料库把空间或文档「添加到任务」，Agent 基于同一份材料执行，成果再存回资料库，人和 Agent 在同一份文档里接力。
  • 发布与存入一步完成：产物点分享、开启「发布为网站」，系统给出在线链接，同时资料库里也留下这份内容。默认不对外公开，公开范围始终由自己掌握。

开工前要有的

  • 先划一条隐私线：资料库在云端，密码、密钥、身份证、未公开合同不要放进去。拿 3–5 条可以公开的示例任务练手，别拿真实客户清单试。
  • 一个能打开左侧边栏「资料库」的 WorkBuddy 账号，界面分「我的文档」和「团队空间」两块。个人练手用前者，多人协作才建团队空间。
  • 想清楚一张表记什么：拿「团队任务看板」最省事，任务名、负责人、状态、截止日期、优先级，5 个字段就够。
  • 如果打算发给别人看，先确认自己账号的发布范围（企业版由管理员配置是否允许全网发布），别等链接发出去才发现组织外的人打不开。
  • 不用装开发环境，也不用写代码；全程用自然语言描述需求，界面文案以你当前版本为准。

步骤

  1. 先把工作台缩成一张表

    别一上来建十个目录。工作台能不能用，取决于它每天要回答的那个问题：今天谁在做什么、卡在哪、什么时候到期。把问题写成 5 个字段，顺序按你平时怎么问来排。这一步只在纸上做，不碰界面。成功标志：你能一口气说出 5 个字段名，并且每个字段都能用一句话解释它存什么。

  2. 分清放哪儿：我的文档还是团队空间

    做错会怎样：一开始就建团队空间又随手分享，同事会看到还没清理的草稿，后面再挪要重新对一遍权限。个人练手先在「我的文档」里做，成品稳定了再挪进团队空间。真要多人协作，在资料库左栏「团队空间」区新建空间，空间内可以像文件夹一样嵌套整理文档树；权限分查看、编辑、管理、无权限四档，空间默认不对外公开。成功标志：你能说清这份资料现在归谁看。

  3. 一句话建数据表，这是工作台的后台

    在会话里用一句大白话把上一步的 5 个字段说出来，不用记命令、不用选产品。比如：

    在资料库里建一张任务表，字段：任务名（文本）、负责人（协作人）、状态（单选：未开始/进行中/已完成）、截止日期（日期）、优先级（单选：高/中/低）。

    WorkBuddy 会创建一张结构化数据表并定义好字段，然后告诉你在哪里查看。手上已有 Excel 或 CSV 也可以直接导入成在线数据表，多个 sheet 能分别建表。字段不是写死的，后面加一列「备注」、改字段名、改字段类型都行，页面下次加载就反映新结构。成功标志：资料库里出现一张能增删记录的表，先手动加 3 条示例任务。

  4. 让页面绑定这张表，别把内容写死

    接着说清楚页面要展示什么、要能怎么筛。比如：

    用上面那张表做一个任务看板页面，能按状态筛选、按截止日期排序，卡片上显示任务名、负责人和优先级。

    静态网页把内容写死在 HTML 里，加一条任务就得重新生成页面；带后台的页面在运行时读取数据表，改数据自动更新，这是两种做法的分界线。做错会怎样：直接去改 HTML 里的图片地址或任务文字，数据表里没变，下次重新生成就被覆盖回去。要换图，就在数据表对应的图片字段里换。成功标志：在第 3 步加的 3 条任务出现在页面上。

  5. 把散落的资料收进同一棵目录树

    往空间里放资料有四条路：直接在空间里新建文档或表格、上传本地文件（PDF、图片等）、把网页链接剪藏进来、或者在任务里指定「生成到某个空间」让 Agent 直接把产物落进去。会话里已经做好的产物还有一条捷径：在产物上点分享并开启「发布为网站」，发布的同时它就存进了资料库。这一步不追求一次收齐，先把这份看板用到的说明、参考链接和图收进来。成功标志：不用再翻聊天记录找那份清单。

  6. 把资料添加到任务，让 Agent 接着干

    在资料库里选中空间或文档，点「添加到任务」，然后说要做什么，例如按这张表写本周周报、把页面标题改成季度复盘。把空间或文档带入任务后，Agent 只读取当前用户有权访问的内容，人看不到的它也读不到，不必为 Agent 单独维护一套权限。MD 文档的 AI 修改不会直接覆盖原文，先以待确认的修订建议呈现，接受后才写进正文；HTML 支持划词直接改。把新产物存回资料库，下一轮就能继续接着用。成功标志：下一轮任务里你没有重新贴一遍背景。

  7. 要分享了才发布，发完立刻验权限

    做错会怎样：公开链接不需要登录，任何人拿到都能打开；发错之后撤回的动作是「取消发布」让链接失效，不是删掉那条聊天消息，而且转存过的副本收不回来。所以发布前先删掉敏感字段，再在产物上点分享、开启「发布为网站」拿到在线链接。团队多人协作走另一条路：在空间菜单里邀请和管理成员，通过复制链接邀请，成员权限按查看、编辑、管理、无权限四档给，获得链接的人还能单独设定访问方式（如需申请权限、可查看等）。发出去之后，用未登录的浏览器窗口打开一次，确认该看的看得到、不该看的看不到。成功标志：链接在另一个浏览器里按预期打开，且分享范围你能说清。

  8. 验收三件事，再决定要不要长期用

    第一，在数据表里加一条记录，刷新页面看它是不是自己冒出来，验证页面真的在读表而不是印了一份快照。第二，把一条记录的状态从「进行中」改成「已完成」，看筛选和排序有没有跟着变。第三，用全库搜索搜一个只在这份资料里出现过的词，能搜到说明资料已经进了索引，以后可以让 Agent 基于它继续工作。三件都过再往里搬真实资料；任意一件不过，按下面「翻车了怎么办」逐条退，别急着加内容。成功标志：三次改动都在页面上得到回应。

  9. 收尾：留一份能回退的备份

    把整张数据表导出成 CSV 存到本机，顺手记下页面链接和所在空间；以后要加字段（比如「备注」列）直接在表里加，页面下次加载就反映最新结构，不用重新生成页面。数据在你手里，就算明天删掉页面，凭这份 CSV 也能重建。成功标志：本机有一份 CSV，你能说出它对应哪张表、哪个页面。

翻车了怎么办

  • 页面空白或数据不显示：先确认数据表里至少有 1 条记录、页面绑的是这张表；在会话里说「确认这个页面绑定的是哪张表，重新绑一次」。还不行就取消发布、只重建页面，数据表别动——记录在表里，重建页面不会丢数据。
  • 同事打不开链接：到分享面板看成员权限是不是落到了「无权限」，或者链接的访问方式设成了需申请；重新生成邀请链接发给他。企业版若配置成「仅允许组织内协作」，组织外账号本来就进不来，别反复重发，先问管理员发布范围。
  • 误把敏感文件放进去、或者发了不该发的公开链接：立刻在资料库删掉该节点，并在分享面板「取消发布」让链接失效；再检查空间成员、发布范围和有没有第二份副本（剪藏的网页、导出的文件、已发布的页面）。
  • 记录改乱了：用第 9 步导出的 CSV 重新导入成一张新表，把页面绑到新表上，逐条核对后再删旧表；旧表先留着，别一边改一边删。

容易踩的坑

把云端当本机硬盘
资料库不在你电脑里，上传即离开本机。密码、密钥、未公开合同、身份证照片不要放进去；先用示例数据把流程走通，再决定哪些真实资料能上云。
在 HTML 里写死内容
看板的意义是数据驱动。把任务名直接写进页面，加一条任务就得重新生成，等于绕回静态网页；内容一律先进数据表。
发布完不验权限
默认不公开不等于永远不公开。公开链接不需要登录，发出去之前用未登录窗口开一次，确认范围再发。
先建了一堆空目录
正确顺序是：先有表、再有绑定它的页面、最后才整理目录树。反过来做，最后得到的是一棵没人用的空树。

常见问题

不会写代码能做吗？
能。全程用自然语言描述需求，建表、生成页面、发布链接都由 WorkBuddy 完成；字段类型和界面文案以你当前版本为准。
数据表和本地 Excel 有什么区别？
数据表在云端，能被页面读取、多人同时维护、字段可增删改；本地 Excel 可以直接导入成数据表，整张表也能导出成 CSV 带走。
团队空间和个人文档怎么选？
只自己用放「我的文档」；要多人协作、按角色给权限就建团队空间，内容可以从我的文档挪过去。空间默认不对外公开。
Agent 会不会看到我没权限的资料？
不会。把空间或文档带入任务后，Agent 只读取当前用户有权访问的内容；人看不到的内容，Agent 也读不到。
