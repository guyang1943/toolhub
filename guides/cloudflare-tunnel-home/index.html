🏠 把家里的服务安全地放到公网（Cloudflare Tunnel）

不开路由器端口、不要公网 IP，只放一个服务出去，并且先加一道登录。

教程 / 把家里的服务安全地放到公网（Cloudflare Tunnel）
难度 中等约 50 分钟风险 高最后核对 2026-11-05
动手之前先看这段。这一步做完，互联网上任何人都能敲到你的域名——「别人不知道地址」不算保护，证书透明度和各种资产测绘平台会把新域名在几小时内公开。真正要守的是三件事：只发布一条路由（不是一个网段、不是整台机器）、先建 Access 登录策略再开通入口、令牌当密码保管。任意一条漏掉，你就是在公网上跑一个没上锁的服务，而且不会有人来提醒你。
家里的 NAS、Home Assistant、自建的文件服务，想在外面也能打开，最直接的办法是在路由器上做端口映射——那等于在自家网络上凿一个洞，谁扫到谁就能敲。Cloudflare Tunnel 换了个方向：从家里那台机器主动向外连一条长连接，访客从 Cloudflare 进来，再由这条连接转给本机的服务。路由器上不用开任何端口，也不需要公网 IP。它只解决「怎么连出去」，不解决「谁能进来」，后者要靠 Cloudflare Access 再加一道登录——所以这篇的顺序是刻意反的：先把登录建好，再开入口。另外先把话说在前面：路由器后台、NAS 管理页、SSH 这三类别挂上去，它们常年是被爆破的目标，Access 挡得住敲门的人，挡不住页面本身的漏洞。

为什么值得折腾

  • 不用公网 IP、不用在路由器上开端口：运营商封 80/443、家里在 NAT 后面都不影响，Tunnel 是主动向外连的。
  • 比端口映射小一档的暴露面：端口映射把「哪个端口」摊给整个互联网，Tunnel 只放出「哪一条路由」，外面还压着一层登录。
  • HTTPS 顺带解决：域名已经在 Cloudflare 上，证书自动签发和续期，不用自己折腾。
  • 随时能关：删一条路由、删一个 Tunnel，入口立刻消失，不用去动路由器。

开工前要有的

  • 一个域名，并且 DNS 已经托管在 Cloudflare（没做的话先照「Cloudflare 免费套餐」那篇把 NS 改过去，等到域名状态是 Active）。
  • 一台常开的机器：家里的 NAS、小主机、树莓派都行，能装软件、能访问外网。它关机，服务就断。
  • 那个服务本身能在本机浏览器里打开，并且你知道它跑在哪个端口。
  • 一个邮箱：注册 Cloudflare 用，也用来收 Access 的登录验证码。
  • 先接受一件事：做完之后你的服务就在公网上了。保护它的是 Access 那道登录，不是「没人知道我的域名」。

步骤

  1. 先决定只放哪一个服务，把地址写死

    在本子上写清楚：要暴露的是哪个服务、跑在哪个端口、本机怎么访问它，例如 http://localhost:8080。规则只有一条：一个 Tunnel 接一个服务、挂一条路由。以后要放第二个，再加一条路由；不要图省事把整台机器或整个网段接出去。做错会怎样：把 192.168.1.0/24 这样的整个网段接进 Tunnel，等于摄像头、路由器后台、打印机全都有了公网入口，而 Access 只保护你写得出来的那个域名，剩下的一概裸着。

  2. 确认这个服务只听在本机

    Windows 打开命令行敲 netstat -ano | findstr :8080，Linux 敲 ss -lntp | grep 8080，看「本地地址」那一列。127.0.0.1:8080 表示只有本机能连，最好；0.0.0.0:8080 表示同一局域网里任何设备都能连——那说明这道门在屋里是敞开的。看到 0.0.0.0 就先去服务自己的设置里把监听地址改回 127.0.0.1，或者确认它自带独立口令。做错会怎样：局域网里中招的任何一台设备（智能音箱、监控、别人连过的手机）都能直接连上这个服务，而这一层根本没有 Access 挡着。

  3. 把域名接进 Cloudflare

    Tunnel 的路由必须挂在一个由 Cloudflare 托管 DNS 的域名上。如果域名还没接进来，先照「Cloudflare 免费套餐」那篇把 NS 改过去，等到面板上这个域名的状态是 Active。做错会怎样：NS 还没生效就去加路由，面板会找不到域名，或者加了之后访问落到 Cloudflare 的错误页——你会以为是 Tunnel 的问题，其实是域名压根没托进来。

  4. 先在 Zero Trust 里建好 Access 应用，再开入口

    打开 one.dash.cloudflare.com（Zero Trust 面板），进 Access controls → Applications，点 Create new application（旧版写作 Add an application），类型选 Self-hosted and private（旧版是 Self-hosted），点 Add public hostname，填你打算用的子域名，例如 home.yourname.com。下面的 Access policies 新建一条 Allow 策略：Include 选 Emails，填你自己的邮箱。身份验证方式（Identity providers）用 One-time PIN，也就是往邮箱发验证码。填完点 Create。顺序不是讲究：官方文档明确建议先建 Access 应用、再建隧道路由，否则从路由发布到策略生效这段时间，任何拿到这个域名的人都能直接打开你的服务。做错会怎样：入口先开着、策略后补，中间那几分钟到几小时就是裸奔，而且事后你未必能从日志里看出有人进来过。

  5. 装 cloudflared

    Windows 从 Cloudflare 的 GitHub release 页下载 cloudflared-windows-amd64.msi，双击装完；Mac 用 brew install cloudflared；Linux 用官方的 .deb 或 .rpm 包。装完在终端敲 cloudflared --version，能打出年份版本号就成了。Windows 版不会自动更新，以后要手动升。做错会怎样：从搜索广告或第三方下载站拿 exe——这个程序会以你的身份连出内网，装错等于把钥匙交出去。只从 Cloudflare 官方文档给的链接或 GitHub release 下载。

  6. 建 Tunnel，拿到那条带令牌的命令

    回面板，进 Networking → Tunnels（有的版本写作 Networks → Connectors → Cloudflare Tunnels），点新建（Create a tunnel / Create tunnel），起个名字比如 home-gw，确认。面板会让你选操作系统，然后给出一条带令牌的命令，令牌是一长串 eyJ 开头的字符。把这条命令复制到那台机器上执行：Linux 上是 sudo cloudflared service install 加令牌，Windows 上是 cloudflared.exe service install 加令牌——按钮文案和命令原文以你当前面板显示的为准。做错会怎样：这条命令里的令牌就是那台机器的通行证，任何人拿到它都能把流量接进你家网络。别贴进群里、别提交进仓库、别写进公开笔记。

  7. 等面板显示 Healthy

    命令执行完回到面板，Tunnel 状态应该变成 Healthy（健康）。显示 Inactive 或 Down 就是没连上：先确认那台机器能出外网的 7844 端口（有些公司网、校园网只放 443），再看命令是不是真的跑完了。做错会怎样：没连上就急着加路由，访问会得到 502 或 Cloudflare 的错误页，然后你去查服务、查端口，白折腾一圈——真正的问题在连接那一层。

  8. 加一条路由，和服务对得上

    点开这个 Tunnel，进 Routes 标签页（有的版本叫 Published application routes），点 Add route，选 Published application。子域名和域名填得跟第 4 步 Access 应用里完全一样——差一个字母就是另一个域名，Access 不认；Service URL 填 http://localhost:8080；点 Add route（旧版这一步叫 Complete setup）。只加这一条：不要填 yourname.com 这种上层域名，也不要用通配符。做错会怎样：hostname 和 Access 应用里的不一致，结果是「页面能打开但不用登录」——你亲手绕过了自己刚建的那道门；填上层域名或通配符，则是把整个域都指到这台机器上。

  9. 从外网验一次，要看的是登录页

    把手机关掉 Wi-Fi、切到蜂窝数据，打开 https://home.yourname.com。预期是：先出现 Cloudflare Access 的登录页，填邮箱、收验证码，登录之后才看到服务本身。如果直接看到服务首页，说明 Access 没生效——立刻回第 4 步检查应用绑的域名和策略；一时查不出原因，先把第 8 步那条路由删掉，按下面「翻车了怎么办」里的第一步做。做错会怎样：这是全篇唯一的验收标准。跳过它，你交付的只是一个「大概加了鉴权」的东西。

  10. 收尾：令牌当密码管，不用的路由删掉

    Tunnel 的令牌可以轮换：详情页的 Overview 标签里点 Refresh token，旧令牌随即失效，然后在机器上按新命令重装一次服务。以后不再用的路由、Access 应用、Tunnel 都要删掉，别留着。做错会怎样：闲置的路由是一扇没人看着的门——服务还在跑、入口还在，只是你先忘掉了。

翻车了怎么办

  • 立刻关掉公网入口：Networking → Tunnels → 选中这个 Tunnel → Routes 标签页，把那条 Published application 路由删掉。删完域名立刻不可达，这一步不需要动 DNS、也不用停服务。
  • 连 Tunnel 一起停：同一个 Tunnel 的详情页点 Delete（删除 Tunnel），或者在机器上执行 sudo cloudflared service uninstall（Windows 去掉 sudo，用 cloudflared.exe）。两条都能让连接断掉；删 Tunnel 之后令牌作废，想再用要重建一个。
  • 撤 DNS 记录：那条子域名的记录如果还在，去 DNS 页面把它删掉，否则访问会落到 Cloudflare 的报错页，而不是干净地不存在。Cloudflare 全量托管时，删路由一般会一起清掉这条记录，以你面板里看到的状态为准。
  • 关 Access 策略：Access controls → Applications，把这条应用删掉，或把策略里那条 Allow 改成 Block。顺序是先删入口、再删策略——反过来的话，中间会有一小段完全公开的窗口。
  • 只停服务本身：Windows 在服务管理器里停 cloudflared，Linux 执行 sudo systemctl stop cloudflared。服务一停，Tunnel 还在但后端没了，访问是 502。
  • 怀疑令牌泄露：面板上 Refresh token 轮换，再在机器上 cloudflared service uninstall 后用新命令重装；同时检查那台机器上有没有别的程序读过这条命令（shell 历史、截图、聊天记录）。

容易踩的坑

先开路由，后补 Access
官方文档把「先建 Access 应用」写成建议，不是可选项：从路由发布到策略生效，入口是公开的。这篇把建登录排在开入口之前，就是为这个顺序。
把路由器后台、NAS 管理页挂上去
这类页面的登录框常年是被爆破的目标。Access 只能挡在前面，挡不住页面本身的漏洞。要看管理页，用 Tailscale 这类私有网络，别给它公网入口。
Service URL 写成 0.0.0.0 或局域网 IP
Tunnel 是从那台机器上发起的，写 http://localhost:端口 最稳。写局域网 IP，那台机器换网络、换 IP 之后就断了。
用通配符或上层域名
一条通配符路由就把所有子域名指过去，而 Access 得一条条配。要几个就配几个，别图省事。
令牌进了 git 或聊天记录
安装命令里就带着令牌，复制时很容易连提交一起带上。放密码管理器，别进仓库、别发群。
手动跑了一次就以为完事
如果只是在前台敲了 cloudflared tunnel run，窗口一关、机器一重启，连接就没了。要长期在线就用面板给的 service install 命令注册成服务。

常见问题

这样算不算「开了端口」？
不算。Tunnel 是从你家那台机器主动向 Cloudflare 建的长连接，路由器上不用做端口映射，也不需要公网 IP。对外看到的只有 Cloudflare 的 443。
免费版够用吗？
个人用途一般够。免费版 Access 有人数上限，具体额度以 Cloudflare 官网的套餐页为准，团队规模上去要付费。
一定要有自己的域名吗？
要。Tunnel 的路由挂在你 Cloudflare 账号下的域名上，没有域名就没有可以发布的 hostname。先去注册一个，再把 NS 改到 Cloudflare。
手机上怎么过 Access 那一步？
One-time PIN 是把验证码发到邮箱，手机上收邮件一样能登。也可以接 Google、GitHub 这类身份提供商，在 Zero Trust 的 Settings → Authentication 里配。
家里断网或断电会怎样？
服务不可达，面板上这个 Tunnel 显示掉线，恢复供电供网后会自动重连。不会留下「半开」的入口——没有连接就没有转发。
