🤖 用 GitHub Actions 实现推代码即上线

写一个 YAML 文件，之后每次 push 自动构建部署，不用手动传文件。

教程 / 用 GitHub Actions 实现推代码即上线
难度 中等约 45 分钟风险 低最后核对 2026-11-05
GitHub Actions 是 GitHub 自带的一个“机器人”：你写好一份步骤清单（一个 YAML 文件），它就会按清单自动干活。本篇以 GitHub Pages 网站为例，做完之后，你改一行文字、push 一下，网站自己就更新了，不用再手动传文件、等构建。整个过程不花钱、不碰命令行，全在网页上完成。

为什么值得折腾

  • 改完 push 就行：不用再手动传文件、手动点部署，少一步就少一次出错。
  • 出错有地方查：每次运行都有日志，红了点进去就能看到是哪一步失败，不用靠猜。
  • 个人小站零成本：公开仓库的 Actions 免费不限量，私有仓库每月也有免费额度。

开工前要有的

  • 一个 GitHub 账号（免费注册即可）。
  • 一个已经能用 GitHub Pages 打开的仓库，里面至少有一个 index.html（跟着本系列第 1 篇《零基础发布第一个网站》做好的仓库正好）。
  • 知道你的仓库是公开（Public）还是私有（Private）——关系到免费额度，见第 6 步。

步骤

  1. 先把 Pages 的发布源切到 GitHub Actions

    打开你的仓库页面，点顶部菜单里的 Settings（设置）。在左侧边栏“Code, planning, and automation”一栏里点 Pages。（若界面分组名略有不同，以 Pages 为准。）找到“Build and deployment”（构建与部署），把 Source（来源）从“Deploy from a branch”改成“GitHub Actions”。成功标志：页面下方出现“GitHub will suggest several workflow templates”（会推荐几个工作流模板）的提示。这一步只是改了个开关，网站本身不受影响。

  2. 新建工作流文件

    回到仓库主页，点右上角绿色的“Add file”（添加文件），选“Create new file”（新建文件）。在文件名那一格里，一字不差地输入 .github/workflows/deploy.yml（注意前面有个点，github 前面没有斜杠）。成功标志：输入完文件名后，页面上方出现 .github / workflows / deploy.yml 的面包屑路径，说明文件位置对了。

  3. 粘贴工作流内容

    把下面这份内容完整粘贴进文件编辑框（工作流主体来自 GitHub 官方部署教程，concurrency 并发控制参考官方静态站点模板（static.yml），workflow_dispatch 是额外加的手动触发，不 push 也能手动跑一次；照抄即可）。内容分三段：on 规定“什么时候跑”（每次 push 到 main 分支）；permissions 规定“允许它做什么”（pages: write 是发布网站的权限，id-token: write 是身份验证，两个都不能少，少了会报权限错误）；jobs 只有一段 deploy（一个任务），里面分 4 步：Checkout、Setup Pages、Upload artifact、Deploy to GitHub Pages。动作后面的版本号（checkout@v6、configure-pages@v5、upload-pages-artifact@v4、deploy-pages@v4）会随官方更新而变，照抄本文时以官方文档为准。

    name: Deploy to GitHub Pages
on:
  push:
    branches: ["main"]
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: "pages"
  cancel-in-progress: false
jobs:
  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v6
      - name: Setup Pages
        uses: actions/configure-pages@v5
      - name: Upload artifact
        uses: actions/upload-pages-artifact@v4
        with:
          path: '.'
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
  4. 提交文件到 main 分支

    编辑框右上角点绿色的“Commit changes”（提交更改）。在弹出的框里直接点“Commit changes”，保持默认的“Commit directly to the main branch”（直接提交到 main 分支）不动。成功标志：页面跳回仓库主页，文件列表里多了 .github 文件夹。

  5. 去 Actions 页看第一次运行

    点仓库顶部菜单里的 Actions（动作）。你会看到一条名叫“Deploy to GitHub Pages”的运行记录，旁边有个转圈的黄色圆点，表示正在跑。等一两分钟，圆点变成绿色对勾，就是部署成功了。成功标志：点进这条记录，deploy 那一步显示绿色对勾，并且能看到“Deploy to GitHub Pages”这一步输出的网址。

  6. 打开线上地址，确认更新

    打开 https://你的用户名.github.io/仓库名/（把“你的用户名”和“仓库名”换成你自己的）。成功标志：页面正常打开，内容和你仓库里的一致。第一次部署后，GitHub 有时要等几分钟才生效，刚部署完打不开先等 5 分钟再刷新。

  7. 改一行字、再 push 一次，看它自己更新

    在仓库里打开 index.html，点右上角的铅笔图标（编辑），随便改一行看得见的文字，比如把标题改成“你好，世界 v2”，再点“Commit changes”提交。然后去 Actions 页，会自动出现一条新的运行记录。等它变绿，刷新你的网站地址，改动就上去了。成功标志：不用你再手动点任何部署按钮，网站自己更新了——这就是“推代码即上线”。

  8. 失败了怎么办：去看日志

    如果 Actions 页的记录旁边是红色叉号，点进这条记录，再点变红的那一步（比如 deploy），往下翻看日志的最后 20 行，错误原因一般就写在那里。最常见的错是 permissions 里漏了 pages: write 或 id-token: write，补上再提交一次就行。另一个常见错是文件名敲错了（比如少了开头的点），检查第 2 步的文件名。修好之后再 push 一次，Actions 会重新跑。

翻车了怎么办

  • 部署失败了，旧网站还在：一次失败的运行不会把旧站弄坏，线上还是上一次成功部署的样子，修好工作流再跑一次就行。
  • 想回到手动发布：去 Settings → Pages，把 Source 改回“Deploy from a branch”，再删掉 .github/workflows/deploy.yml 这个文件，自动部署就停用了。
  • 只想临时停用：去 Actions 页点左边的工作流名字，再点右上角三个点，选“Disable workflow”（停用工作流），想用时再启用。

容易踩的坑

permissions 里漏了 pages: write 或 id-token: write
这是新手最常见的报错。没有这两个权限，deploy 那一步会报权限错误。照抄第 3 步的 permissions 三行，一个都不能少。
动作版本号会变
checkout@v6、deploy-pages@v4 这种 @v 后面的数字是版本号，官方会更新。照抄本文时如果报错，先去官方部署教程核对最新版本号，不要自己猜一个数字填上去。
私有仓库有免费分钟数上限
公开仓库的 Actions 用标准运行器是免费不限量的。私有仓库在免费账号下每月有 2000 分钟免费额度（Linux 等值分钟；Windows/macOS 消耗更快），用完当月就停了——但新账号默认有 0 元消费上限，不会偷偷扣费。个人小站一次部署只要 1 分钟左右，2000 分钟完全够用。
在别的分支上 push 不会部署
第 3 步的工作流只监听 main 分支的 push。你在别的分支上改东西，Actions 不会跑，也不会上线。确认自己提交到了 main 分支。

常见问题

每次 push 都要等多久才能看到更新？
一般 1 到 3 分钟。去 Actions 页看运行记录变绿就是部署完了，刷新网站地址就能看到。刚部署完有时要再等几分钟才生效。
公开仓库的 Actions 真的无限免费吗？
用标准运行器（比如 ubuntu-latest）是的，免费且不限量。但“超大运行器”（更大配置的机器）是要收费的，个人小站用默认的 ubuntu-latest 就行，不要去改 runs-on。
能不能定时自动跑，而不是每次 push 才跑？
能。把第 3 步里的 on 那一段改成定时触发（on.schedule），比如每天凌晨跑一次。写法以 GitHub 官方文档为准，本篇先掌握 push 触发就够了。
和直接从分支发布（Deploy from a branch）有什么区别？
分支发布是把仓库里的文件原样发出去，适合纯静态页面。Actions 发布是先“构建”再发布，适合需要构建步骤的网站（比如要先跑个生成命令）。本系列的静态小站两种都能用，Actions 的好处是流程可控、出错有日志。
GitHub Pages 免费站有什么容量限制？
已发布的网站不能超过 1GB，具体限制以 GitHub 官方文档为准。个人小站一般只有几 MB，离上限很远，不用担心。
