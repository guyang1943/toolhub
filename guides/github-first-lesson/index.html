🐙 GitHub 新手第一课：注册、建仓库、传文件、提 PR

全程网页操作，不碰命令行；做完能看懂别人的开源项目、敢提第一个 PR。

教程 / GitHub 新手第一课：注册、建仓库、传文件、提 PR
难度 入门约 40 分钟风险 低最后核对 2026-11-05
GitHub 是全世界程序员放代码、一起改代码的地方，也是普通人参与开源的入口。你不需要会写代码、不用装软件、不用碰命令行——这篇只用浏览器，带你注册账号、建仓库、传文件，最后给别人的项目提一个 PR（Pull Request，合并请求）。做完你就能看懂开源项目的页面，敢动手改一个错字、提一个建议。

为什么值得折腾

  • 看懂开源项目：README 是说明书，Issues 是问题单，PR 是别人的改动提案。
  • 能动手参与：改错字、补翻译、报问题，都是对开源的真实贡献。
  • 自己的文件也有版本：每次提交都有记录，改错了能找回。

开工前要有的

  • 一个常用邮箱，用来收验证码。
  • 一台能上网的电脑或手机，浏览器即可。
  • 一个想练手的公开项目：比如本站的开源仓库 github.com/guyang1943/toolhub（ToolHub 本身就是开源的）。

步骤

  1. 注册 GitHub 账号

    打开 github.com/signup。填邮箱、密码、用户名：邮箱用常看的（验证码发到这里）；密码至少 8 位，包含数字和小写字母；用户名用小写字母、数字和连字符，它会出现在你的个人主页地址 github.com/你的用户名 里。点继续后，GitHub 会往邮箱发验证码（发件人 noreply@github.com），把验证码填回去点 Verify。找不到邮件先看垃圾邮件箱，或点重发。接下来选 Free（免费）计划，个性化问卷点 Skip personalization 跳过。看到 Dashboard（仪表盘）就是注册成功了。建议顺手开两步验证（2FA）：头像 → Settings →（左侧 Access 分组下）Password and authentication → 找到 Two-factor authentication 分区，点 Enable two-factor authentication，账号被盗的概率会小很多。术语解释：两步验证就是登录时除了密码，还要手机上的一次性验证码。

  2. 认识一个仓库页面

    打开一个公开仓库看看，比如 github.com/guyang1943/toolhub。页面上方是文件列表，点文件名就能看内容；README.md 是项目的说明书，打开仓库第一眼看到的就是它，一般会写项目是干什么的、怎么用。再看右上角三个按钮：Watch（关注，有更新会通知你）、Star（收藏，相当于点赞）、Fork（复刻，复制一份到你名下自己改）。页面上方还能看到 Issues（问题单）和 Pull requests（合并请求）两个标签页——那是大家讨论和提交改动的地方。

  3. 建自己的第一个仓库

    点右上角 + 号 → New repository（新建仓库）。Repository name（仓库名）填英文名，比如 my-notes（小写字母、数字、连字符）。Visibility（可见性）选 Public（公开）：免费账号功能最全，公开仓库人人可见；Private（私有）只有你和你邀请的人能看。勾上 Add a README file，点 Create repository。成功后进入仓库页，看到 README.md 文件。提醒：公开仓库不要放密码、密钥、身份证号、手机号——这些东西一公开，机器人几分钟就能扫到。

  4. 用网页上传文件

    点仓库上方的 Code 标签页，再点绿色 Add file（添加文件）→ Upload files（上传文件）。把电脑里的文件拖进虚线框（比如一张图片、一个文档）。页面下方 Commit changes（提交更改）区域有一行说明文字，默认是 Add files via upload，改成一句人话，比如“上传第一张图片”，再点绿色 Commit changes。文件出现在列表里就是传成功了。术语解释：Commit（提交）就是把这次改动存成一个版本，附带一句说明；之后在 History（历史）里能看到每一次提交，改错了能找回。

  5. 用网页改文件

    点开仓库里的任意文件（比如 README.md），再点右上角的铅笔图标（Edit，编辑）。在编辑框里改几个字，拉到下方，Commit message（提交说明）写一句改了什么，比如“修正错别字”，点 Commit changes。回到文件页就能看到新内容。想看改了什么：点文件上方的 History，能看到每次提交的记录和差异。

  6. Fork（复刻）别人的仓库

    想改别人的项目，先 Fork。打开目标仓库（比如 github.com/guyang1943/toolhub），点右上角 Fork 按钮，选你的账号（如果有多个组织会让你选放哪里）。几秒后页面跳转到 github.com/你的用户名/toolhub——这就是你名下的一份完整复制件，随便改都不会影响原仓库。术语解释：Fork（复刻/分叉）就是把别人的仓库完整复制一份到自己名下，是开源协作的起点；原仓库和你的复刻之间保持着关联，之后才能提 PR。

  7. 提第一个 PR

    在你 fork 的仓库里改一个文件：比如打开 README.md，点铅笔图标改一个错字，Commit message 写“修正 README 错别字”，点 Commit changes。回到你 fork 的仓库首页，页面上方会出现一条绿色提示和 Compare & pull request（比较并创建合并请求）按钮，点它。确认页面：左边 base repository（目标仓库）是原作者的仓库、base 分支是 main；右边 head repository（来源仓库）是你的 fork、compare 是你改动的分支。没错的话，写标题（比如“修正 README 中的错别字”）和一句话说明（改了哪一行、为什么改），点 Create pull request（创建合并请求）。成功后页面显示你的 PR 编号，比如 #10。术语解释：PR（Pull Request）就是“请你把我的改动拉过去”——你把改动提案发给原作者，对方审核后决定合不合进来。

  8. 看懂 PR 的状态和回复

    PR 建好后有三种状态：Open（打开，等作者回复）、Merged（已合并，你的改动进原仓库了）、Closed（已关闭，没采纳或你自己关了）。作者可能会在页面下方评论、让你再改一改——直接在评论框回复就行；你再去 fork 里改文件、提交，PR 会自动更新，不用重新提。第一次提 PR 不用紧张：改错字、补翻译、修文档都是最受欢迎的新手贡献。如果 PR 被合并不了（比如原仓库同时改了同一行），页面会提示冲突（conflict），先放一放，等熟练了再处理。

翻车了怎么办

  • 收不到验证码：先看垃圾邮件和推广标签；发件人是 noreply@github.com；等几分钟点重发；还不行换个邮箱注册。
  • 用户名被占了：GitHub 用户名全站唯一，换一个，加数字或连字符，比如把 xiaoming 换成 xiaoming-2026。
  • Compare & pull request 按钮没出现：点仓库上方的 Pull requests 标签页 → New pull request（新建合并请求），点 compare across forks（跨 fork 比较）→ base 选原仓库的 main，head fork 选你的 fork、compare 选你的分支。
  • PR 显示冲突（conflict）：说明原仓库同时改了同一处。先别硬来，可以在 PR 页面下方直接编辑解决，或关掉这个 PR 换个小改动再提。

容易踩的坑

公开仓库里放了密码或密钥
Public 仓库人人可见，还有机器人专门扫新公开的密钥。密码、API 密钥、私钥、身份证号一律别放仓库里。已经误传了就立刻换掉（改密码、吊销密钥），光删文件没用——历史记录里还有。
PR 标题写“改了点东西”
作者每天可能收到很多 PR，标题要写清改了什么、为什么改，比如“修正 README 中的错别字”。标题不清的 PR 很容易被直接忽略。
直接在原仓库点编辑以为能改
没有写权限的仓库，你点编辑时 GitHub 会自动帮你 fork 一份——这不是 bug，是正常流程。改动发生在你的 fork 里，最后要走 PR 才能回到原仓库。
Fork 完就不管，原仓库更新了
Fork 是复制那一刻的快照，原仓库之后的新改动不会自动同步到你的 fork。长期参与一个项目要定期点 Sync fork（同步复刻）更新。网页上就有这个按钮，在 fork 首页点 Sync fork → Update branch。

常见问题

GitHub 免费吗？
个人账号免费。公开仓库的功能基本全开；私有仓库也能免费建，高级功能（比如某些代码审查、Actions 用量）要付费，以官网为准。学生可以用 GitHub Education 申请更多免费额度。
一定要学 git 命令行吗？
不用。这篇全程网页操作。等你改得多了、想一次改很多文件，再学 git 也不迟——那时你已经理解仓库、提交、分支这些概念了，学命令只是换个工具。
Star 和 Fork 有什么区别？
Star 是收藏（点赞），只表示你喜欢这个项目；Fork 是复制一份到你名下，可以自己改、再提 PR。看项目热度看 Star 数，想参与就 Fork。
提 PR 会不会被骂？
正规开源项目欢迎新手 PR，尤其是文档类改动。先从错别字、翻译、补充说明这类小改动开始，标题和说明写清楚，被接受的概率很高。被拒绝也很正常，看看评论里的原因，下次再提。
README 到底是干什么的？
README.md 是每个仓库的“说明书”，打开仓库第一眼就是它。好的 README 会写：项目是干什么的、怎么安装、怎么用、怎么参与。自己建仓库也记得写几句，否则别人不知道你的项目是干嘛的。
