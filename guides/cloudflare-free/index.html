☁️ Cloudflare 免费套餐：给网站加速和挡爬虫

免费 CDN、缓存、基础防护三件套，不用改代码。

教程 / Cloudflare 免费套餐：给网站加速和挡爬虫
难度 中等约 40 分钟风险 中最后核对 2026-11-05
Cloudflare 是一层挡在访客和你网站之间的免费服务：它替你管 DNS、把页面缓存到全球节点加速打开、免费发 SSL 证书、还能挡住流量攻击。免费版每月 0 美元，不用绑信用卡，个人网站完全够用。这篇把你的域名接进 Cloudflare，改几处设置就完成。

为什么值得折腾

  • 全球 CDN 加速：访客从离他最近的节点拿页面，打开更快。
  • 免费挡攻击：不限量的 DDoS 防护和基础防火墙，小站不用再怕被刷。
  • 免费 SSL：证书自动发、自动续，不用自己折腾。
  • 不用改代码：接在域名层面，网站本身一行业不用动。

开工前要有的

  • 操作前先在原服务商后台把现有 DNS 记录截图备份好：改 NS 之后，域名的解析权就全交给 Cloudflare 了，漏记一条，网站或邮箱可能中断一段时间。
  • 一个已有域名，并且你能进它的注册商后台改设置（第 2 篇注册的 DNSHE 域名就行）。
  • 一个已经上线的网站（GitHub Pages 就可以）。
  • 一个邮箱，用来注册 Cloudflare 账号。

步骤

  1. 注册 Cloudflare，添加域名

    打开 cloudflare.com，点右上角 Sign up（注册），用邮箱建账号（不用绑信用卡）。登录后点 Domains → Onboard a domain（旧版面板叫 Add site），输入你的域名（比如 yourname.bot.cd，不用带 www），点 Continue。选计划时点 Free（免费，$0/月）→ Continue。注意别手滑点成 Pro（$20/月按年付）。

  2. 核对 Cloudflare 扫出来的 DNS 记录

    Cloudflare 会自动扫描你现在的 DNS 记录并列出来。逐条核对：原来在 DNSHE 配的 CNAME（www → 你的用户名.github.io）和 4 条 A 记录都在吗？邮箱的 MX 记录在吗？缺了就点 Add record（添加记录）手动补一条，错了就点 Edit 改。核对完点 Continue。这一步是整篇最重要的一步——漏记一条，网站或邮箱就可能断。

  3. 去注册商改 NS，把域名交接给 Cloudflare

    Cloudflare 会给你两个 nameserver（域名服务器），长得像 ada.ns.cloudflare.com 和 bob.ns.cloudflare.com（每人分到的不一样，以页面显示为准）。去你的域名注册商后台（DNSHE 里叫“修改 NS”或“域名服务器”），把原来的 NS 换成这两个，保存。回来点 Done, check nameservers（完成，检查 NS）。生效一般几分钟到几小时，期间网站不会断——旧的 DNS 还在工作，新旧交接是平滑的。术语解释：NS（nameserver）就是“域名归谁管”的指向标，改了它，域名的所有解析记录就都由 Cloudflare 说了算。

  4. 确认小黄云亮了

    NS 生效后，在 Cloudflare 的 DNS 页面，每条记录后面都有一个云朵图标。橙色小黄云（Proxied，代理）表示流量走 Cloudflare，又快又有防护；灰色云（DNS only，仅 DNS）表示直接指向原地址，不经过 Cloudflare。网站的 CNAME 和 A 记录保持橙色就行。如果看到记录是灰色，点一下云朵切成橙色。

  5. SSL 模式选 Full (strict)

    点左侧 SSL/TLS → Overview（概览），把 SSL 模式选成 Full (strict)（完全严格）。Cloudflare 有四种模式：Off（不加密）、Flexible（灵活）、Full（完全）、Full (strict)（完全严格）。对 GitHub Pages 这样本身带 HTTPS 的站，选 Full (strict)：浏览器到 Cloudflare、Cloudflare 到 GitHub 两段都加密，还会校验对方证书，是最稳的。千万别选 Flexible：Flexible 下 Cloudflare 用 HTTP 回源，GitHub Pages 把 HTTP 请求 301 到 HTTPS，Cloudflare 又用 HTTP 再请求一次，就这样循环下去，浏览器报“重定向次数过多”——这是最常见的翻车。切 Full (strict) 前先确认 GitHub Pages 的证书已签发完成（Pages 设置里自定义域名旁有绿勾），否则会报 526 错误。

  6. 缓存：改完看不到更新怎么办

    Cloudflare 默认会缓存你的图片、CSS、JS 等静态文件，访客打开更快。但这也意味着你改了网站内容，自己刷新可能还是旧页面。排错办法有两个：第一，Caching（缓存）→ Configuration（配置）→ Purge Cache（清除缓存）→ Purge Everything（全部清除），清完再刷新；第二，临时排错用 Development Mode（开发模式）：同一个页面里打开它，3 小时内所有缓存失效、改动即时可见，3 小时后自动关闭，不用记着关。注意开发模式只绕过缓存、不删除已缓存的文件，想彻底更新还是要 Purge。

  7. 顺手开两道免费防护

    最后顺手开两道免费防护。Security（安全）→ WAF（防火墙）：免费的 Managed Ruleset（托管规则集）默认就是开的，能挡常见攻击手法，不用动。再往下找到 Bot Fight Mode（机器人对抗模式），打开：它会自动挑战疑似爬虫的访问。免费版还包含 5 条自定义 WAF 规则和 1 条限速规则（比如“同一 IP 10 秒内超过 20 次请求就拦 10 秒”），个人站基本用不上，先知道有这功能就行。免费版的支持是社区论坛和文档，没有工单、没有 SLA——个人站够用。

翻车了怎么办

  • 改完 NS 网站打不开：先等 NS 生效（几分钟到几小时）；再检查第 2 步是不是漏扫了一条 DNS 记录，漏了就补上。
  • 浏览器说“重定向次数过多”：SSL 模式改成 Full (strict)，别用 Flexible。
  • 改了网站还是旧页面：Caching → Purge Everything 清一次缓存；或开 Development Mode 看即时效果。
  • NS 改了半天 Cloudflare 还显示未激活：去注册商后台确认 NS 是不是真的改了、有没有多填空格；再等一等，全球同步最多 24 小时。

容易踩的坑

改 NS 前没备份旧 DNS 记录
NS 一改，旧服务商那边的记录就不再生效。操作前把现有 DNS 记录截图或导出存好，漏了能照着补。
SSL 选了 Flexible
Flexible 只加密浏览器到 Cloudflare 这一段，Cloudflare 到源站走明文；源站强制 HTTPS 时会来回跳转，页面打不开。GitHub Pages 这种自带 HTTPS 的站，直接选 Full (strict)。
照着老教程找 Page Rules 和 Auto Minify
Auto Minify 已于 2024 年 8 月 5 日下线；Page Rules 已标记为弃用（deprecated），新功能改用 Cache Rules 等替代——老入口可能还在，但新建规则别再用它。看到老教程提到它们，直接跳过，不影响本篇操作。
把 Development Mode 当常开开关
开发模式 3 小时自动关，期间所有缓存失效、网站变慢。只在排错时临时开，平时保持关闭。

常见问题

免费版到底包含什么？
以 Cloudflare 官网为准。免费版（$0/月，不用信用卡）包括：DNS、全球 CDN（流量不限，常规网页内容流量不计费；但按 Cloudflare 服务条款，不能拿免费版主要做视频或大文件分发）、免费 Universal SSL 证书、不限量 DDoS 防护、免费 WAF 托管规则集、5 条自定义 WAF 规则、1 条限速规则、Bot Fight Mode。Pro 是 $20/月（按年付）或 $25/月（按月付），主要多的是更全的 WAF 规则、图片优化和工单支持。
Cloudflare 能代替网站托管吗？
不能。Cloudflare 是挡在前面的加速和防护层，你的网站文件还得住在 GitHub Pages、Vercel 这些地方。它不提供“放网站文件”的服务。
改了 NS，以后还能在 DNSHE 改解析吗？
不能。NS 改到 Cloudflare 后，所有 DNS 记录都要在 Cloudflare 的 DNS 页面里改，DNSHE 那边只剩“域名归属”和续期。想换回去，把 NS 改回原来的就行。
免费版有流量上限吗？
CDN 流量在免费版不单独计费。卡你的是规则数量（比如第 6 条自定义 WAF 规则就要升 Pro），不是流量。个人站基本碰不到上限。
