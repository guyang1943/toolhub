🎵 音视频工具

浏览器里跑 FFmpeg 与音频剪辑：视频体积大，更不该先进上传队列。

工具分类 / 音视频
音视频文件动辄上百 MB，上传等待的时间往往比转码本身还长，而且素材里常有人声、画面、未发布的内容。这一类的本地方案是 ffmpeg.wasm——把真正的 FFmpeg 编译成 WebAssembly 在浏览器里跑，常见转码、抽音轨、转 GIF 都能完成，代价是速度不如桌面版。

适合这些场景

  • 把 200MB 的录屏压到 20MB 再发群，避免被限制发送
  • 从一段视频里抽出音轨存成 mp3，交给同事做文字稿
  • 剪掉播客开头的一段空白与环境噪声

怎么挑

  • 先看目标平台的上限再定参数：微信、公众号、B 站对单文件体积、码率、时长各有要求，先查再转，别转完发现还是传不上去。
  • 首次使用要等核心下载：ffmpeg.wasm 的核心有几十 MB，之后会被缓存；第一次打开慢不代表卡死。
  • 转码时别切走标签页：后台标签会被浏览器降频，同样一段视频可能多花一倍时间。
  • 长视频建议回本机跑：超过十分钟的素材，桌面版 FFmpeg 或剪映更快，浏览器方案适合「临时、单个、不想装软件」。

常见问题

视频会上传吗？
不会。ffmpeg.wasm 在浏览器内存里处理，文件不经过服务器，断网也能转（前提是核心已缓存）。
为什么比桌面版慢这么多？
WebAssembly 缺少部分 SIMD 优化，还有浏览器沙箱与内存拷贝的开销。压缩比与参数是对的，差别只在耗时。
能用显卡加速吗？
不能。浏览器内拿不到 NVENC/QSV 这类硬件编码器，只能走 CPU 软编。
