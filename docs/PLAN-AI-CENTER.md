# AI 中心重做·策划（2026-11-27）

> 这份文档回答一件事：`/ai/` 现在只是一页「AI 工具在哪」的说明加四个工具，要不要、以及怎么重做成一个真正的中心。
> 结论先说：**做「AI 的说明书」，不做「AI 的货架」。**

---

## 一、现在是什么，缺什么

`/ai/` 现在是四段正文加四个站内工具（浏览器内置模型、硬件容量估算、去背景、人脸打码），横带从首页指进来。

它能回答「这个站有没有 AI 工具」，回答不了用户真正会问的三件事：

1. 我这个任务，**该在哪跑**——本机、浏览器、还是必须上云？
2. 这么做**要花多少钱**——是按 token 算，还是订阅，还是要买卡？
3. 具体**怎么一步步做完**，失败了怎么办？

现在的页面里，「四条路别混着走」已经摸到了第 1 问的边，但它是一段散文，不是能查的东西；第 2、3 问完全没有。

---

## 二、三条判断（这份策划的地基）

### 判断一：AI 信息有三种腐烂速度，必须分开装

| 内容 | 腐烂速度 | 能不能做静态表 | 该做成什么 |
|---|---|---|---|
| 价格、模型型号 | **周级**（一次发版就变） | 不能 | 公式 + 计算器 + 官方链接，**不抄数字** |
| 能力属性（支持 MCP、能本地、开源、自带 key） | **季度级** | 能，但必须带核实日期 | 能力矩阵，未知标 `?` |
| 方法论（怎么评估、怎么省钱、怎么不被坑） | **年级** | 能 | 教程，按「做完一件事」组织 |

这一条是这份策划最重要的结论。市面上的 AI 导航站死在第一条上：它们把价格和型号做成静态表，上线两周就开始撒谎，三个月后整站不可信。**我们不抄数字，只给算法和入口**——这不是偷懒，是唯一能长期说真话的做法。

调研时就撞上了活证据：同一天搜到的三份「2026 年 11 月价格表」，一家写 GPT-5、一家写 GPT-6，Claude 从 4.5 排到 5.5，DeepSeek 从 V3.2 排到 V4 Pro。**这些数字互相矛盾，而且我无法逐个核实**（官方定价页大多需要特定网络环境）。如果我照抄一张表，就是第 N 个不可信的表。

### 判断二：这个站的差异化不在「收录多少」

「收录 500 个 AI 工具」这件事没有壁垒——GitHub 榜单、各种导航站、甚至 agentgid.com 那种带能力矩阵的站点都在做，而且比我们更新快。硬拼收录量是必输的仗。

我们真正稀缺的是四样，全是这些年攒下来的：

| 资产 | 在 AI 语境下值什么 |
|---|---|
| 74 个本地工具 + 离线包 + 不上传 | 「数据不出机器」在 AI 时代越来越贵：合同、病历、证件、内部文档，没人敢往别人的服务器传 |
| `ai-hw-check` 硬件实测 | 「我这台机器到底能跑什么」是所有人问的第一句，而大部分教程直接从 `pip install` 开始 |
| 70/70 人工核过的边界证据 | 「这条说法凭什么成立」是 AI 内容最缺的东西——大多是「据说」「实测」（没说怎么测的） |
| 24 篇 193 步教程 + 6 条工作流 | 「做完一件事」的颗粒度，而不是「功能介绍」 |

所以 AI 中心的定位不是「AI 工具在哪」，而是：**在把数据交出去之前，先搞清楚有没有不交的选择。**

### 判断三：不做导航，做「决策 + 验证」

导航站回答「有什么」，我们回答「我该选哪个、这个说法对不对、要花多少」。

这两件事的差别在留存上很直接：导航站是「查一次就走」，决策页是「每次要动手之前都回来查一遍」。前者靠 SEO 吃流量，后者才有回访。

## 三、信息架构

`/ai/` 拆成四个子页 + 一个数据层。首页只做分流，不堆内容。

```
/ai/                 决策入口（三张卡）+ 本地能跑到哪一档 + 最近更新的教程
/ai/where/           这件事在哪跑：本机 / 浏览器 / 云 / 自建，四路的代价对照
/ai/cost/            token 与成本：公式、三个反直觉点、换算器、官方定价入口
/ai/matrix/          能力矩阵：Agent 工具 / MCP / 本地引擎，带核实日期
/ai/how/             教程索引：按任务组织，不按工具
```

### 3.1 `/ai/` 首页

保留现在的「四条路」判断，但把它从散文压成一张**可扫的表**：

| 路 | 适合什么 | 代价 | 数据去哪 |
|---|---|---|---|
| 浏览器内置模型 | 总结、翻译、改写 | 要 Chrome 138+ / 16GB 内存 | 不出设备 |
| 站内 ONNX 权重 | 去背景、打码 | 首次下载 14.6 MB，单张 3 秒 | 不出设备 |
| 本机装推理引擎 | 7B–32B 对话、写作 | 要显卡或大内存，装一次 | 不出设备 |
| 云端 API | 长文档、复杂推理、多模态 | 按 token 付费，内容出设备 | 到服务商 |

下面是「本地能跑到哪一档」（接 `ai-hw-check` 的逻辑，静态化四档结论），再下面是教程入口。

### 3.2 `/ai/where/`

核心是一张**按任务 × 敏感度**的决策表，不是按工具：

| 你的任务 | 数据敏感 | 建议 |
|---|---|---|
| 总结一份内部合同 | 高 | 本机 7B（8GB+ 内存）或浏览器内置模型 |
| 翻译一封邮件 | 中 | 浏览器内置 Translator，零成本 |
| 从 200 页 PDF 里抽条款 | 高 | 本机 + 检索，别整篇塞进上下文 |
| 生成产品图 | 低 | 云端（本地跑不动扩散模型） |
| 代码重构 | 中 | 云端 Agent（本机 32B 以下做不稳） |

每一行都要能点进对应的教程或工具。这张表的价值在于「按你的处境分」，而不是「按产品分」。

### 3.3 `/ai/cost/`

**不放价格表**，放三样东西：

1. **公式**：`成本 = 输入tokens × 输入单价 + 输出tokens × 输出单价`，并说明 token 不等于字数（中文约 1 字 ≈ 0.6–1 token，各家分词器不同）。
2. **三个反直觉点**（这三个比价格数字有用得多）：
   - 输出通常比输入贵 **3–5 倍**，长回答的账单在输出侧
   - 推理模型的**思考 token 按输出计费**，有时比答案还长
   - **缓存命中便宜约一个数量级**，所以系统提示词和长文档前缀要复用
3. **换算器**：输入「每次请求多少 token / 每月多少次」，给「一万次请求多少钱」，单价让用户自己填或选（默认值标来源与日期，且明说「价格会变，以官方页为准」）。

底部是各家官方定价页的直链，**只给链接，不抄数字**。这一条要写进页面的说明里，让用户知道为什么这里没有表。

### 3.4 `/ai/matrix/`

这是唯一做静态表的地方，因为能力属性变化慢。每条带 7 个属性：

`MCP 支持 / 能跑本地模型 / 可自带 API key / 开源 / 有免费档 / 多 Agent / 可 headless`

三态：`✓` 支持、`✕` 不支持、`?` 文档没说。**`?` 不许猜成 ✕**——这是这张表可信的来源。

初版收 30 条左右，分三组：

- **编码/通用 Agent**：Claude Code、Codex CLI、Cursor、Gemini CLI、OpenCode、Aider、Copilot、Trae…
- **MCP 相关**：客户端（哪些 Agent 支持）、常用服务端（文件、浏览器、数据库、搜索）
- **本地推理引擎**：llama.cpp、Ollama、LM Studio、vLLM、MLX/omlx、SGLang

每条必须有 `source`（官方文档 URL）和 `checkedAt`。

### 3.5 `/ai/how/`

教程按**任务**命名，不按工具：

- 「让 AI 读你的 PDF 并回答问题，文件不上传」
- 「8GB 笔记本跑 7B：装什么、选哪档量化、怎么知道它在用显卡」
- 「把公司文档做成能检索的库，整条链路在本机」
- 「给团队接一个本地模型服务：Ollama 起步，什么时候该换 vLLM」
- 「同一个任务，四种跑法的成本对照（含实测）」
- 「怎么判断一篇 AI 教程是不是抄的」（这条是元教程，正好立信）

已有的教程体系（193 步、带 pitfalls）直接复用，不新造格式。

## 四、数据层与保鲜机制

新增 `assets/data/ai-tools.json` 与 `assets/data/ai-engines.json`，**按需 fetch，不进首屏、不进启动数据**。

每条的结构：

```json
{
  "id": "ollama",
  "name": "Ollama",
  "group": "engine",
  "attrs": { "mcp": false, "localModel": true, "ownKey": true, "openSource": true, "freeTier": true, "multiAgent": false, "headless": true },
  "unknown": [],
  "note": "后端是 llama.cpp；单机少并发够用，并发上来要换 vLLM",
  "source": "https://github.com/ollama/ollama",
  "checkedAt": "2026-11-27",
  "staleAfterDays": 180
}
```

保鲜规则（复用 `evidence.boundary` 那套方法论）：

1. 构建期算 `age = today - checkedAt`；超过 `staleAfterDays` 的条目，页面加一行「此条 2026-05 核对，可能已变」，**不隐藏、不删除**。
2. `verify` 输出**待核清单**（不判红），并在 README 里记「本月待核 N 条」。
3. 每条缺 `source` 直接构建失败——和边界证据同一道闸门，不给「据我所知」留口子。
4. `unknown` 数组里的属性在页面上显示 `?`，鼠标悬停说明「官方文档未提及」。

**这套机制本身就是内容**：用户能看到「这条是什么时候核的、凭什么」，这在 AI 内容里几乎没人做。

## 七、明确不做

| 不做 | 为什么 |
|---|---|
| AI 新闻 / 日报 | 需要日更编辑，一个人做不到，做了必烂尾 |
| 静态价格表 | 周级变化，抄错就是误导；给公式和官方入口 |
| 模型跑分排行榜 | 跑分不等于你的任务，且需要持续复现 |
| AI 对话窗口 | 又一个壳，没有留存 |
| 「AI 工具收录 500+」 | 无壁垒，别人更新更快；我们的壁垒是「本地能跑什么」 |

## 八、需要拍板的三个点

1. **`/ai/matrix/` 的 30 条初版，是否允许我按官方文档核到哪算哪、核不到就标 `?`**（而不是凑满 30 条都打勾）。我建议允许——`?` 比假勾值钱。
2. **成本页要不要给「默认单价」**。给了更像工具，但会有过期风险；不给则要用户自己查。我建议给，但标日期 + 一键恢复默认 + 明显提示「以官方页为准」。
3. **教程是否允许写「我实测」**。我的立场：写了就必须附方法（机器配置、量化档、测了几次），否则不写这三个字。这一条如果同意，会写进教程模板的硬规则。

## 九、拍板记录（2026-11-28）

三个问题都按「更严格的那一版」定，并且**落成了闸门**，不只是写在这里：

| 问题 | 拍板 | 落在哪 |
|---|---|---|
| 30 条允许核不到标 `?` 吗 | **允许**，宁可全表都是问号，也不凑满打勾 | 三态渲染 + `verify` 的「格数与数据逐态对账」；`?` 被画成 `✕` 会红 |
| 成本页给不给默认单价 | **给**，但必须：标来源与日期、一键恢复默认、页面上明写「以官方页为准」 | v3.44 实现，三条同时缺一条就不许上 |
| 教程允许写「我实测」吗 | **允许，但必须附方法**：机器配置、量化档、测了几次，缺一样就不许写这三个字 | `verify` 的「我实测必须附方法」闸门，对全部教程生效 |

第三条已经生效了（v3.43 就加进 `verify`）：`guides/*.json` 里任何一篇出现「实测 / 我测」，
正文里就必须同时出现机器/配置/显存类字样与「N 次」——否则构建失败。
现在 24 篇里 0 篇这么写，闸门空转；等 v3.45 的 AI 教程进来，它才开始真的拦人。

第二条记一笔容易忘的细节：默认单价不是「抄一张表」，而是**三个常量加一句免责声明**——
单价、来源 URL、取价日期。页面上要有「恢复默认」按钮（用户改完能退回），
并且不能让默认值看起来像实时价格（写清「2026-11 取价，价格会变」）。
这三样缺一条，这一页就会变成我们自己批评过的那种表。
