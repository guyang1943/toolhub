## 二、任务目标

这一版的重点是「找」，不是「一口气加完」。产出两份东西：

1. **候选清单**（必做）：12 条，每条能回答「跑在哪、数据去哪、多少钱、什么风险」。
2. **落地 3 个**（能做就做）：从清单里挑「零依赖、纯计算、无先决条件」的前 3 个。

挑工具的标准是「**有人确实需要、而不太有人做**」，不是「好实现」。别为了凑数做第四个 JSON 格式化器。

## 三、每轮的执行步骤

### 1. 先读这些（顺序别跳）

- `docs/taskpacks/v328-handoff.md`：一、现在停在哪 / 三、T2｜找工具 / 五、必读清单 / 六、命令与已知坑 / 七、纪律
- `docs/TOOL-CONTRACT.md`：工具接入契约（`tool.json` 字段、manifest 类型表、run() 返回契约、三份内容补全）
- `perf-budget.json`：`budgets` 与 `note` 末尾三段（赊账记录都在那）
- `tools/registry.json`：现有工具 id，别重名
- `docs/taskpacks/TP7-tool-candidates.md`：上一轮留下的候选，先看还有哪些没做

### 2. 独立工作区

```bash
cd "C:/Users/huwei/WorkBuddy/2026-10-20-10-57-11/toolhub"
git fetch origin
git worktree add ../toolhub-tools -b feat/tools-candidates origin/main
```

已存在就先 `cd` 进去看 `git status`，有未提交改动先 commit 再 `worktree remove --force`。
之后都在 `../toolhub-tools` 里干活，**不要**在主工作区 checkout 分支（主工作区和别的任务共用）。

### 3. 写候选清单

写到 `docs/taskpacks/TP<n>-tool-candidates.md`，每条写清：

- 建议 id（kebab-case，不与现有工具重名）与一句话定位
- **跑在哪**：浏览器 / 本地客户端 / 自部署 / 需 API Key（四选一，答不出的不收）
- **数据边界**：输入会不会离开本机；外链项目要写证据（谁、何时、怎么核的）
- **实现成本**：零依赖纯计算 / 需 vendor 三方库（库名、许可证、gzip 体积）/ 需 Canvas 或 WebCrypto
- **预算影响**：进首屏（`tools.json` 元数据）还是按需（工具页才加载）
- **先决条件与风险**

纯云服务（要注册、要 Key、数据必然离开本机）**只进资源库，不进工具目录**——工具目录的语义是「你能用它做完一件事」。

### 4. 落地

按 `docs/TOOL-CONTRACT.md`：

- `tools/<id>/tool.json` + `tools/<id>/run.js`（`export const manifest` / `export async function run`），`index.html` 由构建生成，不手改
- manifest 必填 `inputs`（1-10 项）+ `runLabel`（动词 ≤6 汉字）；输入项**不许带示例默认值**；`file` 类型必须写 `accept`；`aliases` 不手写
- 跑 `node scripts/sync-tools.mjs` 再 `npm run build:prod`；**不要跑 `gen-search-aliases.mjs`**（它会把只有 70 条外链的 directory 别名改瘦）
- `README.md` 头部三处导语数字手改（中文 / 繁体 / 英文；英文那句是「本地在前、总数在后」，与另两处相反）
- 补 `articles.json` / `articles/<id>.json` / `i18n.json` / `i18n-detail.json`；**FAQ 每篇至少 5 条**（verify 钉死）

### 5. 预算（硬闸门）

- 先跑 `npm run perf` 看基线。
- `perf-budget.json` 的 note 里写着赊账：新工具批次必须先确认 aliases 已拆（v3.29 已拆到 `tools/aliases.json` 按需加载，这条账已还）。
- perf 红了**不许抬 total**：要么减工具数量，要么把内容挪到按需文件。抬 `scripts` 这类单项必须单列账（代码变胖 ≠ 内容变厚）。
- 动过搜索加载时机，必须跑 `test:spa` 与 `test:browser` 的搜索用例。

## 五、边界

- **不碰**：`content/guides.json`、`assets/lib/guide-text.js`、`guides/` 产物（属于教程任务）
- 测试红了先判断是真问题还是断言本身错了；**改断言必须在交付说明里单列论证**
- 不许估：外链每条实际访问过（`curl -sI -L` 或 WebFetch），404 剔除，查不到写「未核实」
- 增量提交：清单写完一次，每落地一个工具一次
- 遇审批 / 权限 / SSH 失败：停下，把原始报错写进报告，不绕过
- `git` 报 `index.lock`：另一个任务在同时操作，等 5 秒重试一次
- 浏览器套件超时：先确认 serve 活着、端口没被占，重试一次再判定，别把「慢」当「坏」
- 只有 3 个能全绿就只交 3 个。半成品会一路绿到用户面前（v3.27 media-info 漏反引号的教训）
