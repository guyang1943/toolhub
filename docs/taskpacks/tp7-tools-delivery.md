## 二、逐个工具的口径与踩到的坑

**`ua-parse`**：纯正则表拆浏览器 / 内核 / 系统 / 设备，留空时解析浏览器自己的 UA。
正则表在源码里标注「最后核对 2026-11-06」；认不出的字段写「未识别」并原样回显 UA，
**不猜品牌、不猜型号**。真跑一遍时踩到：桌面 UA 里的 `x64` / `Win64` 被当成设备型号，
已改成「只有认出手机品牌才取型号」。

**`mock-data`**：手机号只用现行已分配号段；身份证带 GB 11643（MOD 11-2）校验位，
地区码用真实码表，生成后逐条自检；邮箱统一 RFC 2606 保留域，不造真实域名；
结果区醒目标注「仅供测试，非真实号码」；支持每行一个 / CSV / JSON 三种导出。

**`json-yaml`**：js-yaml 4.1.0，`load` / `dump` 显式指定 `DEFAULT_SCHEMA`
（不启用 `!!` 自定义类型，避免把 YAML 当代码执行）。锚点、多文档、自定义标签与语法错
都给中文行列提示，而不是把库抛的英文栈直接甩给访客。

**`ascii-art`**：figlet 1.12.0 + Standard / Slant / Small 三份 `.flf`。
**先量真体积再决定留几种**：30,740 + 15,517 + 12,232 = 58,489 B 原始 / 9,819 B gzip，
连同引擎也远低于「单工具 ≤200 KB」的硬规则，所以三种全留，没有为了省字节砍字体。
长文本用 `width` + `whitespaceBreak` 按空格折行不断字；中文明确报错而不输出一堆方块。

**`pinyin-convert`**：重写 `scripts/build-pinyin-bundle.mjs`，从仓库内
`scripts/vendor/tiny-pinyin/dist` 打包出 `assets/vendor/pinyin.min.js`
（**15,316 B / gzip 5,381 B**，与预研的 ~16 KB 对上）。字典只给音节、不带声调，
因此**不猜声调**；多音字取常用读法，页面、结果区、英文详情三处都写明这个口径。
配套闸门见第四节。

四个 vendor 合计 **161,211 B 原始 / 40,349 B gzip**，全部由工具页动态 `<script>` 注入，
不进首屏；`perf-budget.json` 的 `forbiddenFirstScreen: ["assets/vendor/"]` 仍拦着。

## 四、接线与闸门（新页面必须有「入口」+「闸门」）

- **入口**：5 个工具页由构建期生成；首页 / 分类 / 全部工具 / `llms.txt` / `sitemap.xml` /
  `api/tools.json` / `feed.xml` / README 三处导语数字全部同步（70 / 140 / 70）。
  `browser-test` 加了「全部工具页 5 个入口」断言，并对 5 个页面逐个真打开、填值、
  点运行、核对输出，不是 `goto()` 直达就算过。
- **离线**：`gen-sw.mjs` 的 VENDOR 补 4 个按需库，`sw.js` 里 5 页 + 4 库逐条核过，
  断网点运行不失效。
- **探活 / 冒烟**：`smoke-test.mjs` 与 `verify-online.mjs` 的 PATHS 补 5 页 + 4 库。
- **拼音包漂移**：`verify.mjs` 新增「`assets/vendor/pinyin.min.js` 与 `dist` 数据源逐字一致」。
  改了字典忘重打包，页面上不会报错、只会静默沿用旧字音，只有断言抓得住。
- **调度脚本两处加固**（都是这轮真踩出来的）：
  1. `check-all.mjs` 前置加端口占用检测。`8788` 被另一条并行线的 `serve` 占着时，
     原逻辑探到「有响应」就照跑，浏览器全程连到别人的旧站点，白跑 19 分钟；
     现在直接提示换端口（做过故障注入：`PORT=8788 npm run check smoke` 当场拦下）。
  2. 单套超时 600s → **1200s**。真浏览器套件跑满 200+ 用例实测超过 10 分钟，
     原来的上限把还在跑的进程 SIGTERM 掉，表现成「退出码 null」而不是任何一条用例失败。
  3. `browser-test.mjs` 的「12 个第二批工具页」老断言补 `waitEl('#tool-form')`。
     `goto()` 不等懒渲染的表单，机器忙时会读到 null，报出「某两个页面没表单」的假红；
     轮询等待不会掩盖真回归（等满 15s 仍判红）。详见第五节第 3 条。

## 五、验收

三道前置闸门：外链边界 70 条 · 投稿规范 8 个合集 / 64 条 · 存储键 12 个。

| 套件 | 结果 |
|---|---|
| lint | 65 |
| verify（结构校验） | 74（73 + 拼音包闸门） |
| spa | 80/80 |
| func | 321/321 |
| smoke | ✅ |
| browser | **348/348**（655s，修断言竞态后单跑） |
| perf | 94.2 KB / 9 请求（预算 95.0 KB） |
| flow | 114 |
| audit | 288 次页面检查，未发现问题 |

**三次假红，都不是代码回归**：

1. 第一次 `npm run check` 跑在 `8788`，那个端口被另一条并行线的服务占着，
   浏览器看到的是「65 个在本机跑 · 135 个已收录」的旧站点，5 个新工具页全 404
   → 冒烟 / 真浏览器 / 体检 3 套红。换空闲端口 `8899` 重跑即绿。
2. 换端口后真浏览器那套报「退出码 null (600.2s)」，被杀前没有任何 ❌，
   最后一条输出还是 `✅ TP7 ua-parse 留空解析本机 UA` —— 是调度器的 10 分钟上限，
   不是失败。延长到 20 分钟后单独重跑这一套。
3. 延长上限后单跑得到 **347/348**，失败项「12 个第二批工具页都能渲染出表单与运行按钮」
   点名 `shadow-gen, media-info` 两个**老**工具（不是 TP7 新工具）。复核：两个页面的
   `run.js` 语法正常、`tools.json` 元数据齐全、其余 10 个同批页面全过。真正的原因是
   **断言自己的竞态**：`goto()` 只等 `#main-content` 有 20 个元素就返回，而工具表单是
   懒渲染的；这条老断言 goto 完直接查 `#tool-form`，机器忙（本套已涨到 348 条 /
   660s）时就会在表单画出来之前读到 null。项目里本来就有 `waitEl()` 轮询
   （TP7 自己的表单断言正在用），给这条老断言补上 `await waitEl('#tool-form', 15000)`
   即可。**不是放宽判定**：真渲染不出表单时 `waitEl` 会等满 15s 后照样判红。
   这条竞态此前以「并发假红」的形态出现过，这次被 TP7 的用例量放大才定位到根因。

**修复后单跑结果：✅ 348/348（655s）**。三道前置闸门同样全过。
`lint` 70 个工具、`verify` 74 项（含「拼音包与数据源逐字一致」）在改动后也各自复跑过。
