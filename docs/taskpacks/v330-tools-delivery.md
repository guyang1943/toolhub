## 二、落地的三个

| id | 标题 | 分类 | 输入 | runLabel |
|---|---|---|---|---|
| `json-diff` | JSON 语义对比 | 数据 | 4 项（两份 JSON / 数组比法 / 主键名） | 对比 |
| `expense-aa` | AA 分摊 | 效率 | 2 项（账单 / 精确度） | 算清 |
| `text-to-pdf` | 文本转 PDF | 文档 | 4 项（正文 / 标题 / 字号 / 边距） | 生成 PDF |

三个都是零依赖、纯计算、无先决条件：不发请求、不写存储、不要权限、不加载 vendor。

**实现上真正花时间的三处**（都是「结构对但用起来炸」那类）：

1. `text-to-pdf` 的 xref 偏移。PDF 里每个对象的位置写错一个字节，阅读器就整份打不开，
   而构建期、verify 都看不见。做法是边拼边记字节数，不手算；`test:func` 里加了一条
   **逐条解析 xref 并回查偏移**的断言。写的时候真踩到一个：`/Kids` 指成了内容流对象，
   文件「能打开、零文字」——`pdf-cli` 一提取才暴露，已修（页面对象 7/9/11…，内容流 6/8/10…）。
2. `expense-aa` 的尾差与笔数。全程整数分；余数按「垫付最多的人先摊」分配（固定顺序，可复核）；
   转账用最大债主配最大债户，N 人最多 N-1 笔。写的时候踩到一次：配对循环直接改了
   `balances` 里的 `diff`，明细表全变「正好」——已改成复制再算，并加了「转账合计 = 应收」的断言。
3. `json-diff` 的口径。`null` 与缺键分开报（改值 vs 删除）、`1` 与 `1.0` 按数值相同、
   数组可按主键对齐。三条都写在结果区，免得「算得对但被当成算错」。

## 五、改过的断言（1 条，单列论证）

`scripts/browser-test.mjs`「口语词『瘦身』命中图片压缩」。

- **原断言**：打完字，立刻读 `#grid [data-id]`，要求含 `image-compress`。它成立的前提是
  **别名在启动包里**。
- **为什么现在会红**：别名改成按需 fetch，第一次搜口语词时结果要多等一次本地请求。
  断言没变弱，是测量时机变了。
- **怎么改的**：加 `waitGridId()` 轮询（最多 3 秒），先等命中再断言。与 `goto()` 的
  「等渲染稳定」是同一种处理，不是放水。
- **为什么不是「测试错了」的借口**：真正的回归（别名没生效、文件 404、缓存没清）依然会红——
  轮询只等结果出现，不判断结果正确。
