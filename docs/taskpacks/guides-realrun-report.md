## 1. ollama-local-ai —— 未通过，`lastChecked` 保持 2026-11-05

目标动作：装 Ollama → 拉 `llama3.2:3b` → 对话一次。

| 步骤 | 实际动作 | 结果 |
|---|---|---|
| 1 查内存 | 读系统信息 | ✅ 7.9 GB 总量 / 1.7 GB 可用，按教程对照表属「8GB 底线，只适合 3B」 |
| 2 下载安装 | 从 `ollama.com/download/OllamaSetup.exe` 下载（307 跳到 GitHub release） | ❌ 官网安装包 **1.69 GB**；跑了 11 分钟只拿到 **8.1 MB**（文件头是合法 PE `MZ`，说明在慢速传输而非报错页），主动终止 |
| 3 版本号 | `ollama --version` | ❌ `command not found`（未安装） |
| 4 拉模型 | 直接读模型仓库清单 + `ollama pull` | 清单可读：`llama3.2:3b` 共 5 层 / **2,019 MB**（模型层 2,019 MB），blob 2 MB 测速 132 KB/s；但 `ollama pull` 因无客户端无法执行 |
| 5 对话 | `ollama run llama3.2:3b` | ❌ 未执行（前置条件不成立） |

**卡点分类：缺条件，不是步骤写错。**

1. 官方 Windows 安装包从 v0.1.48 的 238 MB 涨到当前的 **1.69 GB**（CUDA/ROCm 运行时打包进去了），旧版也没有 CPU 专用小包；配合实测 36–132 KB/s、GitHub 偶发 502，单是安装包就要数小时。
2. 模型本体 2,019 MB，按同一带宽还要数小时；下载完还要在 **1.7 GB 可用内存**上加载约 2 GB 的模型，本机条件不满足教程第 1 步「8GB 底线」的实际运行要求。
3. 官网/模型仓库是通的，所以不是「网络全断」；是**带宽 + 安装包体积 + 内存**三项叠加。上次 11-06 记的是「GitHub release 502 装不了」，这次 502 变成偶发、根因更准确地落到了体积与带宽上。

**没有为了改日期而改日期**：第 3/4/5 步都没真跑，`lastChecked` 不动。教程正文里「下载 OllamaSetup.exe、约 2GB 模型、8GB 内存底线」三项与官方现状一致，未发现写错的步骤，本轮不改正文。

> 复跑所需最小条件：能提供约 1.7 GB 安装包 + 2 GB 模型的可用带宽（或已装好的 Ollama），且可用内存 ≥ 4 GB。
