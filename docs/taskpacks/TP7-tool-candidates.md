## 一、自研 · 零依赖纯计算（可直接落地，无先决条件）

### 1. `json-diff`｜JSON 语义对比 ✅

- **定位**：把两个 JSON 按结构递归对比，差异定位到路径（`a.b[2].c`），而不是像 `text-diff` 那样比行。
- **跑在哪**：浏览器。`JSON.parse` + 递归，零依赖。
- **数据边界**：输入只在本机内存里，不离开设备（不 fetch、不上传、不写存储）。
- **实现成本**：零依赖纯计算。~200 行。难点不在 diff 而在**歧义处理**：
  `1` 与 `1.0` 是否相等、`null` 与缺失是否同义、数组按位置比还是按 key 比——都要在页面上写清口径，否则用户会以为工具错了。
- **预算影响**：仅按需（工具页才加载 run.js）。首屏只多 `tools.json` 里一条元数据（约 150 B gzip）。
- **先决条件与风险**：无。风险是「和 text-diff 重复」的质疑——已在 usage 里写明分工（行对比 vs 路径对比）。

### 2. `expense-aa`｜AA 分摊 ✅

- **定位**：填「谁垫了多少」，输出**最少转账笔数**的结清方案，不是每人各转各的。
- **跑在哪**：浏览器。纯整数运算（分），零依赖。
- **数据边界**：只在本机算，不上传。金额是敏感信息，这条边界比多数工具更重要。
- **实现成本**：零依赖纯计算。~180 行。核心是「最大债主 ↔ 最大债户」贪心配对，N 人最多 N-1 笔；
  金额一律折成分做整数运算，最后再除以 100，避免 `0.1+0.2` 那种分位误差。
- **预算影响**：按需。
- **先决条件与风险**：无。风险是「贪心不是绝对最优笔数」——在最少的 **N-1** 这个上界上贪心已经达到，
  但要写清「同额多人时顺序可能不同，笔数一样」。不接受小数金额（分以下四舍五入会凭空多钱/少钱）。

### 3. `text-to-pdf`｜文本转 PDF ✅

- **定位**：把纯文本按标题/字号/页边距排成 PDF，**在本地生成字节**，文件根本不进浏览器下载前的任何服务器。
- **跑在哪**：浏览器。自己写 PDF 结构（对象表 + xref），只用内置 Helvetica，零依赖、0 新增字节。
- **数据边界**：完全不离开本机。
- **实现成本**：零依赖，但要自己拼 PDF：~260 行。三条硬要求——分页不切断段落、
  xref 偏移必须逐字节正确（错一个字节 PDF 阅读器就整份打不开）、中文必须明确报错而不是出乱码。
- **预算影响**：按需。
- **先决条件与风险**：**首期仅英文/数字**（TP6 已定，2026-11-05）。中文要子集化字体，约 1.1 MB，
  与「单工具 ≤200 KB」冲突，不做。输入含中文时结果区直接提示，不静默出乱码。
- **为什么不是「又一个在线转换器」**：线上 txt→pdf 基本都要上传文件。这个不上传，且断网可用。

## 二、自研 · 零依赖但价值待评（候选，本批不做）

### 4. `ua-parse`｜UA 解析

- **定位**：把 User-Agent 拆成浏览器/版本/内核/系统/设备，留空则解析本机 UA。
- **跑在哪**：浏览器。纯正则表，零依赖（不引 ua-parser-js，那套正则表 40 KB+，超单工具预算的一半）。
- **数据边界**：本机。
- **实现成本**：零依赖纯计算，~200 行正则表。**成本主要在「维护」而不是「写」**：
  新浏览器（Arc、夸克、微信 X5/XWEB）半年就变一次 UA 词，正则表会过期。
- **预算影响**：按需。
- **先决条件与风险**：正则表必须写「最后核对日期」并标明「未识别的 UA 原样回显而不是猜」。
  本批没做：现有 UA 解析器（含浏览器扩展）已经很多，差异化只有「不上传」这一点，不够硬。

### 5. `mock-data`｜测试假数据

- **定位**：造姓名/手机号/邮箱/地址/身份证号，输出每行一个、CSV 或 JSON。
- **跑在哪**：浏览器。零依赖。
- **数据边界**：本机。
- **实现成本**：零依赖，~250 行。手机号要跟现行号段（`1[3-9]` 后两位不是全部有效）、
  身份证要带 GB 11643 校验位且地区码真实存在，否则「假数据」过不了被测系统的校验。
- **预算影响**：按需。
- **先决条件与风险**：**身份证号必须随机生成、且结果区醒目标注「仅供测试，非真实号码」**（TP6 已定）。
  风险是「生成的号码万一撞上真人」——用 999/000 段与显式提示降低概率，但不承诺零碰撞。

## 三、需 vendor 第三方库（体积进单工具预算，不进首屏）

### 6. `json-yaml`｜JSON ⇄ YAML

- **跑在哪**：浏览器（vendor `js-yaml`）。
- **数据边界**：本机。
- **实现成本**：需 vendor **js-yaml**（MIT），`js-yaml.min.js` 约 39 KB 原始 / **~12 KB gzip**，
  在 200 KB 单工具上限内。接入方式与现有 `marked` / `pdf-lib` 一致：`/assets/vendor/` 一份，工具页按需注入。
- **预算影响**：按需（vendor 文件不进首屏，perf 的 `forbiddenFirstScreen` 已经拦着 `assets/vendor/`）。
- **先决条件与风险**：锚点、多文档、`!!` 自定义类型都会踩坑；`js-yaml` 默认 `safeLoad` 行为在 v4 改过，
  必须显式 `schema: DEFAULT_SCHEMA` 并给人话报错。**没做**：单个 YAML 解析库要为它开一条 vendor 先例，
  而首屏余量只剩 0.8 KB，本批优先做零依赖的。

### 7. `ascii-art`｜ASCII 艺术字

- **跑在哪**：浏览器（vendor figlet 字体子集）。
- **数据边界**：本机。
- **实现成本**：需 vendor **figlet**（MIT）+ 3 种 `.flf` 字体。字体是纯文本，
  `standard` / `slant` / `small` 三份合计约 60 KB 原始 / **~24 KB gzip**（字体重复字形多，压缩率高）。
- **预算影响**：按需。
- **先决条件与风险**：必须先量真字体体积再定「3 种还是 2 种」，超 200 KB 就得砍字体；
  长文本要自动换行不断字。**没做**：趣味类优先级低于「真能解决事」的工具。

### 8. `pinyin-convert`｜汉字转拼音

- **跑在哪**：浏览器（自建 16 KB 包）。
- **数据边界**：本机。
- **实现成本**：数据源 = `scripts/vendor/tiny-pinyin/dist`（已在仓库），用
  `build-pinyin-bundle.mjs` 打成 `assets/vendor/pinyin.min.js`，preflight 实测约 16 KB。
- **预算影响**：按需。
- **先决条件与风险**：TP6 已定方案（2026-11-05），预研目录在 v3.25 前清出仓库，**打包脚本要重写**。
  多音字取常用读法并在页面上注明。**没做**：要先重建一条已经拆掉的打包链路，风险高于本批能承担的范围。

### 9. `drawdb`｜浏览器 ER 图 + DDL

- **跑在哪**：浏览器（外链 `https://drawdb.app`，200）。
- **数据边界**：**本机**（官方 FAQ 原话：「In the free editor, diagrams are stored locally in your browser (IndexedDB)」）。
  Pro 才有云同步/团队协作。核验：2026-11-06 WebFetch 读 drawdb.app 首页 FAQ「Where are my diagrams saved?」。
- **实现成本**：外链，0 代码。`tools/directory.json` 一条，需写 desc / privacyNote / promptNote / evidence。
- **预算影响**：**首屏**（directory.json 在 bootData 里）。一条约 120 B gzip，加上 evidence 对象约 180 B。
- **先决条件与风险**：许可证 **AGPL-3.0**（GitHub API，2026-11-06；40,252 stars；最近提交 2026-10-31）。
  AGPL 对「链接到官网」没有影响，但不能把它的构建产物打进本站——目录只放链接，合规。
  与已收录的 `diagrams`（draw.io）**部分重叠**：draw.io 是通用画图，drawDB 专做「库表设计 → DDL」，分工可写清。

### 10. `bruno`｜离线 API 客户端

- **跑在哪**：**本地客户端**（外链 `https://www.usebruno.com`，200；Windows/macOS/Linux）。
- **数据边界**：**不出本机**。官网原话：「Your data never leaves your machine ... No cloud sync. No account. No login.」
  集合就是磁盘上的 `.bru` 纯文本。核验：2026-11-06 WebFetch 读 usebruno.com「Secure & Local」段。
- **实现成本**：外链，0 代码。
- **预算影响**：首屏，约 180 B gzip。
- **先决条件与风险**：MIT（GitHub API，2026-11-06；48,199 stars；最近提交 2026-11-05）。
  与 `hoppscotch` 同类，**两者只该进一个**：本清单两份都列，是为了让人选「离线客户端优先」还是「网页优先」。

### 11. `dbgate`｜数据库客户端（桌面 + 自部署 web）

- **跑在哪**：**本地客户端 / 自部署**（`https://www.dbgate.io` 200；Docker 镜像可自托管成 web 版）。
- **数据边界**：直连你自己的数据库，没有中间云；web 版也是你自己部署的那台机器。
  核验：2026-11-06 首页含 Docker / Self-hosted 文案 + 仓库描述「Runs under Windows, Linux, Mac or as web」。
  **没有逐条读到「不回传」的官方声明**，这条按「自部署 = 数据在你自己的机器上」的常识判断，标为**部分未核实**。
- **实现成本**：外链，0 代码。
- **预算影响**：首屏，约 180 B gzip。
- **先决条件与风险**：**GPL-3.0**（GitHub API，2026-11-06；7,375 stars；最近提交 2026-11-04）。
  和已收录的 `duckdb`（浏览器内 SQL）不冲突：duckdb 是查询引擎，dbgate 是连生产库的客户端。
  风险：GPL 项目只放链接没问题，但页面上不能暗示「本站提供它的在线版」。

### 12. `hoppscotch`｜网页版 API 调试台

- **跑在哪**：**浏览器 / 自部署**（`https://hoppscotch.io` 200；也有 Desktop 与 CLI）。
- **数据边界**：**未核实**。首页有 Login 与「Personal Workspace」，说明存在云工作区；
  不登录时集合存哪，官方 docs 的 Collections 页没写。核验：2026-11-06 WebFetch 读了首页与
  `docs.hoppscotch.io/documentation/features/collections`，两处都只讲怎么建集合，不讲存储位置。
- **实现成本**：外链，0 代码。
- **预算影响**：首屏，约 180 B gzip。
- **先决条件与风险**：MIT（GitHub API，2026-11-06；80,757 stars；最近提交 2026-11-04）。

## 五、为什么这 3 个先落地

筛选标准不是「好实现」，是三条同时成立：

1. **零依赖**：不引库、不开 vendor 先例（`json-diff` / `expense-aa` / `text-to-pdf` 都是手写）。
2. **纯计算**：无网络、无存储、无权限、无文件系统；输入进、结果出。
3. **真有人需要、且没被做好**：
   - `json-diff`：`text-diff` 只能比行，接口返回体一格式化就全红，语义对比是真空缺。
   - `expense-aa`：Excel 能算总额，算不出「最少几笔转账」；这是每次聚餐都要问一遍的事。
   - `text-to-pdf`：线上转换器全要上传，且中文场景下「明确报错」比「静默乱码」稀缺。

对照被否掉的：`ua-parse`（差异化只有「不上传」）、`mock-data`（假数据生成器满地都是）、
`json-yaml`（要开 vendor 先例，而首屏余量只剩 0.8 KB）。

## 六、预算账（写在实际测量之前，测量结果见交付说明）

- 现状：首屏 **93.2 KB / 94.0 KB · 9 请求**，余量 **0.8 KB**。
- 3 个工具的增量全在 `tools.json` 元数据（`id/name/desc/category/source/license/runtime/tags/since/aliases`）。
  参考 v3.26 的实测：12 个纯计算工具让启动数据 +1.7 KB，**每个约 140 B gzip**；3 个约 **0.4–0.5 KB**。
- 结论：**能不抬 total 就加**（余量 0.8 KB 够），但**加完余量只剩 0.3 KB**，
  下一批必须先还 v3.27 写死的那笔账：把 `tools.json` 的 aliases（实测压缩后 **2.1 KB**，
  60 个工具里 50 个有别名）挪到 `tools/aliases.json` 按需加载。
- 本批若 perf 变红：**不抬 total**，先拆 aliases；拆不动就把工具退回去，只交清单。

## 七、本批不取的 TP6 条目（记录理由，免得下一批重新讨论）

| 条目 | 理由 |
|---|---|
| `sql-format` | 需 vendor `sql-formatter`（约 60 KB gzip），且与已有 `prettier` 外链功能重叠 |
| `pdf-stamp` | 复用 `pdf-lib` 可行，但要先确认 `pdf-merge` 的引擎与坐标换算；文件类工具体验成本高 |
| `note-local` | 要接 `assets/lib/store.js` 的版本迁移，属「存储层」改动，不该塞进加工具的批次 |
| `pomodoro-kit` | Notification 授权 + 后台计时，体验细节多；价值上属「手机自带就有」 |
| `kroki` | 公开实例要把图源码发给它的服务器；能力又与已收录的 plantuml / mermaid / markmap 重叠 |

## 八、需要拍板的事

1. `bruno` 与 `hoppscotch` 同类，**只进一个**：选「离线客户端」（数据不出本机，事实清楚）还是
   「网页版」（不用装东西，但存储位置未核实）？
2. `drawdb` 是 **AGPL-3.0**。目录只放链接、不打包代码，我判断合规；如果要一刀切「只要 MIT/Apache」，
   这条撤掉。
3. aliases 拆不拆由 perf 结果定（见第六节）；若本批没拆，下一批的第一件事就是它。
