## 二、每篇必须有的四件套（缺一项构建失败）

- `prereqs`：前置条件（缺什么会卡住）
- `steps`：操作过程，每步一个动作
- `risk`：只能是 `low` / `mid` / `high`
- `fallback`：回退方法，**必须是可执行动作**，不是「请注意安全」

另按现有篇目补齐：`slug` `icon` `title` `tagline` `difficulty` `minutes` `lastChecked` `intro` `why` `pitfalls` `faq` `tools` `links`。`faq` 少于 2 条 `verify` 直接红。

---

## 三、写之前必须知道的四件事

1. **`riskNote` 只给 `risk=high`**。`mid` / `low` 写了也没人看得见（构建只在 high 时渲染），`verify` 已加断言把它钉死。低/中风险的风险提示写进 `intro`、`prereqs` 或对应步骤的 `body`，并且**放在动作前面**：先说会出什么事，再说怎么做。
2. **正文没有富文本**。`steps[].body` 是一整段纯文本，换行不生效，代码只能靠 ``` 围栏。
3. **围栏前后必须各留一个空行**。`guide-text.js` 按空行切段、整段匹配 `^```` 才认围栏；贴在一起就会把三个反引号原样吐到页面上（v3.29 踩过，`verify` 报「出现字面三反引号」）。
4. **`lastChecked` 填实际核对过的日期**，不是发布日期。

## 四、追加方式（别偷懒）

`content/guides.json` 是**手写排版**：`tools`、`links` 内联，其余数组一行一项。
`JSON.stringify(…, null, 2)` 会把老条目从 117 行撑到 137 行，产生巨大无意义 diff。

用**定点插入**：先按原风格 `fmt()` 生成新块，插在数组收尾前，**老条目字节不动**；`updated` 改当天。
