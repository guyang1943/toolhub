  首屏 94.2 KB / 9 请求一分没涨。
- **check-workflows 加端口闸门**：相邻两步 out ∩ in 必须非空。一条兼容规则是被真实流程逼出来的：
  text 作为「未定型文本」可流向 text / json / csv——base64 解出来可能是 JSON 也可能是普通文字，
  按「text 只能进 text」判会把一直在正常工作的 b64-to-json 误杀；反过来 json / csv 不能互串。
  故障注入：把 b64-to-json 第二步换成 img-to-pdf，当场报「上一步产出 text，这一步只吃 image」。
- **助手升级**：intent.js 新增 recommend()（纯函数，flow 测试可直接断言）+ loadContext()（按需 fetch 两个 JSON）。
  规则：命中工具是某条流程的后半段 + 流程名与这句话说中 ≥2 个词 → 推整条流程。
  「把照片转成 PDF」→ 推「照片成 PDF」（先限边长）；「JSON 格式化」→ 仍推工具（不推「编码串还原 JSON」）。

  还顺手改了他的边长（v3.11 的意图条用例会红，正是那次发现的）。

## 这一轮踩到的坑

- **browser-test.mjs 不自己起服务**：它读 argv[2] 或 BASE_URL，默认 8788。`PORT=8899 npm run test:browser`
  无效，会连到空端口，38 秒后报「首页 0 张卡片」一整片假红。正确姿势：先 `node scripts/serve.mjs --port 8899`，
  再 `BASE_URL=http://127.0.0.1:8899 node scripts/browser-test.mjs`。跑 check-all 前要把手动服务停掉（它自己起）。
- **tool.json 的 tags 有三种写法**：多行数组 / 单行数组 / tags 是最后一个键（后面直接 `}`）。
  给 70 个文件插 io 时正则只认多行，第一批漏了 32 个；改成按 `[` `]` 定位 + 补逗号才对。
  本机是 CRLF，正则里 `\n` 也要容忍 `\r\n`。
- **changelog 文案里混进零宽空格**（「schema」中间），写文件后要扫一遍 `[\u200b-\u200f\ufeff]`。
